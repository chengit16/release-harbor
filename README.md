# Release Harbor

面向 React Native、Flutter 和原生应用的独立商店发布工作台。产品接收已有安装包，统一组织项目、应用、渠道、产物、发布计划、执行记录和后续审核流程。

当前为 **0.1 第三期审核与资料追踪进行中**。已提供本机应用与账号配置、APK／IPA／HarmonyOS APP 检查、只读预检、发布准备与一次确认、逐渠道执行和 Android 多商店串行批次。iOS 支持构建上传、已有构建送审及批准后的手动发布。商店 SDK 和凭据留在可信执行进程，Web 与普通 API 只使用公开合同。

已有 Android 渠道及 iOS 获用户可用反馈；应用宝、鸿蒙、批次及新增细项的具体远端结果分别记录，不从工程测试推断审核或上架成功。当前进度见[路线图](docs/ROADMAP.md)，后文带日期的切片记录保留当时边界。

## 当前开发安排

**发布中心体验已获用户验收，第三期已启动**。首片接入荣耀版本状态只读查询；后续逐渠道扩展集中跟踪与资料待办，见[第三期实施计划](docs/plans/phase-3-review-tracking-plan.md)及[状态查询指南](docs/guides/release-status-observations.md)。此前渠道按小米、OPPO、vivo、魅族、荣耀逐个接入，再恢复 Apple、扩展应用宝和鸿蒙；接入历史见[第二期实施计划](docs/plans/phase-2-android-channels-plan.md)。

日常发版操作为“填写资料 → 准备发布 → 看摘要确认一次 → 查看结果”；预检与快照准备自动完成，账号配置后复用。发布中心汇总本机历史，列表读取不查询商店或触发执行。

## 技术选型

- Web：React + TypeScript + Vite + Ant Design，常见交互优先使用 Ant Design 组件。
- API：NestJS + Fastify adapter，采用模块、依赖注入和 Controller／Service 分层。
- 领域与公开合同：独立工作空间包，便于 CLI、工作台和未来执行器复用。
- 本地存储：原子写入的单进程 JSON 实现；在线多实例部署前替换为有事务与唯一约束的数据库。
- 商店适配：锁定 @huoye/app-ship@0.3.0，运行在可信 Node 执行进程。

Node.js 是运行时，NestJS 是建立在它之上的服务端框架；Fastify 是 NestJS 选用的 HTTP adapter，三者可组合使用。

## 本地启动

需要 Node.js 24 和 pnpm 11.20.0。

```bash
pnpm install --frozen-lockfile
pnpm dev
```

打开 http://127.0.0.1:5178。API 在 http://127.0.0.1:4399，开发工作台通过同源代理访问 API。

## 工作台菜单

- **发布**：发布中心，跨项目查看单渠道计划与多渠道批次，也可发起发布。
- **配置**：应用管理、商店账号。应用内仍可维护商店绑定、安装包和只读预检；点击“前往发布中心”进入该应用的发布记录。
- **了解与支持**：问题档案、商店指南、产品路线图。

iOS 的上传构建、审核与发布也统一从发布中心进入，应用管理不保留审核页签。

发布中心的列表与筛选保存在 URL，读取接口只汇总本机公开摘要，不执行预检、上传或提交。点击记录详情进入对应应用发布工作区；iOS 上传构建、提交审核及手动发布分别列出，审核记录支持刷新与前后退恢复摘要。历史观察显示查询时间与“非实时”提示，人工核对和原始回执分别展示。荣耀已执行记录可在发布摘要或执行详情中显式查询状态，页面刷新仅读取观察历史。

构建后可由 API 一并提供静态工作台：

```bash
pnpm build
pnpm start
```

打开 http://127.0.0.1:4399。创建的项目默认保存到用户目录下 `.release-harbor/projects.json`。设置 `RELEASE_HARBOR_DATA_DIR` 可使用隔离目录，例如测试或演示数据；Node 默认不会自动加载 `.env`，需通过 shell 设置变量或启动时自行加载。

应用与商店绑定独立保存在同目录的 `applications.json`，不改写既有项目文件。服务只支持单进程写入；文件损坏或版本不受支持时拒绝覆盖。停止服务后可备份整个数据目录。进入项目后可登记应用和绑定商店目标；项目内应用列表与应用工作台分别展示；进入应用后通过顶部选择器切换应用，面包屑可返回项目。URL 保存项目、应用及当前页签，刷新和浏览器前后退后可继续查看。

在应用详情切换“安装包”页签，选择已有 APK／IPA 后点击“上传并检查”。默认单文件最大 256 MiB，产物字节预算为 2 GiB，同一时间只接收／检查一个文件。文件与安全记录存于同目录 `artifacts/{UUID}/`，失败字节自动清除；中断记录在重启后标记失败，不自动重跑。首轮不提供成功产物的在线删除或下载入口。

APK 检查需要可用 aapt／aapt2，可通过 `ANDROID_HOME`、`ANDROID_SDK_ROOT` 或本机默认 SDK 路径定位；IPA 检查需要 unzip 与 plutil。缺少工具、包身份不符或文件损坏会显示真实失败。检查通过仅代表接收字节的身份、版本与摘要可核对，不代表签名、商店资格或发布成功。

## 商店账号与只读预检

打开左侧“商店账号”，点击“新增商店账号”，按“账号信息 → 配置材料 → 确认保存”完成配置。也可在应用的商店绑定表单中点击“新增账号”；保存后自动选中，已填写的商店 appId 保留，再点击“保存绑定”。日常录入无需终端或手写凭据引用。

账号名称由用户设置，内部 reference 自动生成；已由 CLI 创建的档案继续可选，默认显示原引用。支持华为 Connect API 的 Client ID／Client Secret，小米开发者邮箱／API 访问密码／RSA 公钥和审核测试材料，以及 Apple 团队 API Key 的 Issuer ID／Key ID／P-256 `.p8` 文件（不超过 64 KiB）。保存只表示本机材料已配置，鉴权及应用目标仍需发布准备中的自动检查或独立只读预检。

本地启动会自动管理独立回环配置进程，页面通过五分钟会话直接提交材料；普通业务 API 不代理材料正文。凭据仅在向导内存临时持有，关闭或保存受理后清理输入，不缓存到浏览器。macOS 如弹出系统 Keychain 访问提示，请在系统窗口完成操作。

账号卡片支持“重新核对”“编辑”“重新录入”“删除”。重新核对只检查本机材料可读取及格式有效，不请求商店；材料缺失时使用重新录入，保留原引用和已有应用绑定。编辑只修改显示名称。删除需确认，存在关联应用时必须先将绑定改用其他账号；删除只清理本机凭据，不影响商店后台的账号或应用。

保存中关闭页面不会撤销已经开始的存储。网络超时后使用“查询本次保存结果”，或在商店账号中重新读取；不要重复录入。保存不明会保留待核对状态，不自动重放材料。账号标签与操作记录独立保存于 `credential-accounts.json`，不修改 SDK Vault 格式。

CLI 保留为维护入口。在仓库目录的 macOS 交互终端运行：

```bash
pnpm credentials add
pnpm credentials list
```

`add` 录入公开引用和商店类型，然后关闭秘密输入的回显；不接受密码或密钥命令参数，不覆盖已有引用。华为使用 Client ID／Client Secret，Apple 使用 Issuer ID／Key ID 和本机 `.p8` 私钥文件。首轮 Apple 档案用于只读查询，不代表已配置构建上传所需的全部凭据和工具。凭据更新可在页面显式重新录入；维护 CLI 仍不覆盖已有引用。

命令显示“凭据引用”后，输入自定名称（例如 `huawei-work`）并按回车；商店类型输入 `huawei`、`xiaomi` 或 `app_store`。标注“输入不回显”的字段不会显示输入字符，输入完成后直接按回车。按 Ctrl+C 可取消当前录入。

标量通过仅使用私有 stdin 的系统 Security 桥接存入 service 为 `release-harbor` 的 macOS Keychain，写后完整读回核对，避免 SDK 密码提示截断长输入。文件凭据经 AES-GCM 加密后存入数据目录的 `credentials/profiles.json`；不扫描 SDK 默认凭据库。仅复制数据目录不能替代 Keychain 迁移。其他系统当前明确显示不支持安全存储。CLI 与服务须使用相同的 `RELEASE_HARBOR_DATA_DIR`。

应用详情进入“只读预检”，选择商店绑定及检查通过的安装包，然后显式运行；该页保留独立核验与历史查看，日常发布可直接使用“准备发布”，无需先切换到此页。如目录已变化可重新读取。worker 重新复核字节和身份，只向对应商店发起鉴权与应用查询，不上传或送审。华为／Apple appId 须为数字 ID；小米目标使用与 Android 身份相同的包名，必须明确允许版本更新。结果关联绑定版本、产物摘要及档案目录版本，有效五分钟；配置、文件、目录变化或环境不可用时失效。修改任一档案会保守地使旧结果失效；绕过 CLI 直接修改 Keychain 无法自动侦测，后续执行仍须再次核验。

预检页将执行配置、最新结果及历史分区展示。历史每页五条，可点击“详情”查看摘要、原始凭据引用、绑定版本及失效原因，翻页和查看详情不会重新执行预检。

记录独立保存于 `preflights.json`，重启后未完成项标记“无法验证／中断”，不重跑。预检通过只证明当次产物、鉴权和目标匹配，上传权限始终为“未验证”，也不构成发布授权。

## 发布计划与人工确认

在“发布中心”点击“发起发布”并选择应用，再选择已接入 Android 商店绑定、检查通过的 APK，填写更新说明后点击“准备发布”。系统自动进行账号、目标和实际产物只读核验，通过后保存不可变摘要；不用先手动运行预检或冻结计划。

正常情况下完成准备会打开“发布摘要”；刷新后也可点击“查看发布摘要”。核对应用、商店 App ID、版本、账号引用、更新说明及摘要，明确勾选后点击一次“确认保存草稿”（华为）或“确认提交审核”（小米／OPPO／vivo／魅族／荣耀），才会上传。关闭摘要不会授权或上传。取消本次发布只取消尚未执行的计划，历史保留；已消费授权不能重用。

准备失败会在原页提示，填写内容保持不变。修正材料、配置或安装包后重新准备。准备中刷新只读原进度，不重复检查；准备过程遇到服务停止时记录中断，不自动重跑。检查和确认仍受五分钟有效期及依赖变更约束，过期或变化时在原页重新准备，不自动延长旧确认。

计划、一次性确认、执行尝试和准备历史保存于 `release-plans.json`，同一队列原子替换；兼容读取版本 1／2／3／4／5／6／7／8，读取原有 preparations，写入升级为版本 9，容纳自动复用的小米资料、审核回执及跨平台上架意图；旧快照不回填字段或改写指纹。最终确认与消费同事务提交，失败不留下孤立授权；相同请求返回原事实。原有确认和执行接口仅保留兼容，日常页面不再分步调用。

执行记录区分复核中、远端执行中、草稿保存、执行前失败、中断与待核对。保存成功不代表送审或上线。当前简化入口开放华为草稿、小米已有应用更新、OPPO、vivo、魅族和荣耀普通应用单 APK 更新。小米自动复用公开上架的名称、隐私政策及图标；用户选择审核后立即上架或指定时间，摘要一次确认后才提交审核；小米已获用户可用反馈；OPPO、vivo、魅族和荣耀工程已验证、真实待验收，Apple 与其他渠道尚未开放。

执行器重新核对计划指纹、实际安装包、账号版本和商店目标；上传使用独立核验的副本，关闭 SDK 自动重试。远端写入前先持久化许可；之后任何超时、异常或回执丢失都保守标记待核对。服务重启只整理中断记录，不重放。待核对目标在未记录人工结论前禁止再次上传。

在“执行记录”点击“详情”，查看目标、版本、安装包摘要、写入许可与原因建议；旧记录没有具体原因时如实提示。到商店后台核对后，可点击“记录人工核对”：确认草稿已存在时，解除目标整体阻塞但继续阻止相同安装包重复上传；确认未保存且无处理中任务时，允许后续新计划。仍不确定则继续保留阻塞。保存要求输入原计划版本号、构建号并明确勾选；记录来源为本地用户人工声明，不冒充自动商店查询结果。结论不会恢复旧授权或自动执行，后续上传仍需重新预检、冻结并确认新计划。

Apple 团队 API Key 已接入独立 altool 上传，使用已配置的 Issuer ID、Key ID 和 `.p8`，不回退密码方式。上传后一次查询对应版本及构建，显示上传已接收、构建处理中或可用；处理失败及许可后异常待核对。说明和上架类型只记录意图，不提交审核、不设置发布策略。工程验证使用隔离合成材料，真实上传由用户在具体计划显式触发，见[使用说明](docs/guides/apple-build-upload.md)。

## 验证

```bash
pnpm typecheck
pnpm test
pnpm build
pnpm format:check
```

已安装 Google Chrome 的本机可额外运行 `pnpm test:smoke`；该检查使用独立端口和临时数据目录，验证真实浏览器创建、刷新持久化、导航和移动布局，并将截图保存到被忽略的 `artifacts/`。

本机安全存储适配如需单独复验，可运行 `pnpm exec tsx scripts/check-keychain.mjs`。它会在随机 Keychain service 中写入并清理合成材料，验证长输入、特殊字符和 Apple 加密文件；不会读取产品账号或请求商店。普通自动测试继续使用内存安全库。

## 开发规范

人工与 AI 开发均须遵守 [AGENTS.md](AGENTS.md)，修改前按范围阅读：

- [Web 前端代码规范](docs/governance/frontend-code-standards.md)：目录与组件职责、状态与 API、样式安全、中文注释和浏览器验证。
- [后端代码与注释规范](docs/governance/backend-code-standards.md)：NestJS 分层、公开合同、存储与执行边界、中文 JSDoc 和复杂流程注释。

涉及公开合同或跨端流程时两份均须阅读。规范对新增与实际修改的代码生效，历史内容按修改范围渐进调整；现有自动检查的覆盖范围以规范和实际脚本为准。

当前 API 仅监听回环地址并拒绝非本机 Host／跨站 Origin；没有生产认证。在线部署是产品演进目标，不是把当前端口直接暴露公网。浏览器可选中的文件必须通过明确上传或受信任执行器交接，线上 API 不能读取用户电脑的本地路径。

本地 Git 仓库已建立。产品命名确定为 release-harbor；远程托管平台、账号、可见性和软件许可尚未指定，不自动推送或授予开源许可。
