# 实施任务

## 本轮规划

- [x] 用户确认首版为同一个 Android 应用的多商店。
- [x] 核对单准备槽、五分钟授权、执行准入、JSON 事务和 Apple 互斥现状。
- [x] 形成交互、批次授权、模型、恢复及验收方案。

## B1 合同与存储

- [x] 新增批次、revision、限定确认、运行和证明的公开安全合同与精确守卫。
- [x] schema13 同文件保存，兼容 1–12 及 Apple，保持旧指纹。
- [x] 批次归属、预约及子计划旧路由旁路保护集成验证。

## B2 逐项准备

- [x] 同应用、多渠道 APK 分配与说明／上架逐行校验。
- [x] 异步逐项准备、稳定请求去重、部分失败和不可变摘要。
- [x] 每个新版本重新核验，同请求只读原事实；确认前配置变化不得静默替换意图。

## B3 一次确认与串行执行

- [x] 单渠道、批次、Apple 共用执行准入，确认事务登记 run、限定授权和预约。
- [x] 新批次证明、可信执行上下文及实际字节／目标复核，旧 local_once 不变。
- [x] 只有持久化首次写许可后才执行；全局并发 1，结果明确投影。
- [x] 虚拟时钟验证超过五分钟、60 分钟、定时已过及配置变化的准入边界。

## B4 恢复与独立结果

- [x] 独立失败、未知阻塞、成功去重、剩余允许项的新 revision。
- [x] 停止与 grant 竞态、启动中断、存储异常和刷新无重放。
- [x] 老单计划及 Apple 操作不能绕过批次预约或超额占用执行槽。

## B5 页面及验收

- [x] 原应用页内批次表单、一次摘要、结果列表和历史。
- [x] 键盘、桌面、390px、失败修正、停止、剩余项和刷新浏览器闭环。
- [x] 类型、集成测试、构建、格式及真实浏览器检查通过。
- [ ] 用户在明确账号、APK 和批次下完成真实渠道验收。
