# Android 多渠道批次需求

以下为拟实现需求，不表示功能已经上线。

## 需求：同应用目标与产物分配

系统必须仅接受当前项目下同一 Android 应用、1–7 个不重复的已支持商店目标。每项使用一个已检查 APK，明确冻结绑定 revision、artifactId、实际 SHA、版本、账号引用、动作、说明和上架策略。

### 场景：复用与独立渠道包

同一 APK 可以分配给多个商店，也可以使用不同 APK；versionName 须一致、buildNumber 按行显示并校验渠道递增。跨应用或平台、坏包、不同 versionName、重复目标和未知字段必须拒绝，不按文件名推断。

### 场景：渠道差异

华为保存草稿，其余既有动作不改名为草稿或上线。统一指定时间遇到魅族时必须报冲突，直到用户明确改选或移除；说明不自动截短或去 Emoji。

## 需求：逐项准备与固定摘要

系统必须先持久化请求再异步准备，首版逐项使用全局单准备槽，准备不能写商店。摘要固定目标集合及顺序，修改产生新 revision。

### 场景：部分失败

七项中两项失败时展示具体原因，不能暗中只执行另外五项。用户修正或移除后必须生成对应新 revision 和摘要；无授权的历史事实保留。

### 场景：请求丢失与过期事实

同一准备请求只查询或返回原记录，不重复商店检查。摘要明确各项检查时间及过期事实，旧预检不能被当作当前有效写许可。

## 需求：一次限定批次确认

系统必须在一份摘要中明确确认一次，消费 local_batch_once、登记 run 及目标预约。重复确认返回同 run，不延长窗口或重复创建任务。

### 场景：长队列

摘要完成后五分钟内可确认；建议首版允许确认后 60 分钟内开始各项首次远端写入。每项开始前必须重新核对原冻结意图，并保存至多五分钟内的临执行证明；不得续单计划授权或改写旧预检。超窗口项须重新准备与确认。

### 场景：变化或绕过

目标、账号、文件、说明、策略或已有来源锚点变化时，不得自动替换并沿用确认。外部请求不得提交证明、改变授权窗口或通过批次子计划的旧接口绕过归属和消费。

## 需求：受控派发与独立结果

单渠道、批次及 Apple 审核必须共用全局并发 1 的执行准入。确认只登记排队项，领取时才创建一次 attempt，首次写许可必须先持久化再 grant。

### 场景：失败不扩散

某项成功、某项许可前失败或某项结果未知时，其他独立渠道可继续。系统分别保留回执，不把结束或受理显示为全部已上架；未知项不自动重试。

### 场景：重复保护

其他批次预约、历史成功的同一产物和未核对目标必须阻止再次执行。换 batchId、revision、单计划路由或账号标签都不能绕过目标保护。

## 需求：停止与恢复

停止必须撤销未授予首次写许可的后续项，不能宣称撤回已获许可的当前商店操作。服务重启不自动续跑排队目标。

### 场景：停止竞争

停止先落盘则拒绝 grant；grant 先落盘则保存当前真实结果，剩余项不再派发。关页／网络中断不自动停止，也不重放。

### 场景：中断与补发

重启后有 remoteStartedAt 的未完成项为待核对，否则为执行前中断；未开始队列需重新准备。已成功同产物不补发，未知项核对明确未受理且无处理中任务后才可进入新 revision、确认和尝试。

## 需求：安全存储与历史兼容

schema13 必须保留现有四数组和 Apple 审核记录，新增批次聚合；读取兼容 1–12，旧指纹与授权事实不变。坏 JSON、未知版本或坏关联必须拒绝覆盖。公开合同不得含秘密、Cookie、解密资料或执行器路径；自动化仅使用隔离数据和受控网络。
