# 同一 Android 应用的多渠道发布批次

## 问题

当前每个商店分别选择 APK、准备、核对和确认，无法统一分配已有渠道包和集中查看一轮发布结果。现有准备、预检和执行均有单槽，五分钟单计划授权也不能直接供多个长任务排队使用。

## 用户确定的范围

2026-11-06 用户选择首版为同一个 Android 应用的多商店。支持既有华为 Android 草稿、小米、OPPO、vivo、魅族、荣耀和应用宝更新能力；不扩张各渠道动作或真实验收结论。

## 提议

在原发布计划页内提供多渠道批次：显式选择渠道、分配 APK、公共或行级说明／上架方式，自动逐项准备、一份不可变摘要确认一次、全局串行执行、逐项回执和安全恢复。批次新增限定目标及时间的授权模型，每项写入前复核并持久化证明，单渠道原五分钟规则保持。

## 非目标

不接入 iOS／鸿蒙混合批次、新渠道或百度；不构建／加工渠道包、不支持双包、不自动重试不明提交、不增加通用任务平台和公网服务。本轮先交付方案；并行写入需要后续独立切片及证据。

## 成功标准

正常一轮多渠道只确认一次；每行目标、包、动作和策略可核对，成功不重发、未知先核对，刷新与重启不会自动重复提交。既有单渠道及 Apple 审核历史保持兼容。完整边界和拆分见[实施方案](../../../docs/plans/android-release-batches-plan.md)。
