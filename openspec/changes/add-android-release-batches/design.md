# 设计决策

## 采用批次编排，复用渠道执行

批次是同应用内的意图聚合，不是把七条旧 API 并发发出去。准备逐项复用既有来源检查；执行复用独立 worker、副本及已证实渠道协议，不在 API handler 加 SDK。首版采用全局写入并发 1；单渠道与 Apple 审核也必须经过同一准入边界。

## 固定 revision 和子计划

每次准备产生不可变 revision；通过的子计划在同事务建立批次归属。摘要绑定完整目标集合、顺序、文件、说明及策略。失败项不能被自动移除；选择变化或重做失败项产生新 revision。批次子计划不得走单计划确认接口旁路执行。

## 授权和事实分离

原 local_once 的五分钟及预检约束保持。批次使用 local_batch_once，摘要确认窗口为就绪后五分钟，建议开始写入窗口为明确确认后 60 分钟，均服务端固定并在摘要说明。旧预检过期不伪装当前通过；临执行必须独立核对冻结意图、字节、账号、目标和已有来源锚点，追加新的安全证明。原计划、检查时间和摘要不修改。

worker 通过版本、nonce、目标及尝试 ID 发送白名单复核事实，控制面在同事务检查剩余授权、预约、时限及停止状态，保存 remoteStartedAt 后才授予一次 grant。不能后台续单渠道授权，或构造伪造的 confirmed ReleasePlan。可信 provider 改用明确的 StoreReleaseContext 并保留旧接口包装，来源查询不重复。

## 同文件原子性

拟写 schema13，保留 plans、attempts、preparations、appleReviews 并增加 batches。确认时只登记授权、run 和排队预约；每次领取才创建一个 attempt。首次写许可、消费、停止及终态由同队列协调。恢复兼容 1–12、旧指纹不变，坏 JSON 或坏关联拒绝覆盖。不得借两个 JSON 文件各自原子写宣称同事务。

## 恢复边界

每项目标独立保留成功／失败／未知，其他独立商店继续。成功同 SHA 和未核对目标沿用跨计划保护。停止只影响未获写许可的目标，页面退出不等于停止；重启后未开始项必须重新准备与确认，不自动续跑。补发只创建剩余允许项的新 revision 和授权，不复活已消费尝试。
