# 统一准备与确认执行

“准备发布”引用当前已保存的账号、目标、产物及资料，自动完成必要只读预检和快照准备，不向商店写入。用户在同一页面看到结果和摘要，不手动跳转多个页签。错误原地修复后重新准备。

摘要固定真实动作、应用、商店目标、产物版本及摘要、资料与有效期。最终操作明确显示“确认保存草稿”或“确认提交审核”，只产生一次用户执行确认。服务端以预期摘要、明确同意和请求去重保护，当前依赖有效后原子产生／消费限定授权与执行尝试；不能只在前端串联两个请求就声称具备原子语义。

重复点击、丢失响应及重启返回原受理事实，不重复派发。过期或内容变化在原页重新准备并展示新摘要，不能自动延长旧授权。准备取消不执行，执行开始后的关闭不冒充远端撤回。既有历史快照与人工核对记录保留。

当前已按下述合同实现华为公共入口，不增加未使用的通用任务队列或一次开放所有渠道。

## 本轮实现合同

- POST `/api/projects/:projectId/applications/:applicationId/release-preparations` 接收 requestId、绑定及产物引用、预期绑定版本／产物摘要和说明；返回 202 安全准备记录。系统登记后后台运行只读预检，通过后冻结计划；失败在记录中保留固定原因。相同请求只返回原记录，内容不一致冲突。
- GET 同路径读取准备历史，不发起商店请求。准备记录含归属、输入快照、状态、固定原因、关联预检／计划及时间。进行中重启仅标为中断，不重放查询或自动确认。预检创建或冻结与关联记录之间中断时可能留下无授权记录，恢复不派发。
- POST `release-plans/:id/confirm-and-execute` 接收预期摘要和 acknowledged:true，在同一计划存储队列中核对依赖、单槽及阻塞，原子产生限定确认与一次尝试。旧确认只复用不续期；取消、过期、冲突或存储失败不得留下孤立确认或派发。
- `release-plans.json` 升级为版本 4，增加 preparations 数组，兼容 1／2／3。未实现的 Apple 上传继续阻止；不用暂缓的 Apple 开发存储格式。
- 准备中刷新可读取原进度；内容修改需要新请求。摘要关闭没有商店写入，最终明确操作才执行。确认失效在同页重新准备，不静默重用。
