# 设计决策

详细交互、进程边界、拟议接口、保存状态和验收要求统一维护在[页面内商店账号配置向导方案](../../../docs/plans/credential-setup-wizard-plan.md)，避免重复维护两个合同版本。

- 用户面向“商店账号”和可读名称，reference 由本机服务生成，绑定仍保存既有引用。
- 允许本地向导短暂持有用户输入材料；材料直接交给独立本机配置进程，NestJS 业务控制面只处理会话控制及安全元数据。
- 仅监听回环地址，采用精确来源限制、短期会话和单操作关联，配置进程通过 provider 写入现有安全存储。
- SDK Vault 不增加自定义字段。名称及操作意图独立保存，以稳定 reference 核对；跨文件失败明确进入待核对，不宣称事务或自动重试。
- 旧 CLI 档案无需重录，保存、绑定及预检分别表达；后续在线模式不能直接复用本机端口或把当前会话当作生产认证。

实施时同步调整现有“Web 不接触秘密”的规范，为本地账号录入模块增加明确例外；本次仅规划，不改写现有实现事实。
