# 小米切片设计边界

先依赖公共发布入口简化，再按账号与绑定、只读核验、更新提交三个顺序开发阶段实施；不一次改造所有渠道。先核实更新提交所需资料，再确定各阶段实际 DTO 和存储版本。

浏览器材料只到独立本机配置服务。公开合同只放名称、引用、商店目标和安全元数据。小米 API 访问密码和签名仅在可信 provider 内使用；RSA 公钥按明确格式校验，不接受网页传服务器任意文件路径。必要的测试账号秘密采用独立受信任材料交接，不能进入普通公开计划。

现有绑定依赖数字 appId；小米按账号和包名定位，实施前明确目标标识合同，不能填假 appId 绕过验证。扩展时兼容既有华为／Apple 数据与守卫，不批量放开 OPPO 等未完成渠道。

只读查询按明确端点白名单限定，无写入副作用；查询失败或平台不允许更新则停止。计划固定当前应用、账号引用、产物摘要、说明、资料指纹及“小米提交审核”动作，不能以“草稿”确认替代送审确认。

独立执行器复核计划、期限、实际 APK 与资料，重新核对商店允许状态后，先持久化写入许可再单次提交。SDK 能力与本产品授权分开，失败不重试不明送审，原始商店消息不穿透。资料缺失、接口差异和签名问题先形成明确诊断，不以假成功补齐。

日常发版复用“准备发布 → 摘要中确认一次 → 执行结果”，预检和冻结由系统完成，不要求用户重复手动操作开发阶段。

当前不新增运行接口；具体字段和迁移将在各实现阶段开工前补入规格。此文档只完成接入方向与边界，不将未定字段写为已实现能力。
