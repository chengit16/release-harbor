# 设计与边界

- 计划以服务端读取的归属、应用身份、绑定版本与目标、产物身份及 SHA-256、凭据目录版本、通过预检记录、动作及更新说明形成快照；更新说明及配置分别计算 SHA-256，再计算整份快照摘要。不含秘密或本机路径。
- 冻结需要当前通过的预检。输入只允许预检 ID、动作、更新说明和幂等请求 ID；同请求重复提交只返回同计划，不能替换其内容。
- 确认要求精确允许的本机 Origin、专用请求头、预期计划摘要及显式同意，授权固定到该计划、动作和本地范围。有效期取确认后五分钟与原预检期限的较早者；重复确认不延长、不重新签发。
- 计划与授权元数据保存在独立 schemaVersion 1 的 release-plans.json，同一队列原子替换。快照不可修改，确认与取消为受控状态转换。取消终止该计划，撤销其授权；不创建任务。
- 查询、确认均重验当前绑定、凭据目录和预检（包括实际磁盘字节），返回明确变化项；失效不改写历史快照。存储无法读取时拒绝覆盖。原预检到期后需重新预检和冻结。
- 文件存储无跨存储事务，确认期间或之后发生的外部变化通过动态有效性使授权不可用。P1-5 必须在领取与远端调用前独立核对全部快照和授权，并原子消费；计划 ID 或授权 ID 均不是执行口令。本轮不提供消费或执行接口。
- 重启只读取已保存状态，不自动确认或派发。前端超时先刷新查询，不自动重发写请求。确认框取消不写入；计划取消需明确确认。
