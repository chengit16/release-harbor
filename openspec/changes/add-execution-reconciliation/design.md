# 设计

执行原始状态、摘要、许可和结束时间保持不变，额外记录固定诊断码及一次性人工核对。历史记录没有诊断码时显示“历史记录未保存具体原因”，不能推测旧失败原因。worker 通过严格白名单 IPC 回传诊断，不暴露供应商消息、路径、堆栈或秘密。许可后仍只标为待核对，不把异常推断为未上传。

release-plans.json 写入升级至版本 3，兼容读取 1／2 版本。人工核对只附加到已结束的 needs_reconciliation 记录，不能覆盖原结论。相同结论重复提交返回原事实，不延长时间；相反结论冲突。损坏文件拒绝覆盖。核对、解除阻塞及新执行在同一个串行存储队列处理。

核对输入仅含预期计划摘要、已核对版本和构建号、固定结论及 acknowledged:true。用户须在商店后台核对目标与任务状态。结论有草稿已存在、未保存且无处理中任务；仍不确定时关闭表单，不解除阻塞。保存来源为本地用户人工核对，不伪装自动商店核验。禁止自由文本，避免把材料录入回执。

未核对记录继续阻止同渠道和 appId；确认草稿已存在时解除目标整体阻塞，但阻止同摘要产物再次上传；确认未保存且无处理中任务时解除目标阻塞。任何结论都不派发任务、不复活旧授权；用户须重新预检并创建、确认新计划。人工判断可能有误，页面明确责任与边界，不声称远端自动核验。
