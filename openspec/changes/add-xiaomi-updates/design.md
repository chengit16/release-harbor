# 设计与边界

1. 渠道合同增加 xiaomi，目标 appId 在此渠道明确表示包名，创建与编辑均须等于应用身份；不要求填写数字 ID。历史华为／Apple 不变。
2. 凭据包含 userName、privateKey（平台 API 访问密码）、publicKey（PEM／证书）和 testAccountJson。测试材料按官方新结构严格验证；不同应用登录材料不同时分别建档。只读查询不发送测试材料。
3. provider 对 /dev/query 使用固定 HTTPS、POST、无重定向、有限响应、无重试；校验 result、唯一包名及 updateVersion=true。SDK 的预检未检查更新许可，故补充适配，不放宽其他渠道只读白名单。
4. 准备输入与计划可选 xiaomi 公开资料，增加需与后台查询一致的商店名称，严格限制键集、PNG 签名和尺寸、HTTPS 隐私 URL、图标摘要。仅小米动作可携带，快照指纹包含资料；旧快照不补字段、不改指纹。
5. 独立 worker 验证原件、副本、计划、账号版本及小米目标，重新查询许可。写入前复核授权与资料摘要，取得持久化许可后单次 /dev/push，固定 synchroType=1，传 APK、icon、隐私政策、说明及安全库中的结构化测试材料。签名按实际 RSA 长度分段，SDK 缺失部分集中 provider 实现。
6. result=0 仅投影审核提交受理。许可后任何错误、非零响应、中断或失去回执均待核对，不重试。人工核对区分审核提交与草稿，历史草稿字段保留兼容；不同渠道的结论不能混用。
7. 图标是非秘密的小型内联资料，便于原子快照及恢复；256 KiB 上限使 HTTP 和私有 stdin 保持有界。大素材与双包另排，不为本轮预建资产平台。

8. 计划存储读取版本 1–4，写版本 5；旧快照和指纹不回填。降级必须使用升级前备份，不手改版本号。页面审核测试材料采用普通字段，仅本机配置请求包含生成的 testAccountJson。
