# 本机团队操作审计（T4）

## 范围

管理员在成员管理打开操作日志，按操作者或目标成员、应用、动作与时间筛选，查看成员创建、启停、改密以及菜单／应用／兼容渠道权限的前后范围。发布摘要及执行详情展示准备、确认、尝试、首次写许可与人工核对人员，覆盖单计划、Android 批次和 Apple 已有构建操作。

## 持久化与失败边界

- 安装级 `team.json` 写 schema2，兼容只读 schema1；账号及管理日志在同一次串行原子替换提交。权限前后仅保存安全成员投影，不保存口令摘要、密码、Cookie 或商店材料。
- 发布存储在既有事务中比较不可变事实，只为新增事实先写安装级审计，再保存业务记录。业务记录仅在有审计时写 schema17，额外关联凭证与业务事实同文件提交，旧快照和摘要不变。两份文件不是跨文件事务：日志只有在唯一事件凭证、ID、时间、摘要与不可变事实指纹全部匹配时标为“已匹配”，否则明确标为“未匹配业务记录”，不能表示已准备或已执行。幂等请求不生成第二位操作者，未匹配意图不自动重放。
- 审计故障阻止新准备、确认、首次写许可和人工核对。终态回执落盘不新增审计写依赖，不因退出、撤权或审计故障丢失既有远端结果。尝试及回执从当前可信业务记录只读关联，不能把确认或许可说成商店成功。
- 总文件上限 16 MiB、事件上限 20,000，账号子集仍限 512 KiB；达到上限拒绝新增操作，绝不静默丢弃历史。仅单宿主写入，不声称防本机文件篡改。后续归档需独立设计。
- 账号、权限和审计均排除业务备份；恢复不重建会话、旧许可或操作者。历史缺失身份显示“历史未记录”，不从当前登录人、最近事件或版本号猜测。

## 读取边界

完整日志仅管理员可读，分页最多 50 条。发布详情查询重新校验当前菜单、应用及原绑定指纹；批次要求所有目标均可读，禁止裸 ID 或旧授权越界。所有 GET 仅读本机事实，不查询官方、不执行准备或恢复。

## 验收

使用隔离根、合成账号与执行器验证授权、分离准备和确认、撤权阻止后续许可、人工核对、幂等、故障、重启及备份恢复；浏览器检查桌面与手机筛选、详情和历史空态。工程验收不能代替真实商店送审、审核或上架。
