# 六期产品路线图

所有阶段以跨项目独立产品为目标，消费已有产物。各期独立定义范围、验收与 OpenSpec 变更；没有真实渠道证据的能力不标记完成。

| 期次                 | 交付目标                                                                   | 验收条件                                                           |
| -------------------- | -------------------------------------------------------------------------- | ------------------------------------------------------------------ |
| 一：本地最小发布产品 | 工作台、项目／应用、安装包接入与检查、凭据引用、计划确认、首批上传与回执   | 华为草稿和 Apple 上传按真实产物验收；取消不执行、变更需重确认      |
| 二：多渠道交付       | 小米、OPPO、vivo、应用宝等按需接入，产物分配、批次、受限并发与失败独立处理 | 不错配账号／包／目标，成功不重发，超时不明先核对                   |
| 三：审核与资料       | 华为／Apple 优先的真实状态查询、资料检查、查询证据和待办                   | 与后台正确应用版本一致，保留时间与来源，不将缓存当实时             |
| 四：送审上线编排     | 逐渠道能力矩阵、选择构建、批准资料更新、送审和上线等适配                   | 真实接口、动作授权、执行结果核验及异常补救均通过                   |
| 五：在线控制台       | 可部署 Web/NestJS、组织成员、数据库、对象存储、执行器配对及任务／回执协议  | 认证与租户隔离完成，远程用户产物可正确交接，云端不读取任意本机路径 |
| 六：团队自动化       | 可验证审批、独立调度、预约操作、异常通知、观测与恢复                       | 自动化身份与凭据经验证，任务授权有效，停止和不明状态处理明确       |

## 当前进度

第一期已完成工程基础、项目创建／读取／持久化，以及 P1-0／P1-1 的规格约定、SDK 静态核对、应用身份和华为／Apple 商店绑定维护。P1-2 已接入 APK／IPA 字节上传、独立本机身份检查、记录及失败／中断恢复，并完成合成数据下的本地验证。工作台采用白色主题与 Ant Design。P1-3 已接入安全 Profile CLI、只读预检和失效记录，完成替身及隔离浏览器验证；真实账号核验待验收。计划确认与商店发布链路尚未接入；第二至六期为规划。

第一期剩余工作的依赖、开发切片、规格准备和验收要求见[第一期实施计划](plans/phase-1-implementation-plan.md)。开发按“本期计划 → 切片规格与任务 → 实现 → 验收”推进，工程基础完成不代表第一期产品完成。

## 下一步优先事项

1. 应用身份与商店绑定模型已落地，包名／Bundle ID 与商店 appId 分开管理；后续围绕此模型核对产物与目标。
2. 产物交接、检查与记录已落地；本地路径仅限可信 Node 侧，Web 采用受控字节流。下一步将产物摘要绑定到预检及冻结计划。
3. 安全 Profile 配置与只读预检已完成工程实现，真实账号核验待验收；先实施 [P1-3A 页面内账号配置向导](plans/credential-setup-wizard-plan.md)，替换普通用户的终端录入及手写引用流程。该增量当前为规划；预检通过不等于上传权限。
4. 冻结计划和人工确认，复核文件、配置与更新说明指纹。
5. 华为草稿、Apple 构建上传真实验收及独立回执。

## 排期方法

第一至四期以发布动作成熟度递进；在线控制面的接口与执行器合同从第一期预留，第五期根据对外使用需求可提前。在身份和授权未落地前不直接公网暴露本地 API。自动化写动作在相应渠道与凭据环境验收后开放，不以复制确认 ID 替代授权。

固定工期在实际渠道、账号材料、产物和接口缺口明确后估算；平台审核等待与工程工时分开记录。
