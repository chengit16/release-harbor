# 六期产品路线图

各阶段以跨项目独立产品为目标，消费已有产物。阶段定义与实际渠道接入顺序分开记录；没有真实证据的渠道不标记完成。

## 当前推进（2026-11-06）

第二期渠道接入及同一 Android 应用的多渠道批次 B1–B5 已工程交付，首版串行写入。用户于 2026-11-06 对批次页面优化反馈“已验证通过”，记录为本轮页面体验验收；该反馈没有列明具体远端批次及各渠道回执，不扩展为所有渠道真实送审、定时及上架细项均已验收。批次实现依据为[多渠道批次方案](plans/android-release-batches-plan.md)。用户随后明确第三期暂缓，本轮优先完善独立发布中心、统一 iOS 记录、导航体验与文档进度；第三期“审核状态与资料中心”保留为后续方向，跨平台和并发 2 后续另行安排；百度可行性证据不足，按用户要求不排期。

以下第三期顺序仅为暂缓的候选规划，当前不据此启动开发或开放新商店操作：

1. **审核状态查询首片**：先核实各渠道官方查询能力、账号权限和版本匹配字段，再选一家具备条件的 Android 渠道实现。支持查看最后查询时间、明确刷新状态和失败原因；无法确认的状态保留未知，不从上传或送审回执推断已上架。
2. **发布跟踪视图**：将经过验证的状态查询逐渠道扩展，关联单次发布及批次目标，集中呈现审核中、被拒、待发布、已上架等可被平台证据支持的状态。保留来源、时间与历史，执行结果和后续审核状态分别显示；先提供手动刷新，自动查询须另行设计频率及停止条件。
3. **资料检查与待办**：集中显示商店可读取的资料及缺项，为审核拒绝、资料待补和人工发布形成操作指引。首片只读检查，资料写回和远端送审／上线仍通过明确动作及确认完成。

## 2026-11-04 确定的优先级

1. 保留华为 AppGallery 的 Android 草稿能力。
2. Android 新渠道依次为：**小米 → OPPO → vivo → 魅族 → 荣耀**，每次只开发和验证一家。
3. 上述 Android 渠道完成后恢复 **iOS／Apple**，未完成的 Apple 改动继续隔离保留，不作为当前 Android 开发的阻塞。
4. **应用宝、华为鸿蒙**放到上述 Android 与 iOS 渠道完成后另行安排，二者内部顺序届时确定。已有华为 Android 草稿不等于华为鸿蒙支持。

Apple 延后是开发顺序调整，不表示第一期原始验收范围已经全部完成。SDK 导出能力不等于当前产品已支持。

## 当前进度

截至 2026-11-05，本机工程、项目／应用／绑定、安全账号向导、APK／IPA 检查、只读预检、不可变计划、一次性执行、诊断和人工核对已交付。用户最新反馈“现在安卓全部渠道都可以了”，本轮已接入的华为 Android、小米、OPPO、vivo、魅族、荣耀据此记录为用户反馈可用。此反馈不包含尚未接入的应用宝及华为鸿蒙，也不代替各渠道定时上架等细项的独立证据，不改写历史失败记录或人工核对事实。

下一开发方向按既定顺序恢复 iOS／Apple：先核对现有 API Key 与上传工具适配，完成 IPA 上传和构建处理结果核对；再接入构建选择、资料检查、提交审核及立即／定时上架。沿用自动准备与一次明确确认；上传完成、审核受理、审核通过和已上架分别展示。该方向为后续计划，当前 Apple 执行仍未开放，暂存改动须先评审再恢复。

第二期实施安排见[Android 渠道计划](plans/phase-2-android-channels-plan.md)，当前首个新渠道为小米。其余渠道到各自切片再核实接口和动作，不一次铺开五套页面或执行器。

## 发布操作简化

开发接入阶段需要核实每家平台的差异；日常发版不要求用户重复研究或手工跑完技术步骤。

华为、小米、OPPO、vivo、魅族和荣耀 已实现交互：选择渠道与安装包、填写资料 → 点击“准备发布” → 系统自动只读校验并准备快照 → 在摘要中明确确认一次 → 系统执行并展示回执。

只读预检、快照与一次性授权仍由系统落实，界面不再要求用户依次切换预检、冻结、确认、执行四个入口。账号配置一次后复用；材料或目标变化时才提示处理。不同商店沿用同一操作方式，但最终确认明确显示真实动作，例如“小米提交审核”与“华为保存草稿”。

P2-0 公共入口已在华为链路完成工程实现与隔离浏览器验证；本轮未重新运行真实商店上传。小米切片也已完成工程及隔离浏览器验证，使用指南见[小米更新](guides/xiaomi-updates.md)。用户已反馈小米可用并授权 OPPO；OPPO 已完成工程接入、真实待验收，不同时展开后续渠道。

## 排期与验收

执行顺序为实施计划 → 切片规格 → 实现 → 工程验证 → 具体渠道真实验收。单渠道交付后才推进下一家；材料缺失时标记待验收，调整顺序按用户后续指令执行。批次与并发在单渠道流程稳定后按需落地，不提前构建通用任务平台。

在线接口从第一期预留，但身份与授权未落地前不直接公网暴露本地 API。不承诺材料缺口尚未明确时的固定工期；平台处理等待与工程工时分开记录。

OPPO 普通应用单 APK 更新已完成工程接入，沿用自动准备与一次确认，支持立即／定时意图及异步任务结果核对；真实 OPPO 验收待用户在具体计划执行。小米已获用户可用反馈，vivo 本轮工程接入、真实待验收，魅族与荣耀已工程接入、真实待验收，Apple 继续暂缓。

## 2026-11-06 Android 多渠道批次

同一个 Android 应用内的七家既有商店批次已工程接入。进入“发布计划 → 多渠道批次”，显式选择渠道、分配 APK 和说明、准备后核对一份摘要，再确认一次。首版全局串行，华为保存草稿、其余执行已有更新提交；结果独立，未知不重试、已成功的相同产物不重发。停止只取消尚未取得写许可的项；服务重启不续跑，剩余项需重新准备及确认。
