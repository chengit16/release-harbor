# 产品定义与首版范围

## 定位与用户

Release Harbor 是独立应用商店发布产品。个人开发者、团队发版人员和验收人员使用同一工作台管理不同技术栈的项目；接入只依赖合适的现有产物和商店资料，不依赖业务仓库的构建脚本。

核心价值是：多个项目配置后复用同一套流程，产物来源可核对，渠道动作可理解，执行与审核结果可追溯。

## 成品形态

产品以 Web 工作台作为主要操作入口。初期在本机运行；后续可部署在线控制台，执行器按需要留在有 SDK、签名检查工具和本机凭据的设备上。CLI 后续复用领域服务，不成为 UI 独占的一套逻辑。

主功能区为项目／应用、产物、渠道账号引用、发布计划、执行任务、审核状态、记录与设置。未完成能力不放置会误导用户的可执行按钮。

## 首个可发布版本

1. 用户建立项目与 Android／iOS 应用身份。
2. 配置已有商店应用与本机账号引用。
3. 明确交接已有 APK／IPA 并检查真实身份。
4. 填写已批准的说明与来源信息，生成计划。
5. 核对计划，明确确认后交由可信执行器上传。
6. 回到工作台查看脱敏回执与后台待办。

首批目标为华为草稿和 Apple 构建上传。Apple 后续选择构建、送审和发布仍需后台操作，直到正式接口适配和账号验收完成。

## 当前渠道优先级与操作目标（2026-11-04）

用户确定先完成 Android：小米、OPPO、vivo、魅族、荣耀依次接入；之后恢复 iOS／Apple。应用宝与华为鸿蒙最后处理。已有华为 Android 草稿能力保留。原始首批目标中的 Apple 当前延后，不能标记为已交付。

发布体验目标是填写资料、准备发布、在摘要中明确确认一次、查看结果。只读预检与快照冻结是系统内部步骤，不要求用户每次发版手动逐项运行；不同渠道统一操作，但确认按钮显示真实动作。当前运行版已在华为、小米、OPPO、vivo、魅族和荣耀链路实现简化入口；小米已获用户可用反馈，OPPO、vivo、魅族与荣耀真实待验收，Apple 及后排渠道仍暂缓，细节见[第二期实施计划](plans/phase-2-android-channels-plan.md)。

## 本次实际交付

- 独立 pnpm 工作空间、本地 Git 仓库和项目协作规则。
- NestJS + Fastify adapter 的运行骨架。
- Web 项目空间、项目创建／列表／详情与持久化。
- 公开合同、领域包、后端 SDK 身份检查适配。
- 项目输入、空间隔离、并发重复写、损坏文件和 HTTP 边界测试。
- 产品架构、完整路线、后续在线部署和商店来源说明。
- 第一期 P1-0／P1-1：规格管理约定、SDK 静态核对、Android／iOS 身份、华为／Apple 绑定、版本冲突保护与隔离文件存储。
- Ant Design 组件与主题统一到项目、渠道和路线图页面；应用与绑定交互通过真实浏览器验证。
- 第一期 P1-2：APK／IPA 字节接收、大小／空间边界、独立进程身份检查、摘要与版本记录、失败清理和重启中断恢复；页面沿用白色主题与 Ant Design。

第一期原始范围尚未全部完成。应用与商店绑定、产物检查、安全账号、只读预检、计划确认、华为草稿执行、回执、诊断与人工核对已交付；华为草稿已有用户后台核对反馈。Apple 上传暂缓，华为简化入口和小米已有应用更新已完成工程验证，小米已获用户可用反馈，OPPO 普通应用更新工程已接入、真实待验收，vivo、魅族及荣耀也已完成工程接入，真实待验收。本地合成包测试不代表生产签名或真实渠道验收。

## 接入约束

安装包必须符合目标商店的包名、签名与用途要求；产品不自动构建或重签。尚未支持的商店或远端动作需要开发适配，不能仅通过填写配置获得。

## 验收环境

基础版用本地 Node.js 24 验证，浏览器核对项目创建、重载持久化、错误显示及窄屏布局。真实发布另行要求明确账号、候选产物与授权计划，不能使用示例数据宣称商店已受理。

OPPO 普通应用单 APK 更新已完成工程接入，沿用自动准备与一次确认，支持立即／定时意图及异步任务结果核对；真实 OPPO 验收待用户在具体计划执行。小米已获用户可用反馈，vivo 本轮工程接入、真实待验收，魅族与荣耀已工程接入、真实待验收，Apple 继续暂缓。

## 2026-11-05 渠道进度

用户明确要求先完善魅族与荣耀、稍后真实验证。两家已有普通应用单 APK 更新已完成工程接入，真实待验收；各自完整送审独立验证，不把上游的文件暂存或草稿绑定当成成功。荣耀支持立即／定时，魅族公开 API 的定时能力尚无依据，明确禁用与拒绝。参见[使用说明](guides/meizu-honor-updates.md)。Apple 继续暂缓，应用宝与鸿蒙仍后排。
