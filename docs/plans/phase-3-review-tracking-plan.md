## 首片体验

打开发布中心的已执行荣耀计划，在发布摘要或执行详情中点击“查询荣耀状态”，无需再次确认上传。页面先自动读取本机观察历史，只有按钮才触发商店请求。

展示版本、查询时间、来源和明确状态；未识别码、其他版本或失败显示未知。失败不覆盖旧成功观察；重读本机历史不请求商店。审核未通过时引导到荣耀后台查看意见，意见原文与附件不传播。

成功查询保守间隔三小时，失败一分钟后允许用户再查，审核未通过或已上架不重复查询；审核通过后仍可在间隔结束后显式核对上架。相同 App ID 不因换计划绕过窗口。未完成查询预约重启后不自动续跑或宣称查询完成。

## 证据与精度

依据见[官方核对](../verification/phase-3-status-baseline-2026-11-06.md)。小米当前官方未开放审核状态，原推送查询和公开旧版本不足以实现；不因此生成猜测端点。

荣耀先按包名唯一核对 App ID，再匹配版本名和构建号。审核结果 0／1／2 分别为审核中、通过、不通过；3、4 或其他安全整数保留未知。`detail.releaseInfo` 只在目标与两个版本字段完全匹配时证明本次版本已上架；审核通过不能单独证明上架。

当前执行记录未保存荣耀原送审 releaseId，本轮查询的是对应版本当前流程，不能宣称准确查询原历史审核单。P3-2 先补锚点再扩展历史状态；魅族同样需要可靠 verId。查询频率为产品保守策略；官方三小时建议针对审核单查询，不冒称是 GET current 的硬限制。

## 边界与验收

- API 恢复目标、拒绝未执行和变更绑定，不解密账号；固定独立 worker 内认证与请求。
- 公开观察不含凭据引用、账号、原始审核意见、附件或原始响应；只存安全状态和时间。
- 原发布存储、回执、授权、人工核对均不改写；查询失败保留旧事实及新失败。
- 测试覆盖版本错配、包名与 App ID、私密字段、并发预约、冷却窗口、终态去重、重启、损坏与跨父级访问。
- 页面覆盖显式查询、刷新零新增查询、错误恢复、桌面及窄屏；工程测试使用合成材料，真实状态由用户具体版本另行核对。
