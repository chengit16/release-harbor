## 原执行关联首片体验（历史切片）

使用与“发布中心”并列的独立菜单“审核状态”。菜单集中展示已执行送审目标、版本、审核状态、查询时间与待处理项，支持项目、应用、渠道、状态和待办筛选。荣耀记录在详情中点击“查询荣耀状态”，无需再次确认上传。页面导航及刷新只读取本机历史，只有查询按钮才访问商店。

发布摘要与执行详情中的“查看审核状态”只负责携带当前应用及记录跳转，不再嵌入状态查询面板。单渠道及批次子目标逐渠道展示；Apple 只复用已有历史观察，其他未接入渠道明确提示能力边界，不根据提交受理推断审核中。

展示版本、查询时间、来源和明确状态；未识别码、其他版本或失败显示未知。失败不覆盖旧成功观察；重读本机历史不请求商店。审核未通过时引导到荣耀后台查看意见，意见原文与附件不传播。

成功查询保守间隔三小时，失败一分钟后允许用户再查，审核未通过或已上架不重复查询；审核通过后仍可在间隔结束后显式核对上架。相同 App ID 不因换计划绕过窗口。未完成查询预约重启后不自动续跑或宣称查询完成。

## 证据与精度

依据见[官方核对](../verification/phase-3-status-baseline-2026-11-06.md)。小米当前官方未开放审核状态，原推送查询和公开旧版本不足以实现；不因此生成猜测端点。

荣耀先按包名唯一核对 App ID，再匹配版本名和构建号。审核结果 0／1／2 分别为审核中、通过、不通过；3、4 或其他安全整数保留未知。`detail.releaseInfo` 只在目标与两个版本字段完全匹配时证明本次版本已上架；审核通过不能单独证明上架。

原首片未保存荣耀原送审 releaseId；2026-11-07 起，新执行保存可信审核单并按单查询，旧记录仍只匹配当前流程版本，不能猜补历史审核单。P3-2 已为魅族新提交保存并使用可靠 verId；旧魅族记录不按名称回填，缺锚点提示后台核对。荣耀新审核单锚点现已补齐，旧记录不回填。查询频率为产品保守策略；官方三小时建议针对审核单查询，不冒称是 GET current 的硬限制。

## 边界与验收

- API 恢复目标、拒绝未执行和变更绑定，不解密账号；固定独立 worker 内认证与请求。
- 公开观察不含凭据引用、账号、原始审核意见、附件或原始响应；只存安全状态和时间。
- 原发布存储、回执、授权、人工核对均不改写；查询失败保留旧事实及新失败。
- 测试覆盖版本错配、包名与 App ID、私密字段、并发预约、冷却窗口、终态去重、重启、损坏与跨父级访问。
- 页面覆盖显式查询、刷新零新增查询、错误恢复、桌面及窄屏；工程测试使用合成材料，真实状态由用户具体版本另行核对。

## 2026-11-06 官方状态查询与本地发布解耦

用户明确更正：审核状态应直接查商店，不以本地发布记录为前提。此安排取代前述仅已执行记录及锚点限定的主入口；旧按计划观察仍在“本地发布关联”保留，不能混淆目录版本与原执行关联。

默认“商店状态”列出当前应用的所有绑定，官网手动提交版本亦可查询。魅族读取官方 `/app/versions` 目录（没有构建号）；荣耀分开当前审核流程与已上架版本；Apple 读取版本及构建目录。vivo 只映射已核实待审核状态；OPPO、应用宝、鸿蒙读取官方版本资料，未核实审核字典时保持未知。小米说明官方未开放；华为 Android 说明独立查询尚待核实接入。具体范围见[查询指南](../guides/release-status-observations.md)。第三期资料待办仍在后续范围，不能据此标记第三期完成。

新 GET `/api/store-status` 仅读取可信绑定目录与缓存；POST `/api/store-status/:projectId/:applicationId/:bindingId/query` 要求本机来源及固定标记、空正文，从目录恢复目标进入独立 worker。API 不加载 SDK 或凭据。新 `store-status.json` 以绑定指纹隔离预约和快照，单进程队列原子写入；未完成预约三分钟、已完成十秒内避免重复，不自动重试。失败保留上次成功及其时间，导航不请求商店，不改写任何计划、回执、授权及人工核对。真实查询由用户具体目标另行验收。

## 2026-11-07 版本定位与资料待办首版

审核状态新增“待办处理”页签，与商店状态共用绑定筛选和详情。依据已有缓存列出审核需处理、等待手动发布、查询失败、需后台核对及资料待完善，保留来源、版本和查询时间；导航、刷新与待办推导不请求商店。原始审核意见与附件不直接展示，缺完整资料明确标记未检查。

OPPO 支持详情输入构建号，经控制面与 worker 双重校验，仅调用固定 info 路由的 version_code 参数；响应构建不匹配视为无法核对。默认目录与指定构建分开缓存，指定构建最多二十个，各保留最近失败及上次成功；同绑定继续共用预约，不能换构建绕过冷却。

小米可在后台核对后追加版本、可选构建号、状态、实际核对时间与简短备注。记录使用独立人工来源和请求编号，保存失败保留表单、相同重试幂等，绑定指纹变化后隔离。该记录不代替官方审核 API，也不解除原未知发布保护。

荣耀新执行将 submit-audit 回执 releaseId 与原终态同事务保存，计划存储写 schema15、读取兼容1–14；旧摘要、授权及缺锚点记录不回填。新关联查询按审核单核对 appId/releaseId；已有通过结论后仅查询在架资料，不再次请求结束审核单、不刷新旧审核结论时间。原本不依赖计划的商店状态入口继续保留。

Apple 区分等待开发者手动发布和等待商店发布，仅前者生成手动发布待办。详情按当前流程、在架和折叠历史分组；有限资料检查只说明本次可见字段，不能据此证明隐私、截图、合规材料完整。实际验证见[本轮验收](../verification/store-tracking-todos-2026-11-07.md)。第三期继续保留逐渠道新送审场景验收与完整资料读取的后续工作。
