# 工作台全站设计统一与布局优化

用户于 2026-11-08 授权按三个顺序全部实施。本轮沿用 React Web、Ant Design、白色主题与统一蓝色，不新增 UI 库或商店接口。设计检查采用 ui-ux-pro-max 的布局、可访问性与交互规则；技能附带检索脚本在当前安装中不可用，因此以仓库规范及真实 Chrome 页面为依据。

## 一、公共布局和视觉基准

- 菜单维持发布中心、审核状态、应用管理、商店账号、本机设置、帮助与支持，首页仅保留处理中、待确认、结果待核对三个小入口。
- 页头移除重复英文装饰，标题、介绍和业务区保持统一起点；桌面标题 24px、手机 20px，内容边距分别为 24px／16px。
- 颜色继续以 `app/palette.ts` 为唯一来源，组件配置沿用统一 ConfigProvider。正文、标签、提示分别表达信息层级；错误和执行授权不折叠。
- 次级帮助使用共用 PageHelp，手机筛选使用共用 PageFilters，折叠后显示已选条件数量；原筛选仍由 URL 管理。
- 增加键盘“跳至页面内容”入口，保留可见焦点和低动效；手机主要按钮、输入与选项扩大触控区域。

## 二、发布与审核主流程

- 发布中心可搜索应用、项目、版本与构建号，搜索值和分页保存在 URL；搜索只筛选本机结果，不新增请求。桌面保留分页表格；手机改为记录卡片，直接显示应用、平台、版本、渠道、处理状态、回执说明、时间和详情入口。桌面与手机共用 URL 页码。
- 审核页压缩为概览与刷新、筛选、列表；非实时与查询来源说明按需展开，查询时间仍显示在记录中。三个主要页签保留，旧本地发布关联从“更多”访问，旧深链仍有效。
- 单渠道发布表单采用编辑区与本次概览，较窄视口改为单列；概览来自当前草稿，不是冻结摘要，不表示远端核对通过。
- 已选渠道使用只读摘要表达，原绑定字段继续参与校验。安装包上传和选择放在同一编辑分区，上传是次级动作，更新说明和上架策略不会因刷新卸载。
- 服务端准备、冻结摘要、明确一次确认、取消、未知结果核对和防重复保护保持原职责。执行、受理、审核通过和上架继续分别展示；不新增自动查询或发布。

## 三、配置、设置和支持

- 应用目录在可信本机绑定读取后显示已配置渠道，缺项或摘要读取失败分别表达；进入目录不鉴权、不预检、不查询商店。
- 账号目录不再重复标题与大型介绍，改紧凑行。详情集中本机材料检查、更新凭据、改名和删除，原关联删除保护及独立敏感录入流程不变。
- 设置通用运行说明改为次级帮助，通知设置使用统一行布局；恢复操作独立危险区，仍须预览和明确确认。容量按 B／KiB／MiB／GiB／TiB 展示。
- 商店指南优先提供按任务跳转与渠道筛选，手机能力卡片取代表格；渠道限制完整保留在可展开说明中。
- 问题档案保留搜索和筛选，统计缩小；路线图先展示当前本地效率安排，第三、四期交付详情按需展开，六期路径仍可查看。

## 验证与交付

需通过类型检查、全量自动测试、构建、格式和真实 Chrome 完整冒烟。新增设计回归核对首屏记录位置、手机卡片与筛选、URL 恢复、页签、账号标题、几何对齐、键盘入口、低动效和导航零写入；使用 1440px、375px、844px 及 720px 桌面折半可用宽度检查。720px 是响应式压力场景，不代替所有系统浏览器缩放模式。

截图人工复核与行为断言共同验收。测试仅用隔离合成数据，不操作真实商店或账号；工程检查不能替代各渠道真实送审验收。实际结果见 [设计验收记录](../verification/workbench-design-2026-11-08.md)。
