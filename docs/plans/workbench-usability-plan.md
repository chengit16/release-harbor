# 工作台菜单与使用流程精简方案

日期：2026-11-08。用户已确认以发布中心为首页，首屏仅放“处理中／待确认／结果待核对”入口，按以下三个顺序实施。

## 一、入口与信息精简

- 保留发布中心、审核状态、应用管理、商店账号、本机设置五个日常入口，将商店指南、问题档案、产品路线图收进帮助与支持。旧 URL 继续恢复原内容。
- 手机使用菜单抽屉，避免全部菜单横向排列。
- 首页三个入口只筛选本机发布摘要，不触发商店查询。普通失败、摘要过期与未知结果分别表达；人工核对完成不改原终态，但不再计入未核对入口。
- 审核统计统一按当前筛选下的渠道计数；历史已下架／被替代版本留在详情，不混入主列表摘要。当前在审和旧版在架可同时保留，不能互相覆盖。
- 账号操作使用“检查本机材料／更新凭据”，改名和删除放更多操作。材料已保存不表示商店权限有效。
- 设置按存储、备份、通知、诊断排列，默认存储。通知记录统一在顶部查看；恢复保护与审核资料／跟踪表单按需展开。

## 二、配置与发布路径贯通

- 应用管理默认平铺应用，项目是可选分组和筛选。保留原项目、应用和配置页签深链。
- 新建应用向导为应用信息、渠道配置、就绪检查。无项目时建立默认分组，自动生成内部标识，技术栈默认 other；平台与真实包身份仍需明确填写。应用创建失败保留输入，项目已经保存时不重复创建。
- 渠道内复用现有账号选择和独立本机凭据向导，秘密不进入普通 API 或浏览器存储。
- 新发布只选择一次渠道，单选进入单渠道计划，多选进入 Android 批次；原计划与批次确认合同保持独立。华为多选批次仍只保存草稿，正式送审须单独选择并明确指定动作。
- 发布页可上传并检查安装包，检查完成刷新可选项，不清空更新说明或策略。模板仍要求重新选包和具体时间。
- 配置页用户名称改为“渠道配置／安装包／发布前检查”，不在配置页重新嵌入发布表单。

## 三、启动与首次环境检查

- 提供 `pnpm workbench` 和 macOS 双击启动文件。检查 Node、依赖和端口；已运行的本机工作台复用，不自动结束其他程序。
- 新实例构建当前页面后启动回环 API，健康和页面就绪后才打开浏览器。不安装软件、不修改系统配置、不开放公网。
- 新用户首页提供“检查本机环境”和“新建第一个应用”，环境检查复用本机诊断，不触发商店鉴权。
- 保留开发命令 `pnpm dev`；桌面应用包装、在线账号与团队化仍不在本轮范围。

## 验收约束

覆盖首页精准分组、旧链接与前后退、向导失败保稿、配置缺项、上传后选项刷新、草稿不丢、导航零商店动作，以及 1440／375／844 视口和页头几何对齐。单元测试只用隔离目录、合成材料和替身网络；真实渠道送审、上架与系统通知投递单独验收。
