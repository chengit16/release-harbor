# 第四期实施计划：送审与上线编排

**编制日期：**2026-11-07

**状态：**第三期工程范围已完成；第四期规划及 P4-0 渠道能力矩阵已完成，尚未新增第四期运行时功能。已核实华为 AppGallery Android v2 提供正式送审 API；下一项拟实现已有应用更新送审及受约束的上架策略。

**依据：**[产品路线图](../ROADMAP.md)、[产品定义](../PRODUCT.md)、[领域术语](../../CONTEXT.md)、[架构设计](../ARCHITECTURE.md)、[第三期状态查询指南](../guides/release-status-observations.md)及[第三期资料能力核对](../verification/phase-3-materials-capabilities-2026-11-07.md)。

## 1. 目标与边界

第四期把已存在的渠道发布动作收敛成清晰、可核对的送审与上线流程。用户能明确选择目标版本／构建、可修改的商店资料、送审动作及审核后的发布策略；系统只呈现渠道官方 API 实际支持的能力，并保留每一步的授权、远端回执和状态来源。

本期不重做已有的账号配置、发布摘要、一次确认、批次队列或审核状态菜单。已有渠道流程属于基线，须先盘点再决定是否需要修改。第三期官方只读查询继续与本机执行记录分离；状态读取不触发发布。

明确排除：新增商店接入、在线多租户控制台、定时后台调度服务、自动轮询通知、商店资料自动写回、未知结果自动重试。若官方接口不支持某项能力，产品须显示“商店不支持／需到后台处理”，不能以浏览器模拟点击、私有接口或本机定时器伪造支持。

| 能力               | 已有工程能力                                                                              | 第四期需要核对的缺口                                                                           |

| iOS 送审与发布     | Apple 已有构建送审、审核后自动发布／手动发布和单独手动发布流程                            | 复核构建处理状态、版本关联、审核策略冻结、自动发布实际生效证据与手动发布的确认边界             |

| 商店资料           | 现有更新大多复用商店资料，部分渠道有只读资料投影                                          | 明确每个渠道能否在同一次更新中修改名称、文案、截图、图标、隐私资料及语言；不重复询问可复用资料 |

## 4. 推进顺序

先完成 P4-0。随后按 P4-0 发现的实际缺口排定 P4-1 至 P4-4 的渠道切片，每次只实施一个可独立核对的行为；不为了表格完整而改动已正确工作的渠道。若 P4-0 证明某项已经实现且证据充分，只补齐文档／回归证据，不重复建设。

渠道次序优先处理已有用户真实反馈且风险较高的策略映射，其余按用户实际发版顺序推进。需要真实账号权限、目标版本或产物时，将远端验收列为用户操作项；不因此阻塞可独立完成的合同、隔离测试和页面完善。

## 5. 安全与行为约束

- 发布动作必须绑定项目、应用、商店绑定、明确版本／构建、真实产物、资料、动作和策略；每次变更生成新摘要。
- 页面只通过公开合同展示安全字段。商店秘密、个人审核材料、私人网址、自由文本审核意见和附件不进入普通 API、日志、URL 或缓存。
- 继续使用一次明确确认、一次性授权、独立可信 worker 和写入前持久化许可；不新增隐式授权或隐式重试。
- 许可后超时、进程中断或回执不完整均进入待核对；在官方状态或人工核对厘清前，阻止对相同目标重放。
- 批次逐项沿用单渠道限制。停止操作只影响尚未取得远端写许可的项；已开始的商店操作须记录真实结果或待核对。
- 状态查询、页面刷新和历史查看保持只读，不能借发布编排启动商店查询或执行计划。
- 新的第三方能力必须有官方依据及合成替身测试；未核实的字段与状态保持未知。

## 6. 验收门槛

- 合同与领域测试覆盖平台／应用错配、版本与构建选择、摘要变化、时间边界、重复确认和结果不明。
- 存储测试覆盖旧快照兼容、失败恢复及损坏文件拒写；不读取本机真实账号材料。
- provider 替身测试验证固定路由、请求字段、返回身份、状态映射、无重试及无秘密泄漏；不得使用真实商店账号或提交。
- 页面变更通过桌面与窄屏 Chrome 冒烟，核对对齐、标签、错误恢复、筛选和确认摘要，不仅检查无溢出。
- `pnpm typecheck`、`pnpm test`、`pnpm build`、`pnpm format:check` 必须按项目约定执行；页面变更另运行 `pnpm test:smoke`。
- 工程验收和真实商店验收分开记录。真实验收只绑定用户明确选择的账号、应用、版本、产物和动作；上传、受理、通过、定时生效及上架各自取证。

## 7. 当前启动项

P4-0 已完成，九个商店目标的工程动作、资料处理、发布策略、状态证据及真实验收边界见[渠道能力矩阵](../verification/phase-4-channel-capability-matrix-2026-11-07.md)。矩阵确认华为 AppGallery Android 当前只有草稿流程；官方 v2 文档具备 APK 上传、文件信息更新及 app-submit 接口。P4-1 将核实请求字段、策略时序、凭据权限和旧草稿执行的兼容后，实现限定的已有应用更新送审。不使用鸿蒙 v3 接口推断 Android 能力。其他渠道真实验收仍逐项记录，不因矩阵完成而标记已验收。
