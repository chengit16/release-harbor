# 第一期实施计划：本地最小发布产品

**编制日期：**2026-11-03  
**状态：**第一期进行中，P1-0 至 P1-3 已完成本地实现与合成数据验收；华为真实预检和草稿保存已获用户后台核对反馈；Apple 待验收。P1-3A 页面内账号配置已完成本地工程实现，真实安全存储录入待验收；P1-4 已完成本地计划冻结与人工确认，下一步为 P1-5。

**依据：**[六期产品路线图](../ROADMAP.md)、[产品定义](../PRODUCT.md)、[领域术语](../../CONTEXT.md)、[架构设计](../ARCHITECTURE.md)、[前端规范](../governance/frontend-code-standards.md)和[后端规范](../governance/backend-code-standards.md)。

## 1. 路线图与实施计划的关系

六期路线图确定产品演进顺序、阶段目标与完成标准。本计划将第一期剩余工作拆为有依赖、可独立验收的开发切片；每个切片在实现前通过 OpenSpec 变更细化字段、接口、规则、交互和测试任务。

执行顺序为：路线图 → 本期实施计划 → 切片规格与任务 → 代码实现 → 工程验收 → 真实渠道验收 → 更新进度。进入后续切片时复核前置条件；不因页面可点击或本地测试通过就把整期标记完成。

本计划按切片推进，本轮已进入应用与商店绑定开发；配置真实凭据与执行商店写操作仍需对应切片及具体授权，不提前排第二至六期的具体开发任务。

## 3. 第一期范围与完成定义

第一期交付一条可追溯的本地流程：建立项目与应用 → 绑定商店目标与凭据引用 → 交接并检查产物 → 只读预检 → 冻结计划 → 人工确认 → 执行 → 查看脱敏回执与待办。

首批动作遵循产品定义：华为保存草稿、Apple 上传构建。其他渠道、多目标批次、受限并发、审核状态中心、自动送审、自动上线、组织认证、公网部署及预约自动化留在后续阶段。

第一期整体完成必须同时具备：

- 工程验收：本计划各切片的领域、合同、持久化和真实浏览器检查通过。
- 安全与恢复验收：取消确认不执行，关键内容变化需要重新确认，重复触发受控，远端结果不明时保留待核对状态。
- 真实渠道验收：在明确授权的账号、目标和真实产物上，分别取得华为草稿与 Apple 构建上传的可核实证据。

缺少真实环境时可记录“工程实现完成，真实渠道待验收”，不得写“第一期完成”。不将上传结果扩展解释为送审成功或已上架。

## 5. 各切片的规格重点

### P1-0：规格与能力核对

- 建立最小 OpenSpec 目录与使用约定，明确提案、规格、设计、任务和验收记录的归属；本计划不代替正式规格。
- 首先为 P1-1 编写具体规则与测试场景，后续切片在开始前各自细化，不一次冻结全部接口。
- 对照锁定的 `@huoye/app-ship` 版本核对检查、计划、执行、确认与回执的真实导出，记录与产品需求的差异。
- 以现有研究作为历史背景；正式适配前重新核实相关能力、凭据环境、Apple 工具链及运行限制，不把旧文档结论当作最新保证。
- 明确本地 API 与未来本地执行进程之间的身份、允许动作和数据边界；不提前实现第五期的远程配对和生产租户体系。

### P1-1：应用身份与商店绑定

- 候选应用字段包括归属、平台、展示名称以及 Android 包名或 iOS Bundle ID；真实字段、长度、规范化和唯一性规则在该切片规格中确定。
- 商店绑定表达应用、渠道、商店 appId 和凭据引用；包名／Bundle ID 不替代 appId。持有引用不代表已经预检通过或具备发布权限。
- 首轮限定创建、读取与必要的绑定维护；删除应用、批量导入、平台迁移等额外能力不默认纳入。
- 检查项目、应用和绑定的工作空间归属及父子关系；同一标识是否允许在不同项目复用须在规格中明确，不能仅靠 UI 防重。
- 应用身份或商店绑定变化对已有产物、预检和计划的影响必须有规则；后续存在冻结计划时，不能使其静默指向新目标。
- 文件存储新增实体时确定结构版本、既有 `projects.json` 的兼容策略与中断恢复，不能覆盖用户已有项目。
- Web 增加项目到应用、绑定的明确导航、空状态、失败反馈和刷新恢复；在受影响范围拆出 API Client 与业务组件。

### P1-2：产物交接与检查

- Web 采用受控字节流上传；规格明确大小上限、流式处理、受控存储键、所有权、中断清理与磁盘不足行为，不读取用户填写的任意路径。
- 本地路径仅在可信执行侧解析；控制面和 Web 只持有公开产物标识及安全元数据。大文件传输与商店长时间上传分开设计。
- 服务端／执行器根据真实文件检查格式、包身份、版本、大小和 SHA-256，并验证目标平台与应用身份；不只信任文件名、扩展名或浏览器摘要。
- 不重复实现 SDK 已经可靠提供的检查；缺失的签名或工具能力显式说明，不以“检查成功”泛化为“满足所有商店要求”。
- 产物记录需区分接收中、检查失败及可用等实际状态；上传成功而检查失败时不得作为可执行产物。

### P1-3：Profile 与只读预检

- Profile 只存公开配置和凭据引用；凭据录入、存储与解析归可信本地提供器，秘密不经过 Web 或公开 API。
- 预检结果区分未检查、通过、失败和无法验证，保留检查时间、适用对象与脱敏原因。
- 按渠道能力检查所需工具、凭据可访问性及商店目标；本地引用存在不等于远端账号具备权限。无法验证的检查项不能显示通过。
- 确定预检有效期及配置、产物、目标变化后的失效条件；不让旧预检结果授权新的发布意图。

### P1-3A：页面内账号配置向导

用户已选择页面内配置方式。具体交互、材料边界、独立本机配置进程、会话、存储恢复和验证要求见[页面内商店账号配置向导方案](credential-setup-wizard-plan.md)，规格与任务见[对应 OpenSpec 变更](../../openspec/changes/add-credential-setup-wizard/proposal.md)。接口与页面已实现，工程验收见[对应记录](../../openspec/changes/add-credential-setup-wizard/verification.md)；真实 Keychain 录入与商店核验仍需单独验收。

- 商店绑定改用按渠道筛选的账号选择，支持新增向导及自动回填；内部 reference 自动生成，旧 CLI 档案继续可用。
- Web 的局部录入模块允许短暂持有输入，材料直接提交本机配置服务；业务 API 与公共合同仍不接收材料。实施时同步具体规范例外。
- 账号保存、商店绑定与应用预检分别表达，保留既有版本与失效规则；结果不明先查询同一操作，不自动重复保存。
- 全流程不要求终端录入，继续使用白色主题及 Ant Design；真实存储和渠道核验另行记录。

### P1-4：冻结计划与人工确认

- 快照固定归属、应用、商店目标、产物身份与摘要、明确动作、更新说明和配置指纹；不包含秘密或执行器本机路径。
- 展示人可理解的确认摘要与变化项，确认授权绑定确定的计划内容和允许范围；复制一个确认 ID 不能绕过授权校验。
- 规格明确授权有效期、消费与撤销规则、重复确认和并发点击行为；本地模式也需要可信来源和限定范围。
- 用户取消时不产生可执行任务。文件或关键配置变化使旧确认失效，执行前再次校验摘要与授权。
- 计划、确认、任务与记录的持久化顺序需可恢复，不能因进程重启丢失授权状态或重复派发。

### P1-5：执行与验收

- 实现独立的本地可信执行职责，不在 Controller 的长请求中调用商店上传；最小启动、任务领取、停止与回报机制在切片设计中明确。
- 每次执行建立独立 attempt，核对身份、目标、动作、摘要和授权后才解析凭据；串行完成首批目标，不扩展到第二期并发批次。
- 明确派发、领取、开始远端调用和持久回报的边界；进程中断、超时及回报丢失进入待核对，不自动重复不明写操作。
- 华为草稿与 Apple 上传分别保存脱敏回执和后续后台待办。可核实的受理证据不足时保持待核对，不宣称完成。
- 用户停止本地等待或终止进程不能被描述为远端撤回。不能安全取消的阶段应明确展示事实。

## 6. 验收与证据

| 层级         | 重点场景                                                           | 记录方式                                          |
| ------------ | ------------------------------------------------------------------ | ------------------------------------------------- |
| 领域与合同   | 身份及平台错配、跨归属、摘要变化、确认失效、重复执行和结果不明。   | 自动化测试及合同变更记录。                        |
| 存储与恢复   | 同时写入、既有项目兼容、损坏文件、中断上传、重启后任务／授权恢复。 | 隔离临时目录测试，不读取个人真实数据。            |
| API 与浏览器 | 无效输入、错误反馈、导航、刷新恢复、重复点击、取消、键盘与窄屏。   | 接口测试及真实浏览器冒烟证据。                    |
| 执行适配     | SDK 错误、超时、凭据不可用、回报失败与脱敏。                       | 可控替身测试，不发送真实商店提交。                |
| 真实渠道     | 明确账号、应用、产物、动作与授权计划，核对平台实际受理结果。       | 脱敏验收记录，关联计划、attempt、时间与证据来源。 |

各切片完成时执行 `pnpm typecheck`、`pnpm test`、`pnpm build`、`pnpm format:check`；页面变化另执行 `pnpm test:smoke` 及该切片所需的浏览器检查。只有本地测试和替身测试时，进度标明真实渠道待验收。

真实验收账号与材料不写入 Git，验收证据去除秘密与敏感路径。普通自动化测试不能调用真实账号或发送商店提交；最终真实验收单独执行，授权到具体计划及动作，不从“同意开发”推导发布授权。
