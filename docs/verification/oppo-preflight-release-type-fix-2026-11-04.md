# OPPO 预检误拦截修复

## 现象与原因

用户反馈 OPPO 预检显示“商店应用尚不具备查询条件”，产物复核与鉴权通过，商店目标未验证。

2026-11-04 对同一目标执行受限只读诊断，仅访问 token 和普通包详情接口。平台返回 `type=7`、`is_freeze=0`、`state=1`、`audit_status_name=上线`、`update_info_check=0`，但未返回 `release_type`。原实现无条件要求该字段为 `1`，误将缺省转换为不支持的状态，因此得到 `application_not_ready`。

[官方普通包详情](https://open.oppomobile.com/documentation/page/info?id=11004)的字段表列出 `release_type`（全量／分阶段），但其响应示例也省略该字段。不能据字段表推定所有真实详情都必然返回它。

## 修复与边界

仅兼容字段未出现的详情；出现时仍须等于 `1`。显式 `null`、空字符串、未知值及分阶段值继续拒绝。其他身份、上线、冻结、资料审核、资料完整性和构建号递增规则不变。预检和执行共用资料校验，因此同步修复执行前复核。

新增不含真实材料的回归场景，修复前得到 `application_not_ready`、修复后为 `verified`；覆盖立即模式的缺省详情、定时模式的显式全量值，以及明确异常状态的拒绝。

修复后同一真实目标的只读资料核验为 `verified`，鉴权与目标均通过。本记录不包含供应商原始正文、联系人、测试材料、密钥或安装包；不改写旧失败记录，不代表已经上传、送审或上架。

## 完整预检的后续限制

通过真实 Chrome 页面对用户所选 APK 重新运行完整预检，现已越过原先的状态误判，返回 `oppo_version_not_newer`。只读核对确认该 APK 的 `buildNumber=875`，商店最新版本的 `version_code=875`；相同构建号不符合更新规则，需要重新构建大于 `875` 的 APK，不能只修改显示版本名或绕过检查。页面刷新后仍保留该明确提示；旧 `application_not_ready` 记录作为历史失败保留。

## 工程验证

在当前基线的独立 worktree 中仅叠加本次五个文件变更，`pnpm typecheck`、`pnpm test`（97 项）、`pnpm build`、`pnpm format:check` 均通过。真实 Chrome 已核对当前工作台的完整预检和刷新持久化。

额外运行的隔离全站 `pnpm test:smoke` 在首屏等待“从第一个项目开始”时超时，尚未进入 OPPO 流程，不能记为通过；本次没有修改页面或该脚本。共享工作区的并行问题中心开发曾导致类型与格式检查失败，其改动不纳入本次修复提交。
