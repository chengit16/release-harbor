# 工作台隧道来源 403 修复与接口核对

日期：2026-11-10。问题编号：RH-0067。

## 复现与根因

用户从已指定的 cpolar 域名进入发布中心，保存当前配置为模板以及准备五渠道发布时遇到 403。对本机正在运行的 API 发送空正文及固定不存在目标，仅改变 Origin：本机来源返回 404“项目不存在”，cpolar 来源返回 403“请从本机工作台明确操作”；批次返回 403“请从本机工作台进行计划操作”。未发送真实发布意图或访问商店。

全局请求保护和独立状态查询已允许该域名，但 `main.ts` 传给发布计划与本机维护服务的来源数组只有回环地址。模板复用维护门禁，批次复用计划门禁，因此页面可以读取，明确操作却被第二层来源校验拒绝。前端已发送对应操作标记，代理并非本次根因。

回归命令为 `pnpm exec tsx --test tests/workbench-origins.test.ts`。修复前四个回环来源通过，两个指定隧道来源均在模板端点返回 403；修复后同一生产启动装配通过。测试不手动拼接业务白名单，避免测试夹具掩盖入口遗漏。

## 修改与同类接口

普通业务全局与服务门禁统一读取 `workbenchOrigins`，保留两个已指定域名的精确匹配。账号配置单独读取 `credentialSetupOrigins`，不将外部来源传入凭据私有协议。

| 接口组                                           | 本次核对结论                                               |
| ------------------------------------------------ | ---------------------------------------------------------- |
| 模板保存／删除、原文件清理、备份删除             | 原先使用本机维护门禁，存在同类遗漏；已统一                 |
| 本机设置、备份、恢复预览／确认、跟踪、保护核对   | 同类遗漏；已统一，原确认与维护约束保留                     |
| 单渠道准备、计划冻结／确认／取消、执行、人工核对 | 原先使用计划门禁，存在同类遗漏；已统一                     |
| 批次创建／编辑／准备／确认执行／停止             | 共用计划门禁；已统一                                       |
| Apple 目录／准备／执行／人工核对、原计划状态观察 | 共用计划门禁；已统一                                       |
| 独立商店状态、指定版本资料检查、人工记录         | 原先已单独放行域名；本次改为统一来源装配                   |
| 项目、应用、绑定、安装包与只读目录               | 没有额外业务来源数组，沿用全局精确来源保护                 |
| 账号会话与管理、独立材料提交                     | 继续仅允许服务所在电脑的回环页面，403 提示明确说明操作位置 |

回归通过真实生产入口启动独立端口、空临时数据目录；普通业务请求使用不存在目标、无效正文，断言抵达 400／404 的格式或归属检查，且缺失操作标记或 Origin 仍返回 403。额外验证非本机 Host、任意域名、伪装子域和 `Origin: null` 被拒绝；本机账号无效输入到达格式校验，隧道账号请求明确拒绝。

## 交付验证与使用

`pnpm typecheck`、289 项 `pnpm test`、`pnpm build` 及专项来源回归通过；`pnpm format:check` 全仓检查通过。`node --import tsx scripts/workbench-origins-smoke.mjs` 使用真实 Chrome，将整个指定域名拦截映射到隔离生产宿主，保留浏览器实际 Origin；点击模板保存返回 201，点击五渠道准备返回 202。五目标因空账号目录全部检查失败，没有确认、执行、真实商店请求或执行记录。这证明来源与准备入口可用，不代表五渠道远端准备或送审验收。

运行中的开发宿主已自动重载；再次从本机及用户真实隧道发送空正文、固定不存在目标，模板返回 404 归属错误、批次返回 400 格式错误，均不再发生来源 403。没有修改用户模板、批次或发布记录。

代码更新后需重启实际提供 API 的服务，再刷新原域名。启动器复用健康旧实例时不会自动替换进程，单纯刷新页面无法更新服务端白名单。已有材料可继续用于发布；需要维护账号时在服务所在电脑打开本机地址。
