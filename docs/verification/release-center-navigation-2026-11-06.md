# 发布中心与菜单调整验收

日期：2026-11-06。

## 实施范围

- 发布：独立“发布中心”。
- 配置：“应用管理”“商店账号”。
- 了解与支持：“问题档案”“商店指南”“产品路线图”。
- 原应用内“发布计划”迁到发布中心的应用工作区，应用管理通过“前往发布中心”带上当前项目和应用筛选。
- 汇总只读计划和批次，原有单渠道、Android 批次与 iOS 操作面板继续使用原摘要和确认接口。

## 查询与导航边界

汇总接口固定本机工作空间，不接受浏览器指定空间作为授权；公开响应只含列表必要摘要，不包含快照、账号引用或本机路径。读取不触发商店预检、准备、确认或提交，故障返回错误。批次子计划不重复列为单渠道计划；没有发布历史的应用仍可用于发起发布。

筛选、分页和详情定位保存在 URL。旧应用发布链接兼容进入新发布工作区；新菜单选择清理冲突页签，项目与应用定位共享 URL 订阅。批次及计划详情刷新恢复原记录；前后退恢复查看，不重新执行。

## 验证记录

本轮使用隔离测试目录、合成安装包、合成账号及替身执行器，没有请求真实商店或开展新的远端发布验收。

- `pnpm typecheck`：通过。
- `pnpm test`：189 项通过。
- `pnpm build`：通过，包含问题档案与证据资源校验和复制。
- `pnpm format:check`：通过。
- `pnpm test:smoke`：隔离 Chrome 完整冒烟通过，覆盖既有渠道与账号配置、发布中心筛选和详情、批次详情刷新与前后退、失败恢复及零新增写入请求。

## 用户反馈与回归保护

用户反馈面包屑及平台标签错位、iOS 配置中残留审核页签。修复前的独立 Chrome 检查复现面包屑文字右偏 15px，配置实际四项页签而预期三项。面包屑改用语义链接；标题与平台标签居中成组、操作按钮独立换行；网格使用 `minmax(0, 1fr)` 防止手机被表格最小宽度撑大。配置移除 AppleReviewPanel 并收紧配置页签类型，旧 `tab=apple-review` 链接只恢复发布中心。

新增 `scripts/release-workspace-layout-smoke.mjs`，纳入完整冒烟。在 1440px 桌面、375px 手机和 844px 横屏断言可见文字与标题左缘、标题／标签及按钮中轴误差不超过 2px，无页面横向溢出；断言配置只有商店绑定、安装包、只读预检且不挂载审核面板。已人工复核桌面与手机截图。前端规范和 AGENTS 同步约束后续菜单迁移与布局验收，记录 RH-0039、RH-0040。

完整回归中发现旧脚本继承手机视口导致桌面操作列不可见，以及菜单更名后全局标题与区块标题同名导致定位歧义；已将验收视口和区域定位显式限定，不用删除功能断言绕过失败。

设计检查遵循仓库白色主题、Ant Design 优先及技能的导航层级、当前选中态、标签与错误恢复要求。ui-ux-pro-max 安装包中的 `scripts` 为失效的路径文本，无法执行其搜索脚本；使用已读取的技能规则与真实浏览器检查，不声称生成了新的设计系统。
