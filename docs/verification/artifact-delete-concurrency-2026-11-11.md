# 失败安装包记录删除误拦截修复

用户确认删除两条失败或已清理记录时，弹窗返回“本机有活动操作，请稍后进行备份或恢复”。隔离回归挂起一个真实工作台读取请求，然后调用确认删除；修复前返回 HTTP 409 和相同文案。截图无法判定当时的具体活动请求，复现确认了该文案和普通读取触发的误拦截路径。

此前删除复用了备份恢复的全局独占和后台空闲检查。任意并发请求都可在进入删除前拒绝；即使只涉及无关安装包，已有导入、准备和执行也会被全局空闲检查拦截。现在删除使用共享维护占用，与真正的备份恢复及原文件清理互斥；由产物队列核对可信归属和所选记录终态。同一队列内完成目录扫描、全组选项验证和删除，避免并发读取将已移除目录误报损坏。重复请求返回 404，整组包含可用、接收中或检查中项时拒绝。

专项测试通过：同文案 409 从失败变为成功、并发重复删除只成功一次且目录读取正常、其他包接收或检查期间仍可删除失败记录、备份维护互斥、跨空间或无效选项整组拒绝、历史回执及防重保护继续有效。

`pnpm typecheck`、`pnpm test`（302 项）、`pnpm build`、`pnpm format:check` 与完整 `pnpm test:smoke` 均通过。Chrome 验证使用真实回环 HTTP 保持另一合成包正在接收，页面确认删除已清理记录返回 201，上传中的记录保留，刷新仍不显示被删除项；人工核对 1440／375／844 确认框。测试未删除用户安装包，未请求真实商店。本机开发服务自动重新加载，API 健康及 Vite 更新文案均已核对。
