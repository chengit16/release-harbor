# 第三期审核状态查询能力核对

核对日期：2026-11-06。只读取官方公开文档及当前代码，没有读取真实账号或请求商店业务接口。本文件用于选择首个切片，不代表工程已经接入或真实状态验收通过。

## 结论

建议首片接入 **荣耀**，小米暂不开放自动审核状态查询。荣耀可按当前申请单的版本名与构建号匹配本次 APK，并区分审核结论与已上架版本；魅族具有版本 ID 查询能力，可作为后续切片，但现有执行回执未保存新 `verId`，需要先补齐可靠锚点。

## 小米：公开接口不足以查询审核状态

依据：[小米应用自动发布接口操作指南](https://dev.mi.com/xiaomihyperos/documentation/detail?pId=1134)，本次可读页面标记更新于 2026-09-07。

`POST https://api.developer.xiaomi.com/devupload/dev/query` 以开发者邮箱、包名和 SIG 查询最新推送包的版本及新增／更新许可。该页 FAQ 明确表示审核中或在架应用的信息／状态查询暂未开放。`packageInfo.versionName`／`versionCode` 与 `updateVersion` 不能推导“审核中”“审核通过”或“已上架”。现有公开商店页只能证明当时可见的上架版本，不能代表正在发布的新版本。

**首片边界：**小米列表保留原提交回执和人工核对，不发送猜测端点，不将查询许可或旧上架版本作为本次审核结果。

## 荣耀：首片可准确匹配本次版本

依据：[荣耀 API 传包服务指引](https://developer.honor.com/cn/doc/guides/101359)。官网当前文档为 V14；公开正文可通过[官方文档详情](https://developer.honor.com/document/portal/tree/101359?platformNo=10001&lang=cn)读取。该地址只是官网资料接口，不是产品运行时业务端点。

### 权限与固定业务端点

账号须已注册开发者并在管理中心申请 API 凭证；`POST https://iam.developer.honor.com/auth/token` 使用 `client_credentials` 获取账号级 Token，业务使用 Bearer 认证。应用查询只返回当前账号有权读取的应用。

业务网关固定为 `https://appmarket-openapi-drcn.cloud.honor.com`：

| 方法与路径                                                  | 安全用途                                                                    |
| ----------------------------------------------------------- | --------------------------------------------------------------------------- |
| `GET /openapi/v1/publish/get-app-id?pkgName=...`            | 核对唯一包名与 App ID；不能只相信原页面选择。                               |
| `GET /openapi/v1/publish/get-app-current-release?appId=...` | 返回最新申请的 `releaseId`、`versionName`、`versionCode` 和 `auditResult`。 |
| `GET /openapi/v1/publish/get-app-detail?appId=...`          | `basicInfo` 核对包名／App ID；`releaseInfo` 是已上架版本的名称与构建号。    |
| `POST /openapi/v1/publish/get-audit-result`                 | 以 `appId` 和送审回执 `releaseId` 查询指定审核单；虽为 POST，语义只读。     |

`get-app-current-release` 的状态字典：

| auditResult | 可显示事实                       |
| ----------- | -------------------------------- |
| `0`         | 审核中                           |
| `1`         | 审核通过，不能单凭此项显示已上架 |
| `2`         | 审核不通过                       |
| `3`         | 其他非审核状态；不能猜测具体阶段 |
| `4`         | 编辑中，尚未提交审核             |

按审核单查询的 `get-audit-result` 定义 `0`～`3`，不应擅自沿用 `4`。其每次最多查询 20 组，并要求事先取得成功送审返回的 `releaseId`。官方建议此审核查询间隔为三小时，已取得通过或不通过结论的审核单不再重复查询；首片仅手动查询，并保守限制同目标重复请求，暂不引入定时轮询。

### 版本、上架与私人材料边界

- 首先核对账号内包名和 App ID，再将 `current.versionName` 与 `versionCode` 同时匹配计划的版本名／构建号。缺字段、值不合法、版本不一致、目标不唯一或查询失败，均不能把当前申请的状态挂到本次计划。
- `current` 表示最新申请，不保证是历史计划的原审核单。当前代码只将 `submit-audit` 返回的 `releaseId` 用于即时成功校验，没有写入公开执行记录。因此首片按版本匹配查询只能声明对应版本的当前观察；若当前版本已换成另一份申请，应返回不匹配／未知，不能冒充原单状态。后续准确历史追踪须保存送审锚点后使用审核单接口。
- `detail.releaseInfo` 明确定义为已上架版本。当目标、版本名和构建号与本次计划完全一致时，可独立记录该版本已上架的证据；不同或为空时，`auditResult=1` 最多显示审核通过。未确认所有必要字段时保留未知，不从定时时间已到或上传成功推断上线。
- `auditMessage` 是可选审核意见，`auditAttachment` 是可选附件 URL。字段存在不等于正文可直接公开：意见可能带账号、联系人或测试材料；附件可能带访问参数。首片建议仅展示“有审核意见，请到商店后台查看”，不将自由文本、附件或整份详情出进程；后续详细拒绝原因需另定脱敏合同。
- `detail.basicInfo.secretKey`、`publishInfo` 私人测试字段、Token 和原始错误正文都不能进入观察合同。固定接口、限时、有界读取及禁止重定向继续复用当前 provider 边界。

## 魅族：后续可基于版本 ID 查询

依据：[魅族开发者 API 文档](https://open.flyme.cn/docs?id=333)及其[官方公开正文](https://apiopen.flyme.cn/api/web/v1/doc-wiki/detail?id=333)，核对章节 3.10、3.11、3.12.6。

`GET https://developer.meizu.com/open/api/v1/app/versions?appId=...` 提供版本列表；`GET /open/api/v1/app/detail?verId=...` 提供确定版本的包名、应用 ID、`verId`、版本名及状态。使用客户端凭证获取 Token，业务 Header 按官方规则签名。

状态 `20`／`100` 分别为待审／审核中，`30` 为审核不通过，`50` 为上架，`70` 为下架。文档未为详情声明构建号或独立拒绝原因字段，不能按版本名猜测 APK 版本资格、不能把通用接口错误 `msg` 当审核拒绝原因。

本项目执行时曾取得并验证新 `verId`，但当前回执只保留 `meizu_review_submitted`。将来可保存该锚点后读取确定详情；旧记录需通过完整有界版本列表准确解析，遇到同版本歧义保持未知。未完成这些工作前，不自动以最新列表项代替本次发布。
