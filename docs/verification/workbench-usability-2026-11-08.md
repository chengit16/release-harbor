# 工作台菜单与流程精简验证

日期：2026-11-08。

## 本轮范围

按用户确认的三步顺序完成首页与菜单精简、应用配置／发布路径贯通、统一启动与首次环境检查。实现说明见[方案](../plans/workbench-usability-plan.md)，使用方式见[快速指南](../guides/workbench-quick-start.md)。

## 需保护的边界

- 首页统计来自本机摘要，未核对标记由后端根据原执行与人工记录投影，不用普通 attention 状态替代。
- 配置向导、就绪检查、菜单和缓存读取不访问商店；凭据继续通过独立本机配置进程录入。
- 安装包上传／检查不等于发布准备，不复用旧授权。单计划和批次分别经过原摘要确认；华为批次与正式送审动作不混淆。
- 旧项目、应用、帮助、审核和发布详情链接继续恢复；数据存储格式、远端写入协议及一次性授权规则不变。
- 启动器仅复用身份与页面均可核实的服务，端口占用不杀原进程；工具和环境检查不自动安装软件。

## 验证结果

- `pnpm typecheck`、`pnpm test`、`pnpm build`、`pnpm format:check` 均通过，自动测试共 270 项。构建仍提示公共依赖包超过 500 kB，该提示不阻断构建，本轮未调整依赖或打包策略。
- `pnpm test:smoke` 完整真实 Chrome 回归通过，覆盖既有九渠道工作流、备份恢复、账号维护与本轮体验调整；使用隔离目录、合成材料及替身网络，没有操作用户的商店账号或送审。
- 首页三个入口的数量、点击筛选和刷新恢复均与本机摘要一致；普通失败和过期不计入结果待核对，追加人工核对后保留原终态并退出待核对入口。
- 验证精简菜单、旧帮助链接和页签恢复、平铺应用、向导输入保留、默认分组创建后应用保存失败重试不重复建组、缺少渠道时禁止开始发布。
- 验证多选华为与小米进入两渠道批次并明确华为仅保存草稿，单选进入原计划；发布页上传和检查完成后可选新包，更新说明不丢失，不自动准备或确认。
- 核对 1440／375／844 视口的标题与面包屑左边缘、平台标签、操作换行和无横向溢出；人工查看首页、发布页、手机抽屉和应用目录截图。截图保存在忽略的 `artifacts/`，不入库。
- `RELEASE_HARBOR_NO_OPEN=1 pnpm workbench` 验证能识别并复用当前开发实例；另在随机端口与临时数据目录实测构建、启动、健康与 HTML 就绪、再次复用同一端口和正常 SIGTERM 退出。Node 版本、服务身份与占用端口拒绝另有自动测试，原监听保持运行。双击脚本通过 `zsh -n` 语法检查并保留可执行权限。

本机测试不代表真实渠道送审、上架、通知投递或 macOS Finder／系统安全弹窗已验收；双击入口的系统交互需在用户环境中体验。
