# 批次默认设置与渠道日期回填核对

## 用户要求与实现

- 批量设置首次进入默认展开；仍需明确点击应用到已选渠道。
- 选择通用安装包后，默认说明为两行：`“版本号”更新说明`、`旨在提升软件稳定性`。版本号来自已检查 APK；未选包时仅提供正文，不猜测版本。用户手写或主动清空后，换包不覆盖说明。
- 渠道编辑回填当前批次已应用的指定时间，按设备时区显示并保留秒数；只修改说明后保存不丢时间。立即上架不带入其他渠道的时间。
- 模板、历史与离页恢复仍只复用发布偏好，不保存具体时刻，也不增加准备、执行或商店授权。

## 根因与复现

渠道编辑初始化只写入说明和上架类型，没有将行内 `releasePolicy.notBefore` 转换为日期控件需要的 Dayjs 值。公共批量应用已经保存时间，丢失发生在弹窗回填。

修复前运行 `node --import tsx scripts/batch-settings-smoke.mjs`，实际 Chrome 返回：默认展开 `false`、通用说明空字符串、预期时间 `2099-05-06 15:04:03`、编辑框时间空字符串，日期断言失败。

- `pnpm typecheck`、289 项 `pnpm test`、`pnpm build`、`pnpm format:check` 通过。
- `node --import tsx scripts/batch-settings-smoke.mjs` 与最终完整 `pnpm test:smoke` 通过。
- 专项断言默认展开、带版本的两行默认说明、换包保留手写与主动清空、公共定时应用后逐行回填、只改说明保存后时间不变、立即模式不残留旧日期；设置过程零准备／确认／执行请求。
- 1440／375／844 视口通过，已人工核对默认说明及渠道日期的桌面、手机截图。

专项使用临时目录、合成应用和真实解析的合成 APK，不读取真实账号或调用商店。完整回归首次遇到固定端口共用及导航测试单页上下文问题，后续重跑已完成；最终默认文案与断言均使用带引号版本。未执行真实上传、送审或上架。

## 批次辅助入口临时隐藏

用户后续要求暂时隐藏“重新读取批次”“新建批次”和“复用配置与常用模板”。批次页将两个按钮及配置复用 JSX 注释保留，并保留原处理函数和组件，后续可恢复。单渠道配置复用不在本次截图调整范围。

已同步现有浏览器回归，检查三个入口不再挂载；模板来源门禁改由隔离浏览器直接验证保留的 API，避免因隐藏 UI 丢失底层回归覆盖。

类型检查、289 项自动测试、构建、格式、完整 Chrome 冒烟和批次专项均通过；1440／375／844 视口及桌面、手机截图已核对，无入口残留或空白占位。独立来源回归模板保存返回 201、五渠道准备返回 202，无确认或执行。测试适配时的短生命周期响应体读取问题改为浏览器内及时消费，并增加请求超时，最终通过。未调用真实商店。
