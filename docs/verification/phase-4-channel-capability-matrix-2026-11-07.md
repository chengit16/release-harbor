## 首个代码缺口与官方能力

最明确的运行时缺口是华为 AppGallery Android 当前只提供保存草稿。其他 Android 渠道与 Apple 已有送审动作，但华为 Android 草稿不能满足“提交审核与审核后上线”的完整发布目标。已从华为 Android v2 官方文档确认：

- `/publish/v2/upload-url/for-obs` 可获取 APK 上传地址；上传完成后 `/publish/v2/app-file-info` 更新应用文件信息。
- `/publish/v2/app-submit` 正式提交应用审核，要求应用资料完整且软件包已上传；官方说明包解析为异步，上传后需等待至少两分钟再调用。
- 官方提交合同包含 `releaseTime`，另有 `/publish/v2/on-shelf-time` 更新上架时间接口，后者仅在应用处于“发布中”状态时可调用。定时策略因此须按审核前设置与审核后改期的具体接口语义分别冻结，不能仅依赖当前统一策略字段推断成功。
- 官方另提供 `/publish/v2/app-language-info`、`/publish/v2/app-info` 与 `/publish/v2/app-file-info` 更新接口。首版仍应限定语言和 APK 版本更新，不因接口存在就自动覆盖图标、截图、隐私政策或基础资料。

下一项建议为 **P4-1：华为 Android 已有应用更新送审**，先补齐官方请求／回执合同、现有发布资料来源和异步解析等待，再实现一次确认后的上传与提交。发布策略先以官方字段及状态约束确认可用路径后开放。新应用创建、全量资料编辑、额外资源替换、分阶段发布及自动重试不纳入首个切片。鸿蒙 v3 API 不能用作 Android 证据。

## P4-0 结论

除华为 Android 正式送审及其发布策略外，其余渠道已有逐渠道工程动作，第四期不需要重建统一发布入口。华为 Android 官方 v2 接口具备上传、文件信息更新及提交审核能力；当前缺的是产品执行接入、完整更新资料边界与策略状态核对，而不是已证明的接口不可行。真实时间设置生效、送审受理、审核结果和实际上架仍属于各渠道用户验收，不能因为其他渠道反馈可用而合并标记完成。
