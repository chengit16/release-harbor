# 送审后审核状态能力与补齐记录

核对日期：2026-11-07。用户询问各平台提交新版本后是否都能查询审核状态，并要求状态摘要使用标签。本记录区分官方能力、当前实现和仍需用户指定版本验收的范围，不以旧版上架证明新包通过。

## 结论与当前覆盖

**无法保证所有渠道都能完整自动查询。小米仍没有已公开的审核进度接口；OPPO 本轮找到独立字典并补齐主要阶段，其他渠道按各自官方接口读取。** 查询由用户点击触发，页面刷新只读本机缓存；当前没有自动轮询、审核回调或审核通知。

| 渠道         | 送审后的官方查询能力                                            | 当前实现与精度限制                                                                                                                                                         |
| ------------ | --------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 华为 Android | 可以读取当前全网流程的在审、拒绝、待发布及上下架                | v2 当前流程与旧在架版本分开。工具现有华为执行动作只保存草稿，草稿成功不能当送审；到后台真正送审后才可能出现审核状态                                                        |
| 小米         | 公开 API 不能查询在审或拒绝结果                                 | 仅读取官方公开商店的在架版本。新包审核期间仍可能看到旧版“公开在架”，不能据此推断通过                                                                                       |
| OPPO         | 普通包详情支持审核状态及可选指定构建号，官方另有完整对照表      | 本轮补齐返回版本的主要审核及阶段状态。独立目录仍默认读取最新版本；必须核对响应版本／构建号，不能保证“最新”在所有阶段都等于刚送审的新包。指定构建号跟踪尚未接入当前独立页面 |
| vivo         | 可以读取草稿、在审、通过、拒绝和撤审                            | 按官方字典读取当前流程，只有通过后再结合上下架字段；官方缺少的版本名保持缺失，不能承诺按任意历史审核单追溯                                                                 |
| 魅族         | 可以按版本目录及版本 ID 读取待审、在审、拒绝、上下架            | 各版本分别显示；官方不提供构建号。新执行的可选本地关联使用原送审锚点，旧执行没有锚点不能猜补                                                                               |
| 荣耀         | 可以读取当前申请的审核结果及独立在架版本                        | 当前申请不是全部历史审核单。官方指定 releaseId 结果接口可作为后续增强，当前没有把原送审 releaseId 持久化为精确历史锚点                                                     |
| Apple        | 可以读取 App Store 各版本的待审、在审、拒绝、待发布、在架等状态 | 按商店版本及其关联构建读取。审核通过后手动发布与自动发布分别处理；查询失败不等于审核失败                                                                                   |
| 应用宝       | 可以读取当前审核流程的在审、驳回、通过和撤销                    | 审核接口不返回版本标识，与线上版本资料分别展示，不能证明属于某个具体 APK；审核通过也不等于已上架                                                                           |
| 华为鸿蒙     | 可以读取当前正式全网流程                                        | 固定 v3 和 releaseType=1，不混用 Android、测试发布或预审结果；在架旧版与当前流程分别显示                                                                                   |

这里的“可以”表示存在官方能力且已工程接入相应读取，不表示已在本轮对每个渠道执行真实送审验证。此前真实只读复验仅见到草稿、在架或已替代，不能代替新包在审／驳回场景的验收。

## 小米的解决路径

重新读取[《应用自动发布接口操作指南》](https://dev.mi.com/xiaomihyperos/documentation/detail?pId=1134)，FAQ 仍明确：

> Q：是否有查询审核中的app或者在架的app应用信息、状态的接口？
>
> A：暂时没有开放。

文档将 `/dev/query` 定义为“本账户推送的最新应用详情，用于判断是否需要进行应用推送”，返回新增／更新许可；它不是审核进度。公开商店详情只证明那个公开版本在架。本次阅读的该指南未提供审核事件回调注册、验签、事件载荷与版本关联合同，不能据此宣称小米永远没有定向开放能力。

可行处理按可靠性排序：

1. **现阶段：官方后台核对。** 保留“公开在架”限定，审核中、拒绝原因和刚送审的版本到管理后台核对。若后续增加页面内人工记录，应明确人工来源、版本和时间，并与官方查询分开，不改写旧回执或解除未知结果保护。
2. **优先争取：官方开放能力。** 向小米客服咨询审核查询或通知是否有定向开放的正式合同；指南提供客服入口。取得文档与权限后再接入固定只读接口或经验证的通知。此次没有代用户联系客服。
3. **可选辅助：用户登录后的浏览器读取。** 技术上可评估本机浏览器辅助，但需另行确定会话保存、二次验证、页面变化与读取范围。它依赖登录和后台页面结构，不应包装成稳定的官方 API。本轮没有实施登录抓取，也没有向产品收集 Cookie。

邮箱通知只有在确认官方确有对应通知、用户明确授权邮箱范围后才可评估；当前没有核实足够的事件及版本关联合同，因此不把它列为已支持或保证可用的替代方案。

## OPPO 的补齐与剩余边界

本轮从官方搜索与 API 目录找到[《审核状态对照表》](https://open.oppomobile.com/documentation/page/info?id=11176)，与[普通包详情](https://open.oppomobile.com/documentation/page/info?id=11004)同属软件商店 API 传包能力。完整依据见[专项调查](oppo-review-tracking-research-2026-11-07.md)。

本次实现：

- 1／4 显示审核中；3／5／444 显示审核未通过；2 显示审核通过；7 显示待上架；111／222 显示已上架／已下架；0 显示未发布。
- 00、11、-11、6、-22、22 分别保留资质审核中、资质通过、资质未通过、运营通过、报备成功、冻结的独立含义；阶段通过不升级成整包通过或已上架。
- 以字符串精确识别码值，00 与 0 不混同。公开 rawState 仍只保留可无损表达的非负整数，前导零及负码不强转；归一化阶段状态本身不会丢失。
- 无状态码但有已核实描述的官方旧样例仍可读取；未知码、未知描述或码与描述冲突保持无法确认，不拿应用级 state 或包处理任务成功覆盖。

本轮没有增加浏览器任意指定商店目标的能力。独立目录只展示本次官方实际返回的版本；若默认返回旧包，不能宣称新包已通过。后续可增加“指定构建号查询”，将用户选定的构建号作为只读查询条件，由服务端校验后传给固定 info 端点，并严格核对响应版本，不要求创建本地发布计划。它是精确跟踪增强，**本轮尚未实施**。

## 状态标签体验

桌面摘要、手机卡片及版本详情统一使用 Ant Design Tag，并保留完整文字：

- 绿色：已上架／公开在架、整包审核通过。
- 蓝色：审核中、预审中、处理中；青色：资质／运营阶段通过。
- 红色：审核未通过、资质未通过等拒绝结果。
- 橙色：待上架、冻结、尚无法确认及本次查询失败；查询失败仍区别于审核未通过。
- 灰色：草稿、未发布、下架、撤审、历史替代、待查询或官方空结果等中性事实。

同一行的相同结论去重，不把历史版本重复堆成长文本；不同状态并列、窄列自动换行。详情保留逐版本事实及时间，不因摘要去重而删除版本，也不凭标签颜色改变状态。

自动化只用合成材料和替身网络，不调用真实商店账号、不上传或送审。页面验收使用隔离存储，不触碰用户的发布计划、授权和原回执。
