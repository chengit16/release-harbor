# 版本定位与资料待办验收

日期：2026-11-07。范围为第三期版本精度与有限资料待办首版。全部工程验证使用临时目录、合成凭据和受控商店网络，未调用真实账号、上传、送审或上线。

## 官方依据与执行边界

- [OPPO 普通包详情](https://open.oppomobile.com/documentation/page/info?id=11004)：pkg_name 与可选 version_code，默认最新。指定构建仍需包名、普通软件类型与返回构建精确匹配；状态字典依据[已有核对](oppo-review-tracking-research-2026-11-07.md)，不从旧在架覆盖新审核。
- [荣耀 API 指引](https://developer.honor.com/cn/doc/guides/101359)及[官方正文](https://developer.honor.com/document/portal/tree/101359?platformNo=10001&lang=cn)：本轮重新读取提交审核与查询审核单章节，submit-audit 返回 releaseId，get-audit-result 使用 POST、Body.appId 列表及 appId/releaseId，返回0在审、1通过、2不通过、3其他。官方建议三小时，并要求已取得通过／不通过的单不再查询。实现只读审核单请求；通过后只读在架版本，不刷新旧审核结论时间。
- [小米自动发布指南](https://dev.mi.com/xiaomihyperos/documentation/detail?pId=1134)：审核进度接口仍缺失，人工核对保留本机用户来源，不冒充官方响应。公开在架与人工版本事实独立展示。
- Apple 沿用已有官方版本状态与构建关系：PENDING_DEVELOPER_RELEASE 为等待手动发布，PENDING_APPLE_RELEASE 为等待商店发布；仅前者提供发布中心跳转，跳转不执行发布。

## 数据与恢复

独立缓存写 schema2、读取兼容schema1；GET读取旧版不写升级。默认快照、指定构建快照与人工记录隔离；每绑定最近二十个指定构建、各最多最近失败与上次成功，人工记录最多二百条。相同请求编号保存相同内容幂等，不同内容冲突；绑定指纹改变后隔离旧记录。原计划、回执、授权与未知保护不受查询或人工保存影响。

计划存储写 schema15，读取兼容1–14；新增荣耀审核单锚点与执行终态同队列原子保存。旧schema14只允许原魅族锚点，旧荣耀无锚点不回填。未取得原审核单的荣耀记录继续使用旧版本匹配；独立商店状态始终不要求本机发布。

待办只用各查询范围最近事实；失败前的成功保留供参考，不产生新的可发布动作。人工事实按实际核对时间取同版本／构建的最新记录；新增更早历史不会取代较新核对。官方原始意见和附件不出可信进程，资料检查仅覆盖本次可见字段，隐私、截图及合规材料明确未检查。
