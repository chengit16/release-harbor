# 第四期官方字段补充核对

日期：2026-11-08。仅从官方公开文档页面及其公开文档正文服务读取；没有真实商店账号请求、上传、送审或上线操作。本记录用于第四期 P4-3／P4-4／P4-5 的字段与产品边界核对；不替代工程验证或真实账号验收。

## 最重要的范围结论

官方有字段，不代表本项目当前已开放写入。P4-3 可以通过明确、冻结、可核对的资料修改范围完成工程流程；未接入的图标、截图、隐私政策、语言增删须明确引导后台。不能把所有渠道都显示为支持全量商店资料编辑。

Apple 官方支持 SCHEDULED，但用户已明确只需要自动／手动，故项目可限定 MANUAL／AFTER_APPROVAL。应写“本项目不提供指定时间发布”，不能写“Apple 官方 API 没有指定时间”。

## 资料写入、语言及资源边界

- **小米**：官方 `appInfo` 包含名称、介绍、关键字、`updateDesc`、`brief`、`privacyUrl`；图标／截图另有文件参数。当前工程只修改更新说明并复用名称、图标、隐私政策；`testAccount` 包含 `zh_CN` 的私有测试材料，不能公开缓存或沿用到跨平台合同。
- **OPPO**：官方 `app/upd` 明列 `app_name`、`summary`、`detail_desc`、`update_desc`、`privacy_source_url`、`icon_url`、`pic_url` 等。图标512×512 PNG小于1M；竖图通常3–5张、1080×1920，小于1M。证明官方有这些写入入口，不代表本项目已开放编辑；版本更新需要复用必需字段。完整私有审核资料不向控制面投影。
- **vivo**：官方更新 `updateDesc` 5–200字符；`detailDesc` 50–1000；`mainTitle` 不超过20字符且每年最多修改4次；`icon`、`screenshot` 为上传流水号（3–5张），不是详情URL；`privateSelfCheck` 可为上传PDF流水号或HTTP(S)地址。现项目只改说明，其余沿用；不应把现有只读URL直接当成文件流水号发回。
- **魅族**：官方3.6节 `app/publish` 明列必需 `appName/appDesc/verDesc`、`icon/screenShots/certificates`、`privacyPolicyUrl`、关键字、推荐语、资质和备案字段；返回新 `verId`。图标、截图及资质的文件路径可复用未变更资源；当前工程固定复用。文档未提供可逐语种编辑的同等语言列表；勿创造“所有语言统一覆盖”的承诺。
- **荣耀**：`update-language-info` 的 `languageInfoList` 包含 `languageId/appName/intro/briefIntro/newFeature`；`newFeature` 最多500字符。`setAll` 默认1：`更新所有语言，不在languageInfoList的多语言信息将被删除`；0：`仅更新当前languageInfoList中存在的语种，其他不变`。所以只改默认语种必须显式0。资源绑定仅更新需替换资源，未更新资源继承；图标、截图、APK有独立类型和语种关系，不能无差别覆盖。
- **华为 Android**：[语言更新v2](https://developer.huawei.com/consumer/cn/doc/AppGallery-connect-References/agcapi-language-info-update-0000001158245057/)具备语言资料更新，当前官方核对文档确认默认语言 `newFeatures` 最多1000字。独立文件信息接口并非只承载APK，但本期当前工程仅APK和默认语言说明；完整隐私／图片编辑不能因存在通用接口自动开放。
- **鸿蒙**：[语言更新v3](https://developer.huawei.com/consumer/cn/doc/app/agc-help-publish-api-language-info-update-0000002271160569)、[软件包绑定](https://developer.huawei.com/consumer/cn/doc/app/agc-help-publish-api-app-package-info-update-0000002236201250)与Android v2分开。现工程仅默认语言 `newFeatures`；资料读取样例有名称、介绍和图文资源，不等于所有字段均为已验证可写。
- **应用宝**：官方 `update_app` 大多变更字段注明`不变更则不填`；包含 `app_name`、修改名称原因、`introduce`、`one_word_summary`、`feature`、图标/截图和资质上传流水号。当前工程沿用资料，仅提交更新说明。资料更新和APK更新可同接口，不代表当前工程已开放纯资料更新授权。
- **Apple**：[AppStoreVersionLocalization更新属性](https://developer.apple.com/documentation/appstoreconnectapi/appstoreversionlocalizationupdaterequest/data-data.dictionary/attributes-data.dictionary)本轮机器schema确认可PATCH `description/keywords/marketingUrl/promotionalText/supportUrl/whatsNew`。每条本地化独立locale；现工程将同一更新说明写入所有已存在语种，不创建语言、不生成翻译。隐私在AppInfoLocalization，图标、截图、年龄分级、Build加密不是同一资源，不可合并为一个“版本资料均已更新”结论。

## 异步和状态证据边界

- OPPO [任务11001](https://open.oppomobile.com/documentation/page/info?id=11001)状态1待处理、2成功、3失败；任务以包名和version_code查询。成功是版本处理任务完成，非审核通过。实际审核另由info/状态字典核对。
- vivo同步更新成功只说明API接收更新；code和subCode都需核对。详情 `status` 与 `saleStatus` 分开，不能以旧在架代替新包审核。
- 魅族 publish 回传新verId后，按该verId回读身份及审核状态；官方没有构建号，不能声称远端校验了versionCode。
- 荣耀 submit-audit回传releaseId，后续审核结果必须匹配该单；官方建议审核查询间隔3小时，不宜自动密集轮询。
- 华为 Android及鸿蒙均有异步解析。鸿蒙 [PackageStates](https://developer.huawei.com/consumer/cn/doc/app/agc-help-publish-api-data-packagestates-0000002271160601) 0完成、1解析中、2失败。解析完成与受理、通过、上架分开。
- 小米官方审核查询未开放；更新许可不是审核进度，公开商品在架不是新版本审核证明。
- 应用宝审核API仅返回当前应用审核状态（1中、2拒、3通过、8撤销），没有版本ID；不能关联到任意旧线上版本。
- Apple ReviewSubmission与AppStoreVersion状态分别处理；提交集合、构建处理、审核、手动发布是不同资源／动作。审核联系人和测试账号是开发者提交资料，不是审核员回复。

## 证据强度与验证限制

策略矩阵中的九个渠道资料，以及 OPPO、vivo、魅族、荣耀、应用宝和 Apple 本地化更新 schema，均在本轮重新从上表官方公开页面或公开文档服务读取。华为 Android／鸿蒙语言修改和鸿蒙解析状态的详细限制复核自既有官方核对记录：[华为送审核对](huawei-android-submit-2026-11-07.md)、[应用宝与鸿蒙基线](tencent-harmony-baseline-2026-11-05.md)，其来源链接已列于正文；没有据此声称本轮重新调用了所有关联文档。

本记录只确认官方字段与产品范围，不声称新增工程实现已经运行，也不声称真实商店策略已生效。工程实现、合成网络测试、页面验收和真实商店验收应分别记录。发布 API 的成功回执不能替代上架策略回读或后台实际时间核对。
