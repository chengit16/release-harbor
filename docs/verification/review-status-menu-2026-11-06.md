# 审核状态独立菜单验收

日期：2026-11-06。用户纠正第三期应作为独立菜单实现，并明确指定名称“审核状态”。本轮修正导航与承载位置，既有荣耀查询及发布授权边界保留。

## 实施内容

- 在“发布”分组下并列展示“发布中心”“审核状态”，独立访问 `?view=reviews`。
- 审核状态集中展示已执行送审渠道目标、版本、已有观察、来源与时间、待处理事项，支持项目、应用、渠道、状态和待办筛选。
- 单渠道与批次子计划按渠道独立展示；Apple 已有审核／发布观察只读复用。草稿、构建上传和未执行计划不冒充审核记录。
- 发布摘要、执行详情及 Apple 已执行操作记录只保留“查看审核状态”跳转，携带当前应用和记录类型；荣耀查询面板迁到独立菜单。
- 桌面表格与手机卡片分别展示，手机无须横向滚动查看状态、时间及待办。筛选、分页与详情使用 URL，刷新和前后退恢复定位。
- 路线图、商店指南、README、第三期计划及菜单规范同步更新。问题登记 RH-0044。

## 安全与读取边界

`GET /api/review-tracking` 固定可信本机空间，只读取存储，不触发预检、产物复核、商店请求、授权或执行。返回最小安全摘要，不含计划快照、凭据引用和授权；失败明确报错。状态观察和原回执分别展示，未获取状态不等于审核中。原结果待核对时仍优先提示核对，不以已有观察自动解除原未知保护。

荣耀查询继续通过既有限定端点明确触发，进入菜单、筛选和打开详情仅读本机历史。未接入查询渠道明确提示；Apple 需要刷新或手动发布时回到原工作区，不在独立菜单复制发布表单。
