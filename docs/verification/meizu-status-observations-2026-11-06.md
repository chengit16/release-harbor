# 魅族审核状态接入与能力核对

日期：2026-11-06。按第三期逐渠道推进，在独立“审核状态”菜单增加魅族确定版本查询。工程使用隔离材料，真实商店结果待用户显式查询核对。

## 官方依据

本轮再次读取[魅族开发者 API 文档](https://open.flyme.cn/docs?id=333)及[官方公开正文](https://apiopen.flyme.cn/api/web/v1/doc-wiki/detail?id=333)，核对章节 3.10、3.11 和 3.12.6。网页读取工具未能解析正文，改用 HTTPS 读取官方公开文档 JSON；不请求账号或商店业务 API。

- `GET /open/api/v1/app/detail?verId=...` 返回确定版本的应用 ID、包名、版本 ID、版本名和状态。状态字典包括待审 20、在审 100、不通过 30、上架 50、下架 70。
- 详情未定义构建号字段。版本列表也不能仅凭版本名建立同一次 APK 送审的可靠关联；不选择列表首项，不按最新版本或名称猜测。
- 通用接口错误正文不是审核意见。详情可能包含联系方式、证件及安装包地址，本轮只投影安全状态，不传播完整响应或自由文本。
- 未查到明确的独立查询频率要求，沿用产品保守策略：成功间隔三小时，失败一分钟，未完成预约重启保留三小时；不冒称平台硬限制。

## 版本关联与兼容

现有执行器已经核对真实 APK、副本与授权，再进行单次上传及新版本发布。本轮在新 `verId` 的详情核对应用 ID、包名、版本 ID、版本名及待审状态后，向父进程回报最小 `reviewAnchor`。父进程校验 schema、nonce、远端许可、动作与锚点格式，且不接受来源旧版本 ID；仅第一次合法锚点有效。

锚点与同一次执行终态在原队列、原文件内原子保存，不修改不可变计划指纹。计划存储写入 schema14，兼容读取 1–13；旧记录不回填。批次子计划沿用同一执行路径。崩溃或回报丢失导致锚点缺失时保守提示后台核对，不重试送审。

查询从原执行锚点恢复确定版本，只发起固定鉴权及详情读取。返回的应用 ID、包名、版本 ID 和版本名必须一致；构建关联来自原执行事实，页面明确详情未再次提供构建号。绑定或凭据目录变化时拒绝混合观察。

## 页面体验

进入“发布 → 审核状态”，选择魅族记录并点击“查询魅族状态”。查询时间和来源与原回执分别显示；刷新、导航和筛选只读取本机记录。已下架有独立状态，未识别整数保留为未知，审核未通过引导到魅族后台查看意见。

历史记录没有版本锚点时显示“未保存魅族送审版本 ID”，不提供查询按钮，明确无需重新提交。未接入的其他渠道保持原能力提示。
