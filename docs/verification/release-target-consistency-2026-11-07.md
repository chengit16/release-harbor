# P4-2 送审目标与摘要一致性核对

**核对日期：**2026-11-07

**工程实现与回归日期：**2026-11-08

本轮核对已有九个渠道目标、Apple 已有构建审核／手动发布和 Android 批次，不新增商店路由或扩大写入权限。工程依据是现有合同、可信执行流程和隔离回归；官方字段依据继续使用[第四期渠道能力矩阵](phase-4-channel-capability-matrix-2026-11-07.md)链接的逐渠道记录。真实账号的受理、审核及上架结果须另行验收。

## 共同约束

- 单渠道快照固定应用、商店绑定、产物身份与 SHA-256、预检及账号目录版本、动作、更新说明和上架策略；整个快照计算计划摘要。说明及配置另有指纹，确认只接受预期摘要与明确同意。
- 确认、消费与首次写许可前检查当前依赖；可信 worker 重新计算指纹、检查实际字节并使用独立副本。配置或产物改变需要重新准备，不能用新资料覆盖旧快照。
- 渠道只读来源在准备时形成公开投影，执行前按各渠道可读取的字段重新核对。私人测试材料仅在可信执行器内使用，不写入公开摘要；对未进入公开投影的字段，不宣称已冻结其完整内容。
- 首次写入前持久化许可。未知结果不得通过新计划、新文件或新批次绕过；检查、刷新、状态查询和历史查看不能派发发布。

## 本轮修复

旧的重复提交保护只比较 SHA-256。同一个版本重新打包会产生新摘要，能够通过本机保护；即使商店最终拒绝，也已经发生了无必要的再次上传。新增回归在旧实现上复现失败，修复后按同一商店目标同时检查文件和版本身份：

- Android／HarmonyOS 比较构建号，数字前导零不改变版本身份；改变显示版本名不能绕过构建保护。
- 魅族按现有来源合同中的版本名保护，保留其官方未提供构建号的限制。
- Apple 上传按市场版本名与构建号组合保护，允许不同市场版本复用构建号。
- 成功或人工确认已存在的记录保护同一版本；未知且未澄清时仍阻止整个目标。人工确认不存在、执行前失败及独立商店目标保持原规则。

本机防重规则不证明商店当前仍保留该版本，也不代替商店的版本递增及审核约束。历史成功记录不可人工改为失败；已受理版本要更新内容时使用新的合法版本／构建。外部后台并发编辑无法由本机事务锁定，不能承诺对商店后台实施跨系统锁。
