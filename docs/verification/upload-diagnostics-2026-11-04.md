# 小米上传异常原因保留验收

日期：2026-11-04。

## 现象与边界

用户的 17:09:35 计划在 17:09:45 获得许可，17:11:45 结束，仅保存 remote_unknown。约 120 秒的耗时与当前上传请求上限吻合，但历史没有保留实际异常，不能据此反填为确定超时，也不能确定小米后台未接收。本次不修改历史记录、不调用真实商店、不重试用户计划。

## 复现与根因

`pnpm exec tsx --test tests/xiaomi-runner.test.ts` 在真实独立副本检查调用链注入合成 TimeoutError。修复前测试失败：预期 upload_timeout，实际 remote_unknown。上传适配器捕获所有错误只返回待核对，控制面还会覆盖许可后的诊断；进程退出也缺少明确中断回报。

修复后只投影固定原因：请求超时、请求中止、网络异常、HTTP 非成功、回执格式异常和接口业务非成功。执行协调器保存已许可阶段的安全诊断，仍将结果标为待核对；许可前材料或目标原因不能冒充上传原因。本机进程意外退出使用 runner_interrupted。原始异常、供应商正文和秘密都不跨公开边界，现有记录无需迁移。

## 验证范围

- 完整 runRelease 使用实际合成 APK、内存凭据和受控网络，覆盖超时、底层超时码、主动中止、连接中断、HTTP 非成功、无效 JSON、缺少结果、超大响应及业务非成功；每种情况仅请求一次，不自动重试。
- 控制面集成验证具体码落盘及公开查询、终态仍待核对、未知目标继续阻止新计划执行，以及许可前原因降级保护。
- 浏览器隔离夹具验证超时原因在计划历史与执行详情可见，保留人工核对与窄屏行为。

实际验证：`pnpm typecheck`、`pnpm test`（89 项通过，无跳过）、`pnpm build` 及真实 Chrome 的 `pnpm test:smoke` 均通过；`pnpm format:check` 也通过。
