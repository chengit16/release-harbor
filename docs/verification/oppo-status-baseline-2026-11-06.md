# OPPO 指定版本状态查询能力核对

核对日期：2026-11-06。此记录仅核对官方公开资料，不代表查询工程已接入或真实账号已验收。

## 已确认能力

读取[官方普通包详情文档](https://open.oppomobile.com/documentation/page/info?id=11004)，正文来自官网页面使用的 `POST /oneoppoapi/doc/detail`，请求仅包含公开文档编号 `doc_id=11004`。该地址用于资料读取，不是产品运行时接口。

- 固定业务端点 `GET /resource/v1/app/info` 支持必填 `pkg_name` 和可选 `version_code`；省略构建号时取最新版本。后续适配必须显式传入原计划构建号，不能按最新资料推断历史审核。
- 详情声明 `app_id`、`pkg_name`、`version_id`、`version_code`、`version_name`。需同时核对原目标包名、版本名及构建号；与来源旧版本混淆、缺字段或不匹配时保留未知。
- `state` 定义 `1` 为上架、`2` 为下架；`online_info_offline_apply` 提供 `app_id`、`version_id`、`online_state` 与上下架时间。需进一步明确这些字段与所选版本的关系，不能将应用旧版本在架状态直接当作本次版本上架。
- `audit_status` 仅声明“审核状态”，`audit_status_name` 仅声明“审核状态描述”，当前正文没有完整取值字典。示例的“上线”不足以定义所有审核阶段。
- 详情含测试资料、联系人、拒绝原因及附件。后续只投影经过验证的安全状态，不能将自由文本、附件或完整正文带入公开观察。

## 当前缺口与实施约束

现有 `task-state` 查询只证明版本处理任务结果；任务成功不能推断审核通过、审核中或已上架。不得用该结果补齐缺失的审核字典，也不得将 `update_info_check` 的资料审核状态当成 APK 版本审核。

继续接入前，须从官方资料补齐审核状态语义和版本级上架依据。已知字段不足以覆盖的状态保持未知；本轮保持原提交回执与后台核对入口，不添加无法解释结果的审核查询按钮。

本次未调用鉴权、应用详情、任务状态或其他真实商店业务接口，没有读取真实凭据。后续测试使用合成材料，真实查询由用户针对具体记录触发核对。
