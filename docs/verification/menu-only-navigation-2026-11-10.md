# 菜单短地址更正核对

日期：2026-11-10。对应 RH-0066 的用户后续反馈。

## 原因与范围

第一轮只清理跨页残留，仍把项目、应用、工作区、已选渠道及记录当作深链必要字段写入地址栏。用户再次指出发布页仍然过长，明确希望与帮助入口一样只有菜单参数。这是导航设计仍未符合预期，并非旧构建或浏览器缓存导致。

本轮统一让所有菜单只显示 `?view=…`；发布页使用 `?view=releases`，`?view=help` 属于帮助菜单。页面内应用、渠道、筛选、分页和详情经既有白名单处理，保存在带版本的当前浏览器历史项，订阅不能只比较地址字符串。

同一标签页刷新恢复当前选择，前进后退恢复对应历史项；菜单点击回到首页，发布详情仍可返回原列表筛选。旧长链接可以导入原定位并原位缩短。复制新的短地址到新标签页或其他浏览器时只打开菜单首页，不从其他标签页或全局缓存猜测应用。

浏览器历史只保存公开定位，不保存秘密、安装包、表单草稿或执行授权，不新增 localStorage／sessionStorage 数据。导航与旧链接迁移不产生商店查询、预检、准备、上传或提交。

## 验证

- 已运行回归，原实现将应用和渠道字段写回地址栏，断言失败；修复后通过。
- 11 项导航测试通过，覆盖菜单短地址、当前历史项恢复、同地址前后退、旧链接导入、版本及菜单不匹配拒绝和公开字段白名单。
- 类型检查、完整自动测试（289 项）、构建与完整 Chrome 冒烟通过。浏览器使用独立回环端口 4473／4474 和临时目录，避免并行验收宿主的数据互相影响。
- 专项覆盖原长链接缩短、当前菜单重置、同地址详情切换、刷新与前后退、发布列表返回筛选，以及复制短地址到独立标签页；导航观察窗口零业务写请求，1440／375／844 视口通过。
- 测试重新访问同一短地址时先离开文档，避免浏览器将其作为刷新并保留上一场景；真正的菜单与刷新行为单独断言。浏览器使用显式上下文支持独立标签页检查。
