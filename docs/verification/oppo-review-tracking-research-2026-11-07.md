# OPPO 送审后审核状态查询调查

核对日期：2026-11-07。范围为普通应用的 APK 版本审核查询，仅使用 OPPO 官方公开文档及其页面使用的公开文档读取接口；未读取真实账号，未调用鉴权、应用查询、上传、送审或其他真实业务接口。

## 调查结论

**OPPO 可以继续接入送审后的审核状态查询，已有足够的一手文档支持主要阶段映射。** 上一轮只阅读普通包详情正文，没有找到独立的[《审核状态对照表》](https://open.oppomobile.com/documentation/page/info?id=11176)。本次从官方文档搜索及“软件商店 → API传包能力”目录确认该表与普通包查询同属一个能力章节，补齐了此前缺失的状态取值证据。

实施时应读取指定版本的 `audit_status`，保留官方阶段描述；查询最新商店状态时可以省略版本参数，但展示与归属只能指向响应中的版本。已发布旧包、异步处理成功、资料审核通过都不能代替新包审核结果。

本次只完成公开资料核查。状态映射、版本定位及真实送审后的可见性仍须分别由合成测试与用户指定版本验收，不能把找到文档写成已经完成真实审核验收。

## 已确认：普通包详情支持指定版本

来源：[《查询普通包应用详情》](https://open.oppomobile.com/documentation/page/info?id=11004)。

| 项目                                         | 官方定义                       | 实施含义                                               |
| -------------------------------------------- | ------------------------------ | ------------------------------------------------------ |
| 查询接口                                     | `GET /resource/v1/app/info`    | 属于读取详情，无须发起新的发布动作                     |
| `pkg_name`                                   | 必传，应用包名                 | 从可信商店绑定恢复，不能接受任意浏览器目标             |
| `version_code`                               | 非必传，版本号，默认取最新版本 | 查询某次新包时显式传入其构建号；独立商店目录可默认最新 |
| `pkg_name`、`app_id`                         | 响应中的应用身份               | 核对目标归属，错配不能产生该绑定的状态                 |
| `version_id`、`version_code`、`version_name` | 响应中的版本身份               | 展示实际返回的版本；指定版本查询须核对构建号等身份     |
| `audit_status`                               | `string`，审核状态             | 可结合独立对照表解释，必须按字符串精确识别             |
| `audit_status_name`                          | `string`，审核状态描述         | 可核对官方描述，不能用任意自由文本推导成功             |

**尚未核实的边界：** 官方“默认取最新版本”没有进一步定义草稿、送审中、线上版本并存时的选择优先级，也没有承诺提交后立即可见。因此默认查询不能被描述成“无论何时都必然返回刚送审的新包”。已知构建号的精确跟踪应带 `version_code`；若未返回该版本或身份不匹配，应明确“尚未查询到该版本”，保留旧包的独立事实，不自动用旧包替换新包结果。

## 已确认：官方审核状态对照表

来源：[《审核状态对照表》](https://open.oppomobile.com/documentation/page/info?id=11176)。官方目录将该文档、普通包详情、发布版本和获取任务状态并列置于“API传包能力”下；目录可从[软件商店文档中心](https://open.oppomobile.com/documentation/page/info?id=10998)导航确认。

下表“官方描述”为原文；“建议展示”属于本项目的产品映射建议，不是官方新增的状态定义。

| 字段值 | 官方描述       | 建议展示与边界                                                 |
| ------ | -------------- | -------------------------------------------------------------- |
| `0`    | 未发布         | 未发布，不显示审核通过                                         |
| `1`    | 审核中         | 审核中                                                         |
| `2`    | 审核通过       | 审核通过，不能直接显示已上架                                   |
| `3`    | 测试不通过     | 审核未通过，并保留“测试不通过”阶段说明                         |
| `4`    | 运营审核中     | 审核中，并保留运营审核阶段                                     |
| `5`    | 运营打回       | 审核未通过，并保留运营打回阶段                                 |
| `6`    | 运营通过       | 展示运营通过；文档未解释与其他审核阶段的先后关系，不推断已上架 |
| `7`    | 定时发布       | 待定时发布，不显示已上架                                       |
| `00`   | 资质审核中     | 明确资质审核阶段，不混为整包审核通过                           |
| `11`   | 资质审核通过   | 明确资质通过，不推断 APK 审核通过或已上架                      |
| `-11`  | 资质审核不通过 | 明确资质审核未通过                                             |
| `-22`  | 报备提交成功   | 仅报备提交事实，不推断整包审核中或通过                         |
| `22`   | 已冻结         | 明确冻结，需要到官方后台处理                                   |
| `111`  | 上线           | 该响应版本已上架                                               |
| `222`  | 下线           | 该响应版本已下架                                               |
| `444`  | 审核不通过     | 审核未通过                                                     |
| `x`    | 其他           | 保持未知，不猜测结果                                           |

`audit_status` 的合同类型为字符串；`00` 与 `0` 语义不同，不能先转为数值，也不能以数字正负、大小或通用真值来判断成功。未知取值保持未知，不能默认落入审核通过。

交叉核对：[普通包详情](https://open.oppomobile.com/documentation/page/info?id=11004)的官方成功样例只含 `audit_status_name: "上线"`，没有 `audit_status` 字段，因此不能用该样例证明 `1` 代表上线。[多包详情](https://open.oppomobile.com/documentation/page/info?id=11005)的官方成功样例分别包含 `audit_status: "111"` 配 `audit_status_name: "上线"`，以及 `audit_status: "222"` 配 `audit_status_name: "下线"`，与独立对照表一致。测试使用的状态组合应遵守这项证据，不应把人工构造的 `1` 与“上线”视为官方返回事实。

**`audit_status_name` 的枚举边界：** 普通包详情没有单独列出该字段的完整枚举，也没有明示所有描述始终与上表逐字一致；其官方示例仅提供“上线”。所以可以使用已核实的有限状态码及固定描述进行安全投影，不能假设任意未来文案都属于上表，也不能把响应中的自由文本不加限制地带入公开合同。状态码和描述明显冲突时，宜保留无法确认并提示核对。

**版本适用范围的证据与局限：** 该表在软件商店的通用 API传包章节下，没有限定只供某个版本或只供最新版本使用；普通包详情的同一响应结构同时覆盖指定 `version_code` 和默认查询。因此可以作为该接口的审核状态字典使用。但没有找到保证所有历史版本、所有未来新增取值都完整受该表覆盖的官方承诺，仍须保留未知值与身份核对分支。

## 已确认：这些字段不能替代新版本审核

| 字段或接口                         | 官方语义                                                     | 不能推导的结论                             |
| ---------------------------------- | ------------------------------------------------------------ | ------------------------------------------ |
| `state`                            | 上架状态，`1` 上架、`2` 下架                                 | 应用旧线上版本在架不能证明新送审包已通过   |
| `online_info_offline_apply`        | 上架信息，包含应用 ID、版本 ID 和上下架时间                  | 未核对 `version_id` 时不能归到本次目标版本 |
| `update_info_check`                | 更新资料审核状态，`1` 审核中、`0` 不在审核中                 | 不能当作 APK 审核中或审核通过              |
| `release_status`                   | 分阶段发布状态                                               | 不能代替完整审核结论                       |
| `old_audit_status`                 | 文档列出字段，但说明为空                                     | 不能自行赋予旧包或新包审核语义             |
| `POST /resource/v1/app/task-state` | 发布版本异步处理任务，`1` 待处理、`2` 处理成功、`3` 处理失败 | 处理成功不能证明审核通过或已上架           |

依据：[普通包详情](https://open.oppomobile.com/documentation/page/info?id=11004)、[发布版本](https://open.oppomobile.com/documentation/page/info?id=10999)、[获取任务状态](https://open.oppomobile.com/documentation/page/info?id=11001)。发布版本文档明确说明创建新版本属于异步任务，任务状态文档描述的是该任务处理结果。

## 回调及替代途径

**未找到公开可接入的普通应用审核结果回调合同。** 本次阅读 API传包能力目录、接入说明、详情、发布版本、任务状态、状态对照表、API传包 FAQ，并搜索官方站内“审核通知”“审核结果回调”“状态回调”。没有找到用于普通应用 APK 审核结果的回调 URL 注册、事件格式、验签、重试和版本关联说明。这个结论表示当前调查尚未找到，不能扩大为 OPPO 官方绝对不提供内部或定向能力。

已知可行途径：

1. **现在可做：官方读取接口主动查询。** 使用普通包详情和已确认字典；已知待跟踪版本时带 `version_code`。在产品现有显式查询与缓存模型内接入即可，不依赖回调，也不要求重新提交。
2. **现在可保留：官方后台人工核对。** [《应用管理FAQ》](https://open.oppomobile.com/documentation/page/info?id=10913)明确指向管理中心的应用详情与版本管理，并提到可查看修改建议。版本未返回、字典冲突、特殊冻结状态或未知状态均可引导用户在官方后台核对。
3. **后续核实：向官方在线客服确认未文档化能力。** [《API传包能力接入》](https://open.oppomobile.com/documentation/page/info?id=10998)明确建议有疑问咨询在线客服。可询问最新版本选择规则、同构建号更新时的身份区分、审核回调及权限范围；收到可验证合同后再规划回调。

没有公开合同前，不接入推测的后台私有接口，不将支付、游戏发货、推送消息或小游戏的通知回调套用到普通应用审核，也不把需要人工登录的网页读取包装为稳定官方 API。

## 建议本轮接入范围

- 补齐 OPPO 已核实审核状态码映射与固定阶段说明，并对 `00`、未知码、阶段通过和正式上架分别测试。
- 独立商店状态继续读取官方最新资料；明确展示响应版本与查询时间。
- 已有明确版本的可选发布关联查询携带 `version_code`，对返回包名、版本和应用身份进行校验，不回填授权或改写原回执。
- 继续保留网络、鉴权、无目标版本和无法识别状态的区别，不能将查询失败显示为“未送审”。
- 回调暂不列为已支持；先用官方主动读取解决用户送审后查询需求。
