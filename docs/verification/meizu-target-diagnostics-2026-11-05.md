# 魅族目标预检诊断与兼容修复

日期：2026-11-05。针对用户反馈的“商店应用尚不具备查询条件”进行一次只读故障诊断；不是发布验收，没有上传安装包、创建发布计划或提交审核。仅在可信本机进程内解析选中的凭据，诊断输出只保留状态整数、字段类型与匹配布尔值，未保存原始响应、联系人或证件资料。

## 已确认的两层原因

1. 目标列表和详情均返回数字状态 `50`，应用 ID、包名和来源版本一致。列表的 `replaceStatus` 为数字 `-1`，旧适配器却拒绝所有非空值，导致在读取详情前返回 `application_not_ready`。这是本次截图错误的直接原因。
2. 修正这一拦截后，只读核验继续发现来源详情的 `recommendDesc` 是空字符串。其他已检查的必需字段未触发相同结构异常。当前公开发布接口要求推荐语，因此新检查返回明确的 `meizu_recommendation_missing`，不能编造内容或用空字符串提交。

[魅族官方开发者 API 文档](https://open.flyme.cn/docs?id=333)及其[公开正文](https://apiopen.flyme.cn/api/web/v1/doc-wiki/detail?id=333)列明：状态 `50` 表示上架；修改审核状态 `0`、`1` 分别表示同版本 APK 替换待审、内容修改待审；发布接口将 `recommendDesc` 列为必填。公开字典没有说明 `-1`，本次仅将实际已上架目标返回的数字哨兵作窄范围兼容，不能把其他未知值一律当作无待审。

## 处理与保护

- 允许已上架目标的修改状态省略、null 或数字 `-1`；数字 `0`、`1` 继续阻止更新并明确提示先处理后台修改。其他类型及未知值仍拒绝。
- 列表及详情必须同时满足已上架；ID、包名、版本与普通应用范围检查保持不变。列表通过后详情变为在审，仍然停止。
- 推荐语缺失时，准备页和执行诊断都指向魅族后台补齐；通用失败提示不再一律要求在本页修改账号或安装包。
- 旧预检记录保持原样，只新增只读检查事实。最后一次实际只读复核的结果为 `meizu_recommendation_missing`：产物复核通过、鉴权通过、目标尚未完成核验。没有将其写成发布成功。

## 用户后续操作

在魅族开发者后台维护应用的“推荐语”。如修改资料触发审核，先等待该流程完成，再在工作台点击“准备发布”。只有准备通过并核对摘要、明确确认后才会上传；本轮不会自动重提。

推荐语补齐后的真实准备、安装包资格与送审结果仍待用户验证。当前错误并不要求重新创建账号或重复上传安装包。

## 回归范围

隔离的目标核验回归覆盖数字 `-1`、省略、null、明确待审、未知整数、字符串及布尔值，列表和详情状态变化、目标与版本错配，以及推荐语为空、空白或 null。凭据使用内存替身，网络仅响应固定只读路由。完整魅族执行协议夹具也改用 `-1`，保护预检与执行共用的来源核验。

浏览器夹具以固定合成目标复现推荐语缺失，验证页面显示具体建议、失败不创建计划或尝试，修正后显式重新准备及既有确认流程；不请求真实商店。
