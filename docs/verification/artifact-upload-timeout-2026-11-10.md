# 隧道慢速安装包上传超时修复

日期：2026-11-10。对应问题：RH-0070。

## 原因与证据

用户通过已指定 cpolar 域名上传约 154 MiB APK，页面显示“文件接收超时，已停止本次接收。”只读核对实际记录，两次 `upload_timeout` 分别在接收开始后 120.019 秒和 120.020 秒结束。本机与隧道健康接口均返回 200。

接收器原来对整个请求设置固定 120 秒期限，收到新字节也不延期；浏览器另有约 125 秒期限。持续传输的大包仍会被主动中断。已确认该根因，不据此推断隧道没有其他独立限制。

## 修复范围

- 接收器独立保留一小时绝对总时限，连续两分钟没有写入进度才按空闲超时停止。只有实际写完非空字节块可以续空闲窗口。
- 前端使用同一公开合同，等待一小时加五秒，为失败持久化和响应预留时间。
- 保留流式写盘、实际长度与 SHA-256 核对、失败清理、单接收／检查槽位和独立身份检查。没有修改来源、归属、配额或发布授权。
- 超时保留失败事实，用户核对后重新上传；不重写旧失败记录，不自动重传。

## 验证

`node --import tsx --test tests/artifact-upload-timeout.test.ts` 已通过四项回归：持续进度超过原两分钟仍完成、初始无数据超时、中途停滞超时、持续进度不能延长绝对总时限。修复前持续进度场景已复现同一 `upload_timeout`。

服务层回归实际验证超时清除 partial／payload、保留失败分类，以及下一次上传可进入检查并通过身份检查。全部使用临时目录与合成数据。

`pnpm typecheck`、`pnpm test`（294 项全部通过）、`pnpm build`、`pnpm format:check` 与 `pnpm test:smoke` 全部通过。完整 Chrome 冒烟覆盖实际安装包上传、损坏与错配反馈、批次默认说明和日期回填、隐藏入口及多视口，未发现未处理异常。

慢速浏览器命令为 `node --import tsx scripts/artifact-upload-timeout-smoke.mjs`：独立端口 4418、临时工作台与合成 IPA；浏览器发起真实 Service 请求，测试转发器将相同字节分成四段、每隔 45 秒发往真实接收接口。126 秒时检查浏览器仍等待、服务端仍接收，135 秒后核对 HTTP 202、独立身份与摘要及刷新持久化。该场景不经过真实隧道、不使用用户 APK，不代表真实商店发布验收。

慢速专项实际通过：126 秒双端状态断言成功，136.565 秒完成 HTTP 202、真实独立身份检查、SHA-256 核对及刷新恢复，浏览器无未处理异常。补充测试初始化的有界等待后，四项计时回归与服务清理回归再次通过。
