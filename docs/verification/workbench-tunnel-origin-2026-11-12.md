# 隧道换域名 403 核对

问题编号：RH-0082。

在实际运行的回环 API 上向只读健康接口发送未配置域名作为 Host，复现 403「当前服务仅接受本机访问」。只变更 Origin 时命中另一处拒绝；使用旧来源与回环 Host 访问团队会话，又命中团队同源限制。之前的修复统一了业务来源，仍未覆盖保留外部 Host 的代理及团队登录。

回归先使用隔离的生产入口配置一个新 HTTPS 来源。旧代码在团队会话探测处返回同一条 403；修复后，配置由 API、团队认证、普通业务门禁和 Vite 共同读取。未配置域名、伪造转发头、不匹配的 Host／Origin、缺操作标记和隧道访问个人模式继续拒绝。已启用团队时匿名业务返回 401，退出后会话不可重用；账号材料配置继续只接受本机页面。

- `pnpm exec tsx --test tests/workbench-origins.test.ts`：使用真实 API 和 Vite 进程，验证新域名同源登录、HTTPS Cookie、业务操作标记与旧域名拒绝。
- `node --import tsx scripts/workbench-origins-smoke.mjs`：隔离 Chrome 模拟保留 Host 的代理，登录后保存模板返回 201，准备五个渠道返回 202。使用合成 APK 和空商店账号目录，无确认、执行或商店请求。

使用真实隧道的只读健康接口也复现了原 403；当时 HTTP 与 HTTPS 都会转发到旧实例。启用团队域名入口前，应先在代理侧关闭 HTTP 或设置 HTTPS 跳转，再在同一安装的 `.env` 配置实际 HTTPS 来源并重启。未修改运行中的代理或 API，专项使用合成域名，不能代替真实隧道的上线验收。详见[部署指南](../DEPLOYMENT.md#通过指定-https-隧道访问)。
