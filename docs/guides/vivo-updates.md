# vivo 普通应用更新

当前工程接入已有、已上架普通应用的单 APK 递增更新。真实商店验收待完成，不支持游戏、新应用创建、32／64 分包或分阶段发布。

## 一次配置

1. 在 vivo 开放平台“管理中心 → 账号管理 → API 管理”开通 API 传包，获取正式环境 access_key 和 access_secret；不要使用推送密钥或沙箱账号。
2. 在“商店账号”新增 vivo 账号，页面填写 Access Key 和 Access Secret，安全保存在本机；重新核对仅检查本机材料，不是商店授权验证。
3. 为 Android 应用添加 vivo 绑定，目标自动使用该应用包名，选择已配置账号。

## 日常更新

选择检查通过的 APK，填写 5–200 字更新说明，选择“审核通过后立即上架”或“指定时间上架”，点击“准备发布”。构建号必须高于商店来源；在审、待上架、缺失兼容设备等情况会停止准备。

系统沿用现有名称、图标和其他资料，不要求重复上传。摘要展示来源构建号、兼容设备、版本、说明和上架意图。定时时间从设备时区换算成 UTC 保存，再按 Asia/Shanghai 发送中国平台，请在后台核对实际设置。关闭摘要不会上传。

核对后勾选并点击一次“确认提交审核”。系统先上传 APK，核对文件回执，再同步提交更新。明确成功显示“更新已接收”，不代表已过审或已上架。

## 异常处理

- “未上传”：本次未取得远端许可，按具体诊断修正后重新准备；原授权不能重用。
- “待核对”：核对同一包名、构建号、审核／更新记录及处理中任务，不能仅因列表暂时没有版本就重新提交。系统不自动重试。
- 只有后台确认已接收，或确定未接收且无处理中任务，才在原记录登记对应人工结论；保留原始回执。
- 接口限流或日限额、权限／签名、版本、说明及时间错误展示固定建议；供应商原始正文和秘密不进入页面。
