# 工作台快速使用指南

## 启动

首次准备 Node.js 24、pnpm 11.20.0，在项目目录执行 `pnpm install --frozen-lockfile`。macOS 安全凭据需要系统钥匙串；出现系统访问提示时在系统窗口处理。

日常双击项目根目录的 `启动 Release Harbor.command`，或执行 `pnpm workbench`。启动器先检查环境和端口，已有健康实例时只打开页面；新实例构建当前工作台，再启动本机服务并自动打开浏览器。终端中会显示访问地址，关闭本次启动终端会停止本次服务。

如果提示缺少工具，请按提示安装；启动器不会自动安装软件或结束占用端口的程序。macOS 首次通过系统安全检查后可从 Finder 打开；若当前权限不允许双击，仍可使用上述终端命令。开发者继续使用 `pnpm dev`，页面地址为 `http://127.0.0.1:5178`；统一启动的新实例默认为 `http://127.0.0.1:4399`。

## 第一次配置

1. 首页进入“检查本机环境”，查看安装包检查工具及服务状态。这不验证商店权限。
2. 回到发布中心，选择“新建第一个应用”；或从应用管理选择“新建应用”。
3. 填写应用名称、平台和真实包身份。项目仅用于分组，可复用已有项目；无项目时自动建立“我的应用”，不要求手填内部标识或技术栈。
4. 在渠道配置中添加目标，选择已有账号或页面新增账号。保存账号材料不代表商店鉴权通过。
5. 就绪检查仅读本机配置。没有渠道时可返回配置；缺少安装包时可在发布页上传。已保存应用可从应用管理继续维护。

## 日常发布

发布中心是首页。三个快捷入口只显示本机处理中、待确认／待执行和未核对的未知执行；普通失败和过期摘要从完整列表进入处理。

点击发起发布、选择应用，再选择渠道。单渠道使用原有发布确认，多渠道使用 Android 批次摘要。华为批次只保存草稿；需要正式送审时单选华为并明确选择提交审核。iOS 上传构建与已有构建审核／手动发布各自保留。

有新包时展开“上传新安装包”，选择后点击“上传并检查”，通过后在发布安装包选项中选择。填写说明与策略，准备、核对摘要并确认。更改渠道会清除当前未保存的内容，页面会先询问；刷新只恢复已保存定位和记录，不恢复未保存的表单草稿。

审核状态按商店渠道计数，详情保留官方来源、版本和时间。查询失败与审核拒绝分别显示，历史版本收在详情。设置自动跟踪、检查商店资料和查询历史按需展开；原本地发布关联是辅助历史入口，不是查询前提。

## 配置与帮助

- 应用管理直接列出各平台应用，支持项目分组筛选；应用内维护渠道配置、安装包与发布前检查。
- 商店账号的检查本机材料仅核对本机保存情况；更新凭据复用原引用，改名和删除在更多操作中。
- 本机设置依次为存储管理、备份与恢复、通知设置、运行诊断。通知记录从右上角铃铛统一查看。
- 商店指南、问题档案和产品路线图统一在帮助与支持。历史链接仍可访问。

所有默认导航和刷新仅读取本机事实。明确查询或用户已开启的只读跟踪才访问商店；上传并检查安装包不会自动准备、送审或上线。
