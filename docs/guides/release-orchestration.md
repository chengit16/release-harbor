# 送审与上线操作指南

更新日期：2026-11-08。第四期工程范围已交付，实际商店验收按具体版本分别记录。本指南覆盖已有应用更新，不创建商店新应用、不做全量资料编辑或后台自动调度。

## 日常操作

1. 在“应用管理”维护身份、商店绑定和检查通过的新安装包；商店账号配置后可复用。
2. 进入“发布中心 → 发起发布”。Android／HarmonyOS 选择已有渠道和安装包，填写更新说明与上架类型；华为 Android 明确选择草稿或正式送审。Apple 已上传构建从“已有构建审核与发布”选择对应商店版本和构建，无需重新上传 IPA。
3. 点击“准备发布”，系统只读校验并冻结目标、产物、资料、语言、动作和策略。准备不上传；资料缺项、来源变化或有在审冲突时，按提示到后台处理并重新准备。
4. 在摘要中核对“计划动作”“资料写入范围”“说明修改语种”和“上架类型”。新包、更新说明和复用字段均随同一次摘要确认；修改意图需要重新准备，不编辑旧快照。
5. 明确同意并确认一次。执行器完成渠道步骤并记录实际阶段，关闭摘要不会发放授权。执行成功、审核通过和上架是不同事实。
6. 到独立“审核状态”菜单显式查询官方。刷新和历史查看仅读取缓存；缓存有时间且非实时。平台未公开的信息到官方后台查看。

| 渠道／动作                  | 工作台本次修改与复用                                                            | 语言边界                     |
| --------------------------- | ------------------------------------------------------------------------------- | ---------------------------- |

| OPPO／魅族                  | 新 APK 与更新说明；按接口要求重新提交原有资料，私人材料仅在执行器内复用         | 沿用接口现有范围，不新增语种 |
| vivo／应用宝                | 新 APK 与更新说明，其他未修改字段沿用后台                                       | 接口不独立选择语种           |

| 华为 Android 正式送审／鸿蒙 | 新安装包与默认语言更新说明，等待解析后送审                                      | 摘要展示默认语种             |
| 华为 Android 草稿           | 原有草稿上传；不承诺指定语种说明已同步                                          | 仅按原 SDK 草稿范围          |
| Apple 已有构建送审          | 关联构建、同一更新说明写入摘要列出的现有语种，并设置发布方式                    | 不新增语种、不自动翻译       |
| Apple 上传／手动发布        | 上传仅接入 IPA，说明与策略仅保存在计划；手动发布仅请求发布已批准版本            | 不再写商店资料               |

名称、介绍、截图、图标、隐私政策、资质及完整合规资料的主动编辑继续在官方后台进行，完成后重新准备。部分官方 API 提供更多写入字段，但本工作台尚未开放这些编辑或纯资料更新动作；不能把“沿用资料”理解为整份内容均已检查或冻结。私人审核资料不出执行器，公开摘要不显示登录材料。

## 上架策略

- Android／HarmonyOS 可选择审核通过后立即上架或指定时间，魅族公开 API 没有定时字段，明确不可选。华为草稿仅记录意图；多渠道批次的华为项仍保存草稿，不隐式升级成正式送审。
- 时间按设备时区选择，计划保存 UTC。小米按毫秒、应用宝按秒时间戳发送；华为 Android、鸿蒙及荣耀使用明确 UTC 偏移。秒级接口向后取整，最多延后不足一秒，避免比确认时刻提前。
- OPPO／vivo 的无时区时间按 Asia/Shanghai 发送。这是当前工程映射，官方字段没有明示时区，须核对后台显示时间。鸿蒙立即发布显式发送过去时间，避免继承旧定时设置。
- iOS 按本项目需求仅提供审核后自动／手动发布。Apple 官方另有定时能力，本项目不开放。审核提交设置 MANUAL／AFTER_APPROVAL，清除旧 earliestReleaseDate；手动发布需待 Apple 明确批准且等待开发者发布后，再准备独立摘要并确认一次。
- 摘要中的选择是冻结意图；受理回执证明相应动作阶段，不能标成“定时已生效”。实际策略由官方回读或后台确认，审核通过也不保证商店已可下载。到期的指定时间会停止后续执行，不能自动切换立即上架。

## 读懂执行结果

| 结果                               | 能证明什么                               | 后续操作                                             |
| ---------------------------------- | ---------------------------------------- | ---------------------------------------------------- |
| Apple 上传已接收／构建处理中／可用 | 上传或对应构建处理阶段                   | 选择已有构建进行独立审核准备                         |
| 华为草稿已保存                     | 草稿保存事实                             | 另行选择正式送审，不能当作已在审                     |
| OPPO 版本处理成功                  | 同包名、同构建号的异步任务处理完成       | 查询版本审核状态；不是审核通过                       |
| vivo 更新已接收                    | 同步更新请求明确受理                     | 继续查看官方审核及上架状态                           |
| 已提交审核                         | 该渠道明确受理或核对到本次在审版本       | 审核与实际上架继续独立核对                           |
| Apple 手动发布请求已受理           | 发出发布请求，不能由本工作台撤销         | 查询实际上架状态                                     |
| 提交前失败／执行前中断             | 未获远端写许可，本次授权已消费           | 修正后重新准备                                       |
| 待核对                             | 写许可后结果不明、任务仍处理或回执不匹配 | 到后台核对同一目标、版本及处理中记录，再登记人工结论 |

许可后不自动重试、续跑或回滚。人工确认不存在时也只允许重新准备，不恢复旧授权；确认已存在保留版本防重。状态查询和人工记录不改写原回执，也不会自动解除未知执行保护。

## 真实验收

在准备好的真实摘要中，由用户明确选择账号、应用、版本／构建、安装包和实际动作后执行。分别核对资料语言、审核受理、策略时间、审核结果及最终上架；未发生的步骤继续待验。逐渠道表与本轮工程证据见[第四期收尾记录](../verification/phase-4-completion-2026-11-08.md)，官方字段见[核对](../verification/phase-4-official-policies-2026-11-08.md)。合成网络及浏览器通过不能替代这一过程。
