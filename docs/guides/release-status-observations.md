# 商店审核状态查询

“审核状态”直接从已绑定应用查询商店官方版本，**不要求在 Release Harbor 创建计划或发布过应用**。在官网手动提交的版本也可以查询。各渠道接口能力不同，版本资料可读取不等于已能确认审核结果。

## 操作步骤

1. 在“应用管理”保存应用与商店绑定，并在“商店账号”配置对应账号。
2. 打开“发布 → 审核状态”，默认进入“商店状态”。按项目、应用、渠道筛选，绑定存在就会显示。
3. 点击“查看详情”阅读该渠道的查询范围，再点击“查询商店状态”。这一步只读，不上传、送审或发布，不需要再次确认发布授权。
4. 核对版本 ID、版本名、构建号、查询时间及状态。字段未提供时明确显示缺失，不从本机历史猜测。

页面刷新及“刷新商店目录”仅读取本机绑定与缓存，不自动请求商店。查询结果均带时间并标记非实时。桌面显示表格，手机显示卡片；筛选、详情与页签定位保存在 URL，可刷新、深链和前后退。

## 渠道范围

| 渠道         | 当前独立查询能力                                                             | 限制                                                                                            |
| ------------ | ---------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| 魅族         | 官方版本目录，按商店版本 ID 展示待审／在审、不通过、上架、下架               | 官方不提供构建号；未知码保持未知，不要求原执行锚点                                              |
| 荣耀         | 包名核对 App ID，读取当前审核流程及已上架版本                                | 当前流程与在架版本分别展示；不能冒充历史审核单                                                  |
| Apple        | App Store 版本及其关联构建，识别在审、拒绝、待发布、在架、撤审及已替代等状态 | 查询不再扫描全部 TestFlight 构建；超过 200 个商店版本仍明确拒绝截断，自动／手动发布仍在发布中心 |
| vivo         | 官方审核字典：草稿、在审、通过、拒绝、撤审；通过后再结合在架／下架           | 旧包在架不能覆盖当前在审或拒绝；官方未提供版本名时保持缺失                                      |
| OPPO         | 官方返回版本的在审、未通过、通过、待发布、上下架及资质／运营等阶段           | 资质／运营通过不代表整包通过；默认最新不保证始终是刚送审新包，须核对版本和构建号                |
| 应用宝       | 官方独立审核接口：在审、驳回、通过、主动撤销；另列版本资料                   | 审核接口不返回版本标识，不将审核结果挂到详情的线上旧版本；通过不等于上架                        |
| 华为鸿蒙     | v3 正式全网状态，包含草稿、在审、拒绝、待上架、下架及预审；旧在架另列        | 仅 releaseType=1，不混用测试字典或 Android 端点                                                 |
| 小米         | 小米官方公开详情页的当前在架版本，标记“公开在架”                             | 暂未开放审核进度接口；在架旧版本不代表当前送审通过，更新许可不作为审核结论                      |
| 华为 Android | v2 正式全网状态，当前流程与明确的旧在架版本分别列出                          | 不混用鸿蒙、测试或分阶段发布状态                                                                |

此处范围指工程接入；真实商店结果由用户点击具体绑定查询后核对，本地合成测试不能代替真实验收。

## 提交新版本后能否查到

华为 Android、vivo、魅族、荣耀、Apple、应用宝及鸿蒙已接入相应官方审核查询；OPPO 本轮找到官方独立字典，已补齐主要阶段。它们的精度并不相同：荣耀独立查询为当前申请，新执行关联可按原审核单查询；应用宝审核不返回版本标识；OPPO 默认查询最新版本，也可在详情输入构建号定位。送审后应在详情核对响应版本／构建号；若仍是旧版本，不能当作新包已通过。

小米仍没有公开的审核进度接口，当前“公开在架”只证明公开商店的那个版本已上架，送审中和拒绝仍需到小米后台核对，可在详情保存人工记录及实际核对时间。可进一步向官方咨询正式开放能力；需要登录的浏览器辅助属于后续单独评估，当前没有接入。完整能力表和解决路径见[送审后查询核对](../verification/submitted-review-capabilities-2026-11-07.md)。

摘要、手机卡片和版本详情使用状态标签：上架／整包通过为绿色，在审为蓝色，拒绝为红色，待发布或无法确认等为橙色，草稿、下架和历史替代等为灰色；资质／运营阶段通过使用青色。完整文字与范围提示保留，不能只凭颜色判断。本行多个标签可能来自不同历史版本，查看详情才能确定各自所属版本。

## 没有数据时

“商店状态”没有绑定行时，先点击“重置查询筛选”，再检查应用管理中的商店绑定及当前本机数据目录。仅保存账号不会自动替应用建立绑定。**无需为了出现列表而重新发布应用**。

有绑定、没有版本时，先区分尚未查询、查询失败、官方本次没有返回版本、渠道尚未接入。升级程序后请点击具体渠道的“查询商店状态”更新旧缓存；仅刷新页面不会自动重新查询。查询失败不是审核失败；“尚无法确认”也不是审核中。

## 查询失败与重复点击

错误使用固定分类提示：账号验证、请求被商店拒绝、网络、响应无法核对或尚未支持。请求被拒绝与网络失败分开，避免把不合法参数当成网络故障。原始商店正文、私人审核意见和附件不进入页面，具体拒绝原因到商店后台查看。

失败保留上次成功版本及原查询时间，明确标为历史参考，不冒充本次成功。查询前持久化预约，活动查询最多等待 160 秒；同绑定未完成预约三分钟内不重发，已完成查询十秒内不重复。这是本机产品防重复策略，不宣称为官方额度；不会自动轮询或终态永久停止，后续新版本仍可主动查询。关闭页面只结束浏览器等待，服务已开始的只读查询可能继续并保存。

绑定配置变化后旧目标缓存不展示，查询期间改绑将拒绝将结果关联新目标。新缓存保存在数据目录 `store-status.json`，不改写发布计划、执行回执、授权和人工核对，也不解除原待核对保护。

## 本地发布关联

“本地发布关联”是原有历史视图，用于查看本工具曾执行过的记录与原观察，不作为查询官网版本的前置条件。旧发布详情深链继续定位该页签；原按计划查询及其节流规则保持原样。

魅族旧记录缺少送审版本锚点时，无法证明该次本机执行和某个商店版本属于同一提交；这不妨碍在“商店状态”读取官方版本目录。新版本目录结果不反填旧锚点、不改旧快照、不将其他版本的状态关联原执行。

2026-11-07 的官方依据、iOS 根因与实际只读复验见[渠道状态补齐记录](../verification/store-status-channel-fixes-2026-11-07.md)。

## 精确定位与人工记录

OPPO 详情的“按构建号查询”接受 APK versionCode 或后台显示的正整数构建号。指定构建结果单独保存，默认目录不被替换；响应未匹配指定构建时明确失败。两种查询共用同绑定十秒冷却，查询中和未完成预约继续受原窗口限制。每个绑定最多保留最近二十个构建范围，不作为永久历史档案。

小米详情点击“添加人工核对”，填写版本、可选构建号、后台状态、实际核对时间与简短备注。时间按本机时区输入，保存使用带时区时间；不可填未来时间。人工记录追加保存且显示来源，无法替代小米官方缺失的审核接口。相同输入失败重试不会重复追加；修改输入将生成新记录。每个绑定指纹最多二百条，达到上限须先备份并由维护者整理。不要在备注粘贴账号、密钥、测试登录资料或原始审核意见。

荣耀新送审成功后会保存原审核单 ID，在“本地发布关联”查询该确定审核单。旧记录没有锚点时保持原匹配规则；不需为补锚点重新送审。审核单已通过后，后续只核对同版本是否上架，未确认在架时保留此前审核时间，不冒充本次重新取得通过结论。

## 待办处理与资料检查

“审核状态 → 待办处理”使用已有官方查询和人工记录，支持项目、应用、渠道及待办分类筛选；进入、刷新、前后退均不主动查询商店。

- 审核需处理：到官方后台阅读具体意见，处理后再通过发布中心准备新动作。
- 等待手动发布：仅 Apple 的 PENDING_DEVELOPER_RELEASE 生成；前往发布中心选择版本并确认。PENDING_APPLE_RELEASE 只表示等待商店发布。
- 查询失败：展示固定原因与恢复指引，失败前的成功只在详情保留参考，不生成新的可发布动作。
- 需后台核对：未知／冻结状态，或小米缺少人工记录；无来源事实时明确显示尚无核对记录。
- 资料待完善：草稿版本提供核对指引，详情检查可见的版本定位字段及 Apple 草稿构建关联；隐私、截图和合规材料标为未检查，不能据此认定已齐全。

人工核对按实际核对时间取每个版本／构建的最新事实，保留旧历史；没有待办仅表示当前记录没有匹配事项，不表示全部商店均已审核通过。详情将当前流程、在架版本及可展开历史分别展示，避免旧上架或已替代版本干扰处理。
