# 商店审核状态查询

“审核状态”直接从已绑定应用查询商店官方版本，**不要求在 Release Harbor 创建计划或发布过应用**。在官网手动提交的版本也可以查询。各渠道接口能力不同，版本资料可读取不等于已能确认审核结果。

## 操作步骤

1. 在“应用管理”保存应用与商店绑定，并在“商店账号”配置对应账号。
2. 打开“发布 → 审核状态”，默认进入“商店状态”。按项目、应用、渠道筛选，绑定存在就会显示。
3. 点击“查看详情”阅读该渠道的查询范围，再点击“查询商店状态”。这一步只读，不上传、送审或发布，不需要再次确认发布授权。
4. 核对版本 ID、版本名、构建号、查询时间及状态。字段未提供时明确显示缺失，不从本机历史猜测。

页面刷新及“刷新商店目录”仅读取本机绑定与缓存，不自动请求商店。查询结果均带时间并标记非实时。桌面显示表格，手机显示卡片；筛选、详情与页签定位保存在 URL，可刷新、深链和前后退。

## 没有数据时

“商店状态”没有绑定行时，先点击“重置查询筛选”，再检查应用管理中的商店绑定及当前本机数据目录。仅保存账号不会自动替应用建立绑定。**无需为了出现列表而重新发布应用**。

有绑定、没有版本时，先区分尚未查询、查询失败、官方本次没有返回版本、渠道尚未接入。升级程序后请点击具体渠道的“查询商店状态”更新旧缓存；仅刷新页面不会自动重新查询。查询失败不是审核失败；“尚无法确认”也不是审核中。

## 查询失败与重复点击

错误使用固定分类提示：账号验证、请求被商店拒绝、网络、响应无法核对或尚未支持。请求被拒绝与网络失败分开，避免把不合法参数当成网络故障。原始商店正文、私人审核意见和附件不进入页面，具体拒绝原因到商店后台查看。

失败保留上次成功版本及原查询时间，明确标为历史参考，不冒充本次成功。查询前持久化预约，活动查询最多等待 160 秒；同绑定未完成预约三分钟内不重发，已完成查询十秒内不重复。这是本机产品防重复策略，不宣称为官方额度；不会自动轮询或终态永久停止，后续新版本仍可主动查询。关闭页面只结束浏览器等待，服务已开始的只读查询可能继续并保存。

绑定配置变化后旧目标缓存不展示，查询期间改绑将拒绝将结果关联新目标。新缓存保存在数据目录 `store-status.json`，不改写发布计划、执行回执、授权和人工核对，也不解除原待核对保护。

## 本地发布关联

“本地发布关联”是原有历史视图，用于查看本工具曾执行过的记录与原观察，不作为查询官网版本的前置条件。旧发布详情深链继续定位该页签；原按计划查询及其节流规则保持原样。

魅族旧记录缺少送审版本锚点时，无法证明该次本机执行和某个商店版本属于同一提交；这不妨碍在“商店状态”读取官方版本目录。新版本目录结果不反填旧锚点、不改旧快照、不将其他版本的状态关联原执行。
