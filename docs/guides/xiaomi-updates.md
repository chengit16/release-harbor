# 小米已有应用更新使用说明

当前工程支持小米中国应用商店已有应用的单 APK 更新，动作是提交审核，不是草稿保存。真实账号与商店结果仍需首次验收；本轮开发没有代用户上传真实应用。

## 初次配置

1. 到小米开发者平台的管理中心，打开“自动发布接口”，准备开发者登录邮箱、API 访问密码及平台公钥／证书内容。平台将 API 访问密码称为“私钥”；不要填小米登录密码或 Apple `.p8`。
2. 工作台“商店账号 → 新增商店账号”，选择“小米”。填写上述材料，选择审核测试方式，并填写体验路径。需登录的应用填写审核测试账号密码或固定测试验证码，不需要手写 JSON。
3. 不同应用的测试材料不同时，请为每个应用建立单独命名的档案。不要把某个应用的测试登录材料复用到另一应用。需要调整时使用“重新录入”，原引用及绑定保持。
4. 在 Android 应用的“商店绑定”添加“小米”，目标包名自动使用当前应用身份，无需商店数字 App ID，选择刚创建的账号后保存。

凭据及测试登录材料经独立本机进程保存，普通 API、公开计划和浏览器存储都不保存秘密；页面不能回读旧密码。重新核对只检查本机材料，鉴权和目标检查在准备阶段自动执行。

## 日常版本更新

1. 在“安装包”上传并检查单个 APK。
2. “发布计划”选择小米绑定、安装包，填写更新说明、小米后台当前应用名称、HTTPS 隐私政策和 PNG 图标。图标不超过 256 KiB、边长不超过 2048px；此为本工具接入上限，不等于平台图标质量验收。
3. 点击“准备发布”。系统查询当前账号包名并要求明确允许版本更新，冻结公开资料与字节摘要，不提交商店。
4. 核对摘要：包名、版本、名称、图标、隐私政策、说明和动作。勾选后点击一次“确认提交审核”。关闭摘要不执行。
5. 查看执行记录。“小米已受理审核提交”仅代表明确的接口受理回执，后续审核、审核通过及上线均应在商店后台核对；本轮没有自动查询审核进度或控制审核通过后的上线方式。

执行前会再次比对后台应用名称，避免把本地别名作为商店名称发送；名称变化请重新核对后准备。凭据、绑定或实际字节变化及五分钟期限届满时旧摘要失效，不能静默续期或换材料。

## 失败和结果不明

- 准备失败：根据原页原因修正账号、包名或资料后重新准备。没有明确更新许可时不进入执行；可能需要先处理后台现有任务。
- 已获写入许可后超时、中断或缺少确定回执：显示待核对，并阻止同一目标再次提交。先到小米后台核对版本及审核／上传任务。
- “记录人工核对”选择“审核提交记录已存在”或“未提交且无任何处理中任务”，输入原版本与构建号并明确勾选。结论是用户声明，原始未知记录不改写；旧授权不会恢复或自动重试。
- 系统成功或人工确认已有提交后，相同安装包仍禁止创建另一执行来重复送审。

首轮不支持新应用创建、双包、测试账号超过一个的页面编辑、平板新增素材、审核状态追踪、自动上线或其他 Android 渠道。维护 CLI 可导入官方多测试账号结构，页面重新录入会以当前单测试账号配置替换；历史档案不会自动变更。

## 存储兼容

`release-plans.json` 读取版本 1–4 的旧记录，写入版本 5 以容纳小米公开资料及审核回执。华为／Apple 原快照、指纹及时间保持，新增小米字段不回填旧记录。升级前可在停止服务后备份整个数据目录；旧程序不能解释新增动作，降级应恢复升级前备份，不手改版本号。

接口依据：[小米应用自动发布接口操作指南](https://dev.mi.com/xiaomihyperos/documentation/detail?pId=1134)。
