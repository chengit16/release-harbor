# OPPO 普通应用版本更新

## 初次配置

先在 OPPO 开放平台创建并上架普通应用，开通 API 传包能力。使用管理员账号进入“管理中心 → 产品导航 → 我的 API → 创建服务端应用”，获取同一服务端应用的 Client ID（19 字符）和 Client Secret（64 字符）。详情见[官方接入说明](https://open.oppomobile.com/documentation/page/info?id=10998)。

在工作台“商店账号”新增 OPPO 账号。材料仅交给独立本机配置服务，不经过普通业务 API。保存后可重新核对、编辑名称、重新录入或删除；有关联绑定时先解除关联。账号保存不代表已通过平台鉴权。

打开 Android 应用的商店绑定，选择 OPPO，目标包名自动采用应用身份。不要填写 Client ID、App Key 或华为式数字 ID。

## 日常发版

1. 上传并检查 APK，versionCode 必须高于 OPPO 最新版本。
2. 在“发布计划”选择 OPPO 绑定和 APK，填写至少五字的更新说明，选择立即或定时上架。
3. 点击“准备发布”。系统自动鉴权、匹配包名及当前版本，并复用商店现有资料；无需日常重填名称、图标、隐私政策或资质。
4. 核对摘要，勾选同意后点击一次“确认提交审核”。关闭摘要不会上传。
5. 查看执行结果，刷新不会重复提交。

定时时间保留 UTC 意图，在国内平台请求中按中国标准时间（Asia/Shanghai）发送。摘要显示时间及作用范围；真实验收时请核对 OPPO 后台的时间。设置不是预约上传，也不表示审核必定在该时间之前完成。

## 资料复用和限制

本切片仅支持已上架普通应用（type=7）、全量、单包、非冻结且无资料审核的版本升级。合作应用、合作游戏、多 CPU 包、新建、同版本更新和分阶段发布待后续安排。状态无法明确核对时停止，不猜测为可更新。

OPPO 普通包详情可能省略 `release_type`，官方详情示例也未提供该字段；缺省本身不作为阻塞条件，但普通应用、已上线、未冻结及无资料审核仍须明确核对。若返回 `release_type`，仅接受全量值 `1`，其他值或空值仍拒绝；本次提交继续使用既有单包更新规则，不因缺省字段开启分阶段发布。

公开资料按白名单固定到计划。测试说明及商务联系人仅在可信执行器内从同一来源版本读取，不显示或持久化到公开计划。平台若缺少必需资料，请先在 OPPO 后台完善，再重新准备；不会用示例联系人或说明兜底。公开资料或来源版本发生变化时，必须重新准备。

## 结果与恢复

OPPO 文件上传成功不代表提交成功；版本接口受理后还要核对异步任务。仅本次包名和构建号匹配且任务处理成功时，显示“版本处理成功”，不代表审核通过或已上架。

处理中、处理失败、上传回执 MD5／大小不匹配、超时或回执不明均显示具体安全原因并保留“待核对”。到后台核对本次版本、审核及上传任务，再记录“审核提交记录已存在”或“未提交且无任何处理中任务”；仍不确定时不解除阻塞。旧授权不能重用，不会自动重试上传或送审。

工程自动化使用合成凭据和隔离目录。真实 OPPO 提交须由用户对具体计划确认，本次开发未代用户上传。
