# Apple IPA 上传与构建核对

当前切片支持已有 iOS 应用的 IPA 上传，不提交审核或设置上架方式。使用前在商店账号配置团队 API Key：Issuer ID、Key ID 与 P-256 `.p8`；绑定数字 App ID，应用身份为 Bundle ID。本机需 macOS、Xcode 与支持 `--upload-package`、API Key 和私钥文件参数的 altool；仅安装 Command Line Tools 不保证可上传。

## 日常操作

1. 接入已签名的 IPA 并通过身份检查。
2. 发布计划选择 Apple 绑定与 IPA，填写说明和上架意图，点击“准备发布”。说明及上架类型仅记录到计划，本次不会同步商店版本资料。
3. 在摘要核对 App ID、Bundle ID、营销版本和构建号，勾选后点击“确认上传构建”。关闭摘要不上传。
4. 查看执行记录：上传已接收表示工具报告成功，但尚无匹配构建；构建处理中表示已匹配目标但尚未处理完成；构建可用表示查询到 VALID，仍未送审或上架。构建处理错误进入待核对，去 App Store Connect 查看具体问题。

上传后仅查询一次构建状态，查询以当前应用、营销版本、构建号和 IOS 平台定位；查询延迟或失败不能把已接收的上传改为未上传。页面刷新只读取原回执，不持续观察商店；处理中的构建后续在 App Store Connect 核对。本次尚无主动刷新处理状态入口。

## 恢复与安全边界

一次确认只消费一次，相同安装包的成功记录阻止重复上传。工具失败、超时或许可后进程中断均待核对；请先检查后台构建及处理中上传，再记录“构建已存在”或“未接收且没有处理中任务”，之后才能创建新计划。不能用草稿或审核提交结论代替 Apple 构建核对。

私钥只在可信 worker 的 0700 运行目录以 0600 临时文件供固定工具读取，不进入参数正文、普通 API、回执或日志。工具 HOME、TMPDIR 与密钥搜索目录均隔离；正常退出及宿主停止会终止进程组并清理。宿主整体被强制结束或系统崩溃可能留下受限临时目录，不能据此推断远端是否已接收。

上传工具单次执行，无备用密码方式或自动重试。版本是否符合递增、签名和平台资格最终由 Apple 检查；工程测试只用合成 IPA、内存凭据及替身工具，真实验收须由用户在具体计划明确执行。

按用户最新纠正，iOS 发布方式为审核通过后自动发布或手动发布，不提供指定时间选项；新准备及冻结拒绝 iOS 定时／Android 手动策略，旧 iOS 定时快照只读保留且不可执行，须重新准备。选择随计划固定，本轮仅记录，后续送审时再同步 Apple。
