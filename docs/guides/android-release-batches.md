# Android 多渠道发布批次

首版适用于同一个 Android 应用的小米、OPPO、vivo、魅族、荣耀、应用宝和华为 AppGallery Android。每家一个绑定、每项一个 APK；iOS 与鸿蒙继续使用独立入口。工程已接入，真实批次验收需在实际账号、安装包和摘要下确认。

## 开始一轮发布

1. 在“发布中心”点击“发起发布”，选择 Android 应用和“多渠道批次”；或从应用管理点击“前往发布中心”后发起。未绑定商店先到“商店绑定”添加账号及目标，安装包须已经上传并检查通过。
2. 勾选本次渠道，展开“批量设置”，选择通用 APK、填写说明及上架方式，点击“应用到 N 个已选渠道”，应用后自动收起。也可逐行选择渠道包、点击“编辑”查看目标和账号引用、修改本行说明及方式。手机未选渠道仅显示标题，勾选后展开配置。同批版本名称须相同，构建号可以不同；不按文件名猜测渠道。
3. 点击“准备 N 个渠道”。这一步只读检查，不上传、不授权。每行失败都有原因，部分失败不会自动排除；修正或明确取消该行选择后重新准备。
4. 全部准备完成后核对一份摘要：渠道和顺序、目标、账号引用、文件及 SHA-256、版本、说明、真实动作及上架选择。勾选后点击“确认执行 N 个渠道”。关闭摘要不授权，摘要五分钟后需重新准备。
5. 查看逐项结果。系统一次执行一个渠道，刷新或关页不会重复提交。华为仍为保存草稿，其他渠道为各自的更新提交；操作结束不表示审核通过或已上架。

通用值不会自动覆盖每行。魅族暂不支持指定时间，需明确改为立即上架或取消该行；华为草稿的上架方式只记录意图，不能当作商店设置生效。

“批量设置”中的输入在本次页面内收起后保留，只有点击应用才覆盖当时已选渠道；之后再勾选的渠道不会自动继承。批次历史默认收起，展开后可查看原有批次和摘要。

## 时间、停止与补发

一次确认固定授权当前摘要中的完整集合和顺序，开始写入窗口为 60 分钟，不会自动延长。每项开始前独立检查实际安装包副本、账号、目标及来源，证明须在五分钟内，且绑定、账号、产物或指定时间均未失效；旧检查时间保留。

“停止后续执行”取消尚未获得远端写许可的项。已获得许可的当前项保留真实结果，停止不表示撤回远端操作。服务停止或重启不会继续旧队列，未开始项标记中断，需要重新准备。

点击“重新准备剩余项”，成功及待核对的渠道默认不勾选。对待核对项先打开执行回执，到商店后台确认版本及是否存在处理中任务，再记录人工结论；确认未受理后才可准备新意图。系统成功或人工确认存在的同一产物始终受去重保护，不会因新批次而重发。

新准备生成新的摘要版本。历史摘要、原回执、写许可和人工结论保留；被新草稿或新摘要取代的版本不可重新确认。网络响应不明时先刷新页面读取已保存的批次，不要把超时当成未执行。批次页暂时隐藏“重新读取批次”“新建批次”和“复用配置与常用模板”入口。

## 存储和验证边界

批次与计划、尝试、准备及 Apple 审核保存在同一个 `release-plans.json`，写入 schema13、读取兼容 1–12。损坏关联会拒绝覆盖。仅支持本机单实例；批次、单渠道及 Apple 操作共用全局写入槽。

自动化只使用隔离合成账号、实际合成 APK 与替身商店网络。真实商店验收另行进行；参见[工程验收记录](../../openspec/changes/add-android-release-batches/verification.md)。

## 第三期衔接

发布中心体验已获用户验收，第三期现已启动。首批荣耀状态观察的入口与边界见[状态查询指南](release-status-observations.md)；既有发布确认、未知结果核对与 Apple 观察继续保留，不把本轮新能力扩展为所有渠道均有审核查询。

## 已受理版本与重新打包

本机已记录成功或人工确认已存在时，相同商店目标不能通过重新签名、重新打包或新建计划／批次重复上传同一版本。Android 按构建号保护，魅族按版本名。更新内容须使用新的合法版本／构建并重新准备确认。结果不明时仍先核对后台；只有明确不存在且没有处理中任务，才记录对应人工结论后重新准备。历史成功记录不可改为失败，查询状态不解除原保护。具体范围见[P4-2 核对记录](../verification/release-target-consistency-2026-11-07.md)。
