# 本机团队工作台

本机团队沿用现有工作台和数据，不需要 Docker、PostgreSQL、域名或组织账号。管理员可以登录并维护成员，也可逐项分配菜单、应用渠道及审核和发布动作权限。成员不能管理商店账号、绑定配置、备份或本机设置。仅支持同一台 Mac 的浏览器访问。

1. 停止使用同一数据目录的旧工作台、开发服务及转发。已有业务数据无须迁移；如果指定过 `RELEASE_HARBOR_DATA_DIR`，初始化与启动使用同一个目录。
2. 在仓库根目录的本机交互终端运行 `pnpm team:init admin`，按提示输入两次管理员密码。密码为 12 至 128 字节，不显示、不放在命令参数中。引导只创建一个管理员，重复运行不覆盖原账号。
3. 执行 `pnpm build && pnpm start`，打开 `http://127.0.0.1:4399`。自定义过 `RELEASE_HARBOR_PORT` 时，用实际端口。团队登录必须直连本机工作台，不能使用现有开发代理或隧道。
4. 管理员登录后可继续操作原有应用、商店账号、审核状态与发布中心。点击右上角「成员管理」可创建成员、停用、重新启用或重置密码，并在成员行打开「成员授权」。成员使用独立浏览器会话登录；同一个浏览器配置中的标签页共享登录会话。

启用后，现有业务 API 也需要登录，成员目前不能绕过页面访问。停用、重新启用或重置密码都会让该成员的旧会话失效；重启工作台后所有人重新登录。安装级团队账号不会随业务备份还原；请保护操作系统账号及工作台数据根，勿运行旧版本绕过团队登录。管理员密码丢失时，当前版本未提供自助重置。

授权按完整绑定配置版本保存；修改商店账号引用或目标后，旧授权自动失效，管理员需重新分配。缓存读取、官方查询、准备、确认执行和人工核对分别授权；Apple 上传、已有构建送审及手动发布独立区分。发布批次须对所有渠道完整授权。成员菜单和按钮仅用于导航提示，API 与后台写许可仍会复核当前权限。

常见授权方式：

- 只看状态：勾选「审核状态」，在指定应用渠道勾选「查看审核缓存」。需要主动查询时，再勾选「查询官方／检查资料」。刷新和导航只读缓存。
- 准备发布：勾选「发布中心」，在指定渠道勾选「准备发布／上传包」及对应发布动作，例如「华为保存草稿」。该成员可以准备摘要，但不能确认执行。
- 准备并执行：在准备权限基础上，再勾选「确认执行」。Apple 上传、已有构建送审与手动发布须分别勾选；多渠道批次每个目标都要具备完整权限。
- 核对未知结果：额外授予「人工核对」。核对保留原回执和版本保护，不能代替重新发布授权。

保存权限后，成员重新聚焦窗口或刷新即可加载菜单与按钮。服务端对下一次操作立即使用新权限；排队任务取得实际写许可前也会检查。已经发出的商店写许可保留原事实，撤权不能撤回远端动作。

已启用并验收 T1 的安装只需停止旧服务，再执行 `pnpm build && pnpm start`，无须重复初始化管理员。下一步 T4 将补齐操作者与授权变更审计；当前历史不会补造成员身份。
