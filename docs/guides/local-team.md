# 本机团队工作台

本机团队沿用现有工作台和数据，不需要 Docker、PostgreSQL、域名或组织账号。管理员可以登录并维护成员，也可逐项分配菜单、应用及审核和发布操作权限。成员的应用管理复用管理员的应用卡片、项目分组和分页，只展示服务端返回的已授权应用；发布中心跳转按菜单授权显示。成员不能新建项目或应用，也不能管理商店账号、绑定配置、备份或本机设置。默认在服务所在电脑访问，也可按[部署指南](../DEPLOYMENT.md#通过指定-https-隧道访问)为此安装指定一个 HTTPS 隧道地址。

1. 停止使用同一数据目录的旧工作台、开发服务及转发。已有业务数据无须迁移；如果指定过 `RELEASE_HARBOR_DATA_DIR`，初始化与启动使用同一个目录。
2. 在仓库根目录的本机交互终端运行 `pnpm team:init admin`，按提示输入两次管理员密码。密码为 12 至 128 字节，不显示、不放在命令参数中。引导只创建一个管理员，重复运行不覆盖原账号。
3. 执行 `pnpm build && pnpm start`，打开 `http://127.0.0.1:4399`。自定义过 `RELEASE_HARBOR_PORT` 时，用实际端口。首次在回环地址登录；指定 HTTPS 隧道也使用同一团队账号和权限，商店账号材料仍在服务所在电脑录入。
4. 管理员登录后可继续操作原有应用、商店账号、审核状态与发布中心。进入侧栏「配置 → 成员管理」可创建成员、停用、重新启用或重置密码，并在成员行打开「成员授权」。成员使用独立浏览器会话登录；同一个浏览器配置中的标签页共享登录会话。

启用后，现有业务 API 也需要登录，成员目前不能绕过页面访问。停用、重新启用或重置密码都会让该成员的旧会话失效；重启工作台后所有人重新登录。安装级团队账号不会随业务备份还原；请保护操作系统账号及工作台数据根，勿运行旧版本绕过团队登录。管理员密码丢失时，当前版本未提供自助重置。

新授权按应用保存，每个应用只配置一组操作，覆盖当前及后续新增的全部渠道。授权窗口支持按应用或项目搜索；尚未配置渠道的应用也能预先分配。缓存读取、官方查询、准备、确认执行和人工核对分别授权。准备／确认权限涵盖该应用对应的渠道发布动作，执行时仍遵守原摘要、真实动作和一次性确认规则。

旧渠道授权保留原指纹及动作范围，不因升级自动扩大。在应用卡中重新勾选操作，会明确替换该应用的旧渠道授权；移除应用授权同时清除该应用旧授权。应用配置变更后，旧计划仍须重新核对，应用权限不能恢复过期授权、解除未知保护或绕过版本防重。菜单和按钮仅用于导航提示，API 与后台写许可仍会复核当前权限。

常见授权方式：

- 只看状态：勾选「审核状态」，在指定应用勾选「查看审核缓存」。需要主动查询时，再勾选「查询官方／检查资料」。刷新和导航只读缓存。
- 准备发布：勾选「发布中心」，在指定应用勾选「准备发布／上传包」。该成员可以准备摘要，但不能确认执行。
- 准备并执行：在准备权限基础上，再勾选「确认执行」。这会覆盖该应用的渠道发布动作；跨应用仍需分别授权。
- 核对未知结果：额外授予「人工核对」。核对保留原回执和版本保护，不能代替重新发布授权。

保存权限后，成员重新聚焦窗口或刷新即可加载菜单与按钮。服务端对下一次操作立即使用新权限；排队任务取得实际写许可前也会检查。已经发出的商店写许可保留原事实，撤权不能撤回远端动作。

已启用并验收 T1 的安装只需停止旧服务，再执行 `pnpm build && pnpm start`，无须重复初始化管理员。T4 已补齐操作者与授权变更审计；旧历史不会补造成员身份。

后续交付顺序见[第五期计划](../plans/phase-5-local-team-plan.md)。

## 操作日志与发布操作者

管理员进入「成员管理 → 操作日志」，可按操作者或目标成员、应用、操作类型和时间筛选，每页最多 50 条。成员创建、启停、密码重置和权限变更记录管理员、时间及变更前后范围；密码重置只记录动作，不保存密码或密码派生材料。应用筛选同时匹配发布记录及授权变更前后的应用范围。

单渠道发布摘要、执行详情、批次详情与 Apple 发布摘要增加「操作者与操作记录」。展开可查看准备、确认、建立尝试、首次写许可和人工核对人员；准备和确认可以来自不同账号。批次包含各子计划的关联，回执始终来自原尝试或 Apple 记录；确认、许可或日志已匹配都不表示审核通过、上架或策略已生效。旧记录显示「历史未记录」，不使用当前登录人补填。

审计先保存安装级事件，再与业务记录一起保存唯一关联凭证。若业务文件写入失败，管理员日志显示「未匹配业务记录」；这可能表示写入未完成、原记录已不在当前数据代或已删除，须核对原事实，不能据此重试送审。发布详情只展示与原记录、摘要和阶段事实匹配的身份。重复请求不更换原操作者，终态回执保存不增加审计写依赖。

账号、权限与日志同属安装级保护目录，不纳入业务备份，不因恢复旧业务数据而回退。当前只支持单宿主写入；日志不提供抵抗操作系统账号直接改文件的保证。事件上限 20,000、团队文件上限 16 MiB，达到容量时拒绝新增变更和发布阶段，保留全部历史；当前没有自动归档或删除日志入口。

升级到本轮版本前停止原工作台服务，再运行 `pnpm build && pnpm start`，用管理员账号重新登录。无需重复执行 `team:init`。团队目录兼容旧格式，首次变更才写入新格式；有新团队发布事件的业务文件使用 schema17，旧快照与摘要保持原样。升级后不要用旧版本宿主读取或覆盖同一数据根。
