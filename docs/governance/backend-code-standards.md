# 后端代码与注释规范

**修订日期：**2026-11-03  
**适用范围：**`apps/api`、`packages/domain`、`packages/contracts`、`packages/provider-app-ship`、`packages/runner-local`，以及相关测试、Node 脚本和后续执行器。

**执行要求：**本规范是人工与 AI 开发、重构、修复和评审的必读约束，从本次建立后对新增及实际修改的代码生效。历史代码按修改范围渐进调整。

本规范参考 KnowSpace 的 `backend-code-standards.md` 中模块、公开接口、业务边界和阶段注释规则，将 Python docstring 适配为 TypeScript／JavaScript JSDoc；工程规则以本项目的 [协作约定](../../AGENTS.md)、[领域术语](../../CONTEXT.md)和[架构设计](../ARCHITECTURE.md)为准，不引入参考项目的 Python、FastAPI、Celery 或数据库选型。

## 1. 技术基线与模块责任

使用 Node.js 24、TypeScript、NestJS 和 Fastify adapter。使用 pnpm，新增依赖固定版本并同步锁文件。格式遵循 `.prettierrc.json`：单引号、无分号、尾逗号、100 列及默认 2 空格缩进。

| 位置                         | 职责与约束                                                                                                          |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| `apps/api`                   | 控制面 HTTP、可信上下文、用例编排、持久化装配与公开错误映射；不解析商店秘密，不在请求内执行长时间上传、送审或上线。 |
| `packages/domain`            | 业务校验、不变量、领域动作与存储端口；不依赖 Web、NestJS、文件存储实现或供应商 SDK。                                |
| `packages/contracts`         | 可公开传输的类型和能力描述；不包含秘密、解密账号、执行器本机绝对路径或框架对象。                                    |
| `packages/provider-app-ship` | 可信 Node 执行器使用的 SDK 适配；统一外部能力、错误与公开投影，不直接暴露 HTTP。                                    |
| 后续执行器                   | 身份、任务领取、产物核对、凭据解析、远端动作和回报；按已批准计划与授权执行。                                        |

Controller 只处理协议参数、调用用例和响应映射；Service 编排业务；Domain 表达规则；存储和外部 Adapter 实现端口。依赖装配留在启动模块，不创建无实际职责的空层或万能 `BaseService`、`BaseRepository`。当前 `projects.module.ts` 可在职责增长后拆分，不要求只为目录形式迁移。

同一业务概念沿用 `CONTEXT.md` 命名，不把发布计划、执行授权、执行记录、回执和远端状态合成一个成功标志。

## 2. TypeScript、命名与公开合同

- 保持 `strict`、`noUncheckedIndexedAccess`，类型导入使用 `import type`。新增公开函数与方法明确参数和返回类型；外部未知输入用 `unknown` 并验证，不能用 `any`、双重断言或非空断言绕过检查。
- 类、接口和类型使用 `PascalCase`；函数和变量使用 `camelCase`；稳定常量、DI Token 可使用 `UPPER_SNAKE_CASE`；NestJS 职责文件使用 `xxx.module.ts`、`xxx.controller.ts`、`xxx.service.ts`，其他文件使用有业务含义的 `kebab-case`。
- 公共合同保持现有字段与类型命名，不机械套用外部项目的 `snake_case` 或请求类型后缀。时间使用明确时区的 UTC 表示，公开时间优先 ISO 8601；大小、摘要和版本说明单位或格式。
- TypeScript 类型不执行运行时校验。HTTP 输入、磁盘 JSON、SDK 返回和后续任务载荷均在边界校验；区分字段缺失、`null`、空字符串与空集合，安全敏感输入拒绝未知字段。
- 不把 NestJS 请求对象、SDK 对象或持久化内部结构直接作为公共响应；映射为 `packages/contracts` 中的安全数据。合同变化同步检查 Web、API、Domain、Adapter、测试与文档。
- 当前 `ApiError` 为 `{ statusCode, message }`，当前 `DomainError` 含状态码是既有实现。新增稳定错误码或框架无关错误分类时统一迁移映射，不在无关任务中改造，也不假设 OpenAPI 生成或错误码系统已经存在。

| 文件类型            | 推荐范围 |    预警范围 | 处理方式                     |
| ------------------- | -------: | ----------: | ---------------------------- |
| Controller、Module  |  ≤200 行 | 201～350 行 | 按资源、装配或用例拆分。     |
| Service、用例       |  ≤250 行 | 251～400 行 | 拆查询、命令或独立业务能力。 |
| Domain              |  ≤300 行 | 301～500 行 | 按领域规则或状态机拆分。     |
| Store、外部 Adapter |  ≤350 行 | 351～600 行 | 按存储聚合或外部能力拆分。   |
| 测试                |  ≤500 行 | 501～800 行 | 按业务行为分组。             |

行数是维护风险信号，生成文件、合同声明和配置另行判断。超过预警上限先评估职责，保留时说明原因，不用无意义转发规避。

## 3. 可信上下文与运行边界

- 当前仅允许 `local` 模式，API 监听回环地址并保留 Host／Origin 校验；这些限制防止本地接口被误用，不代表生产认证已经完成。
- `workspaceId` 当前由可信入口固定为 `local`，请求体不能指定租户归属。未来 hosted 模式的用户和租户必须来自服务端验证的认证上下文，不信任浏览器提供的角色、账号或工作空间 ID。
- 读取、创建、修改、任务和产物访问均保留工作空间约束。知道资源 ID 不构成授权；不先跨空间取数据再交给前端过滤。
- 当前无认证 API 不绑定公网地址。身份、租户授权、线上存储和执行器合同落地前，不通过删除保护检查“临时”开放 hosted。
- 配置只保存凭据引用；商店密码、Token、私钥只由可信执行器在需要时解析。日志、异常、回执、测试夹具及公开响应均需脱敏。
- 环境变量读取与校验优先集中在启动和配置边界，保留 `RELEASE_HARBOR_` 前缀；业务规则不随意读取环境变量，关键配置无效时明确失败。

## 4. 存储、错误与并发

- 当前文件存储只支持单进程串行写入与同目录原子替换。新增写路径必须参与相同并发约束；不能把进程内 Promise 队列描述成跨进程锁或数据库事务。
- 数据损坏、解析失败、权限错误不能降级成空列表后覆盖原文件。仅在明确允许的缺失文件场景初始化；失败必须向调用方返回真实结果。
- 同工作空间项目标识唯一性在存储写入边界保护；不能只在页面或写入前无锁查询。读取及更新须保持相同归属范围。
- 捕获异常用于分类、脱敏、清理或恢复；不静默返回成功。为保持写队列可继续而捕获失败时，必须保留本次操作对调用方的拒绝结果，并注释解释两者区别。
- 公开错误按现有合同映射，不泄露堆栈、本机路径或上游秘密；输入无效、冲突、不存在与内部故障分别处理。基础设施故障不得伪装成业务空结果。
- 后续数据库实现需通过事务和唯一约束保护一致性，查询及更新同时限定工作空间；网络副作用不放在长期持锁的事务内。迁移需说明旧数据兼容、回填和恢复方案，未引入数据库前不预建 ORM 或迁移系统。

## 5. Adapter 与后续执行规则

本节为能力实现时必须满足的设计约束，不代表任务、授权、上传或发布能力当前已完成。

- SDK 依赖、版本差异与错误处理集中于 `packages/provider-app-ship`，锁定实际版本，不把 SDK 方法和类型散落到 API、Domain 或 Web。
- Adapter 接收可信执行上下文，只返回经过筛选的身份、摘要和脱敏证据；执行器本机路径和秘密不得进入公开合同。
- 执行前独立核对执行器身份、计划、工作空间、目标、动作、产物摘要和授权范围。计划存在、按钮可点或任务 ID 有效，都不自动等于获准执行。
- 每次执行保留独立 attempt ID。超时、断网或进程中断可能意味着远端结果不明，应进入待核对流程，不自动重复送审或上线。
- 只读查询或确有幂等保证的动作才能按明确策略有限重试，并说明上限、退避、去重依据与失败恢复。不能笼统给所有 SDK 调用套自动重试。
- SDK 回执、执行事实和状态观察分别保存；上传成功不是已上架，取消本地任务不是撤回远端操作。
- 引入异步任务时定义载荷版本、可信上下文恢复、重复投递、乱序、授权失效和失败记录；HTTP 请求不等待长时间远端动作结束。

## 6. 中文注释规范

### 6.1 文件头、类与公开接口

所有新增手写 `.ts`、`.mjs` 文件，以及实际修改到职责或行为的既有文件，必须提供中文 `@description` JSDoc 文件头，放在首个 `import` 前；有 shebang 时放在其后。生成文件、第三方代码和纯再导出入口除外。

普通文件说明维护主题；启动模块、Controller、Service、Domain、Store、Adapter、执行器及跨模块基础设施还说明职责、依赖方向、写入权，以及实际存在的授权、并发、事务或副作用边界。

```ts
/**
 * @description 本机项目文件存储
 *
 * 实现 ProjectStore，以同一进程内的串行写入和同目录替换保护数据。
 * 存储损坏时拒绝写入，不负责在线认证或多进程事务。
 */
```

新增或实际修改的公开顶层类、函数、接口、类型、跨模块常量与配置必须紧邻提供中文 JSDoc。Controller 公开端点和 Service 公开用例即使未直接导出，也须说明输入来源、返回事实和关键约束。装饰器场景将 JSDoc 放在该声明的装饰器前。

- 用例、Adapter 和执行器入口补充实际存在的前置条件、错误、副作用、幂等、事务或授权要求。只出现于签名中的自解释参数不机械重复写 `@param`。
- `ProjectStore` 等端口在接口级说明方法集合的归属、读写、并发及失败约定；单个方法有额外约束时再说明。Adapter 类说明自身锁、文件、网络或事务差异，实现方法不重复抄写相同契约。
- 公开合同字段说明业务语义；自解释字段可由类型整体说明覆盖。不直观的默认值、省略、状态、单位、时区、摘要格式、敏感级别及所有权字段必须单独注释。
- 构造函数、框架固定生命周期和私有简单方法可由类级说明覆盖；发生额外非直观行为时补充说明。不要仅将类名翻译成一句话。

例如存储接口注释应解释“按可信工作空间读写，同空间标识冲突时拒绝创建”，而非“项目存储接口”；`workspaceId` 应解释由谁确定及是否构成授权，而非仅写“工作空间 ID”。

### 6.2 业务边界与阶段注释

以下逻辑必须在职责最近处添加中文说明：三个及以上业务步骤、多个顺序依赖的外部调用、工作空间隔离、默认拒绝、状态转换、产物摘要核对、授权、并发锁、原子写入、幂等、重试、失败兜底及历史数据兼容。

线性用例以连续编号的 `// 1. ...`、`// 2. ...` 标注业务阶段；一个注释覆盖完整逻辑块。非线性规则说明为何限制、拒绝、降级或必须保留，不逐行描述语法。

| 函数有效代码行 | 注释与拆分要求                                                   |
| -------------- | ---------------------------------------------------------------- |
| 少于 30        | 不因长度强制分段；高风险规则仍须说明。                           |
| 30～59         | 存在两个以上控制流、存储或外部调用阶段时，连续编号说明主要阶段。 |
| 60～99         | 连续编号划分主要流程，通常不少于三个阶段，并评估拆分。           |
| 100 及以上     | 默认拆分；确需保留时写明“长函数保留原因：”，继续按业务阶段说明。 |

有效代码行不含签名、空行、注释、纯类型及排版行。长度不能替代业务判断；不足 30 行的租户校验或结果不明处理同样需要解释，不以无语义小函数凑行数。

| 位置                        | 最低说明                                             |
| --------------------------- | ---------------------------------------------------- |
| 启动、Module                | 运行模式、依赖装配、监听及可信上下文边界。           |
| Controller、错误过滤器      | 公开端点、协议映射、字段来源与安全错误投影。         |
| Service、用例               | 可信上下文、操作顺序、并发及副作用。                 |
| Domain、端口                | 不变量、合法输入／状态、归属和可替换契约。           |
| 文件 Store、后续 Repository | 写入权、锁／事务、唯一性、损坏处理和恢复限制。       |
| 公开合同                    | 数据事实、字段默认／省略、单位、时区与安全边界。     |
| SDK Adapter                 | 可信调用方、能力差异、超时、重试及脱敏。             |
| 后续执行器、任务            | 授权核对、载荷版本、attempt、去重和人工核对。        |
| 脚本、迁移、测试            | 运行环境与清理、数据兼容及恢复，或被保护的业务行为。 |

TODO/FIXME/HACK 必须注明责任人或角色、日期和退出条件，例如 `TODO(执行器维护者, 2026-11-03): 完成身份与授权合同验收后开放任务领取。`。注释与行为同步更新，不写真实密钥、临时推测和无法验证的承诺。许可证、协议固定文本、第三方与生成文件保持原格式；生成内容应修改生成源。

## 7. 测试、交付与 AI 执行要求

1. 修改前读取根目录 `AGENTS.md`、`README.md`、`CONTEXT.md`、`docs/ARCHITECTURE.md` 和本规范；影响 Web 消费的合同与交互时同时读取[前端规范](frontend-code-standards.md)。
2. 新增文件、公开接口和复杂流程同步补充必要中文注释；只整理本次实际修改涉及的历史内容。检查依赖方向和公开响应中是否混入内部对象、秘密或本机路径。
3. 使用现有 `node:test`、断言及 Fastify 注入测试工具保护真实业务行为。优先覆盖输入拒绝、同空间冲突、跨空间访问、并发创建、损坏存储保护、持久读取、本地 Host／Origin 限制、hosted 拒绝与未实现发布接口。
4. 适配器和后续任务使用可控替身验证失败、超时、重复与结果不明；文件测试使用临时目录并清理，不读取个人真实数据。禁止使用真实账号或发送商店提交。
5. 完成变更运行 `pnpm typecheck`、`pnpm test`、`pnpm build`、`pnpm format:check`；影响页面时补充 `pnpm test:smoke` 和相关真实浏览器检查。
6. 合同破坏、存储变化和执行规则变化同步说明调用方迁移与恢复方案。交付报告如实区分已通过、未运行和失败的检查。

当前没有 ESLint、注释结构或模块边界自动检查，上述规则由开发与代码评审执行；不得宣称自动门禁已覆盖。未来远端发布仍需另有明确账号与计划的真实验收，本地测试不能替代。
